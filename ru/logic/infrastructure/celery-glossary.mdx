## Модели и поля

### Базы данных

*Две БД проекта: основная tenant-aware и отдельная geo для GPS-данных. На geo также может выставляться RLS-контекст, если задача указывает её в списке баз для установки контекста.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Основная БД | соединение | tenant-aware PostgreSQL на кастомном движке проекта. |
| БД геолокации (GPS) | соединение | Отдельный PostgreSQL для GPS-данных; обычный движок django. |

**Базы**

| Поле | Тип | Описание |
| --- | --- | --- |
| Маршрутизатор БД | список | Направляет модели между базами (основная база и GPS). |

### Конфигурация Celery

*Настройки Celery в settings.py, задающие брокер, бэкенд результатов, часовой пояс и планировщик.*

**Транспорт**

| Поле | Тип | Описание |
| --- | --- | --- |
| URL брокера | строка (URL) | Адрес брокера сообщений (из окружения). |
| Бэкенд результатов | строка | Хранилище результатов задач; по умолчанию БД. |
| Расширенные результаты | флаг | Сохранять дополнительную информацию о задаче в результате. |
| Срок хранения результатов | число (секунды) | Результаты хранятся 24 часа. |

**Время**

| Поле | Тип | Описание |
| --- | --- | --- |
| Использовать UTC | флаг | Включён режим UTC. |
| Часовой пояс | текст | Совпадает с часовым поясом проекта (Asia/Tashkent). |

**Очереди**

| Поле | Тип | Описание |
| --- | --- | --- |
| Очередь по умолчанию | текст | Очередь, в которую по умолчанию попадают задачи. |
| Импортируемые модули задач | список | Модули, загружаемые для регистрации задач. |

**Расписание**

| Поле | Тип | Описание |
| --- | --- | --- |
| Планировщик Beat | строка (путь) | Расписание хранится в БД. |
| Частота синхронизации Beat | число / пусто | Как часто планировщик пишет изменения в БД (из окружения). |

### Tenant-aware приложение Celery

*Подкласс Celery, который при постановке задачи впрыскивает в заголовки id текущей компании. Экземпляр приложения переопределяет базовый класс задачи и реестр на tenant-aware варианты.*

**Настройка**

| Поле | Тип | Описание |
| --- | --- | --- |
| Класс реестра задач | строка (путь) | Указывает на реестр, оборачивающий каждую задачу в tenant-aware задачу. |
| Базовый класс задачи | строка (путь) | Указывает на базовый tenant-aware класс задач. |

**Методы**

| Поле | Тип | Описание |
| --- | --- | --- |
| Создание базового класса задачи | метод | Формирует абстрактный tenant-aware класс задачи, привязанный к этому приложению. |
| Обновление заголовков | метод | Гарантирует наличие словаря заголовков и добавляет туда идентификатор текущей компании. |
| Добавление текущей компании | метод | Кладёт id текущей компании из контекста соединения в заголовки. |
| Отправка задачи | метод | Перед постановкой в очередь дописывает id компании в заголовки. |

### Tenant-aware задача

*Базовый класс всех задач: переносит id компании в заголовки и знает, на каких БД устанавливать RLS-контекст. Наследует стандартную задачу Celery и объявлен абстрактным.*

**Атрибуты**

| Поле | Тип | Описание |
| --- | --- | --- |
| Абстрактный класс | флаг | Класс не регистрируется как самостоятельная задача. |
| Базы для установки RLS-контекста | список / пусто | Перечень БД, где нужно устанавливать RLS-контекст; пусто означает значение по умолчанию. |

**Методы**

| Поле | Тип | Описание |
| --- | --- | --- |
| Получение баз для RLS-контекста | метод | Возвращает заданный список баз, иначе значение из конфигурации, иначе только основную БД. |
| Обновление заголовков | метод | Кладёт id компании из соединения в заголовки задачи. |
| Синхронный запуск | метод | Для eager/синхронных вызовов тоже прописывает id компании в заголовки. |

### Реестр tenant-aware задач

*Реестр Celery, который каждую регистрируемую задачу-класс оборачивает в tenant-aware задачу. Реализовано через динамический класс-наследник, поэтому задачи не обязаны наследовать tenant-aware класс явно.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Регистрация задачи | метод | Если задача-класс ещё не tenant-aware, создаёт наследника с примешанным tenant-aware классом. |

### Определение компании задачи

*Функция, извлекающая компанию из заголовков задачи по id, с кэшированием в Redis. При отсутствии компании или заголовков задача прерывается.*

**Источники**

| Поле | Тип | Описание |
| --- | --- | --- |
| Идентификатор компании | число | Читается из заголовка/запроса. |

**Кэш**

| Поле | Тип | Описание |
| --- | --- | --- |
| Ключ кэша по id | текст | Ключ для кэша компании в Redis по идентификатору. |

### Установка RLS-контекста перед задачей

*Обработчик сигнала «перед задачей»: определяет компанию и устанавливает RLS-контекст на всех её БД до выполнения задачи, а также выставляет идентификатор запроса для логов.*

### Сброс RLS-контекста после задачи

*Обработчик сигнала «после задачи»: сбрасывает RLS-контекст на всех задействованных БД и очищает идентификатор запроса.*

### Сигнал «перед задачей»

*Сигнал Celery, к которому подключён обработчик установки RLS-контекста. Подключён для всех задач.*

### Сигнал «после задачи»

*Сигнал Celery, к которому подключён обработчик сброса RLS-контекста.*

### Очереди задач

*Определение очередей Celery с их exchange и routing_key.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Очередь по умолчанию | очередь | Сюда идут все задачи без явной очереди. |
| Очередь сообщений | очередь | Для задач рассылки и уведомлений. |

### Расписание периодических задач

*Набор периодических задач Celery Beat; хранится и редактируется через планировщик на основе БД. Каталог самих задач — на странице [фоновых задач](/ru/logic/background-tasks).*

**Расписание**

| Поле | Тип | Описание |
| --- | --- | --- |
| Автоштрафы по заявкам | периодическая задача | Каждую минуту. |
| Синхронизация Wialon | периодическая задача | Каждые 5 минут. |
| Автосписание | периодическая задача | Ежедневно в 05:00. |
| Удаление дублей (сервис автомобильных штрафов) | периодическая задача | Ежедневно в 00:00. |
