## Модели и поля

### Базы данных

*Две БД проекта: основная tenant-aware и отдельная geo для GPS-данных. На geo схема тоже может переключаться, если задача указывает её в списке баз для переключения.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Основная БД | соединение | tenant-aware PostgreSQL на кастомном движке проекта. |
| БД геолокации (GPS) | соединение | Отдельный PostgreSQL для GPS-данных; обычный движок django. |

**Базы**

| Поле | Тип | Описание |
| --- | --- | --- |
| Маршрутизатор БД | список | Направляет модели по схемам и базам. |

### Конфигурация Celery

*Настройки Celery в settings.py, задающие брокер, бэкенд результатов, часовой пояс и планировщик.*

**Транспорт**

| Поле | Тип | Описание |
| --- | --- | --- |
| URL брокера | строка (URL) | Адрес брокера сообщений (из окружения). |
| Бэкенд результатов | строка | Хранилище результатов задач; по умолчанию БД. |
| Расширенные результаты | флаг | Сохранять дополнительную информацию о задаче в результате. |
| Срок хранения результатов | число (секунды) | Результаты хранятся 24 часа. |

**Время**

| Поле | Тип | Описание |
| --- | --- | --- |
| Использовать UTC | флаг | Включён режим UTC. |
| Часовой пояс | текст | Совпадает с часовым поясом проекта (Asia/Tashkent). |

**Очереди**

| Поле | Тип | Описание |
| --- | --- | --- |
| Очередь по умолчанию | текст | Очередь, в которую по умолчанию попадают задачи. |
| Импортируемые модули задач | список | Модули, загружаемые для регистрации задач. |

**Расписание**

| Поле | Тип | Описание |
| --- | --- | --- |
| Планировщик Beat | строка (путь) | Расписание хранится в БД. |
| Частота синхронизации Beat | число / пусто | Как часто планировщик пишет изменения в БД (из окружения). |

### Tenant-aware приложение Celery

*Подкласс Celery, который при постановке задачи впрыскивает в заголовки схему и id текущего тенанта. Экземпляр приложения переопределяет базовый класс задачи и реестр на tenant-aware варианты.*

**Настройка**

| Поле | Тип | Описание |
| --- | --- | --- |
| Класс реестра задач | строка (путь) | Указывает на реестр, оборачивающий каждую задачу в tenant-aware задачу. |
| Базовый класс задачи | строка (путь) | Указывает на базовый tenant-aware класс задач. |

**Методы**

| Поле | Тип | Описание |
| --- | --- | --- |
| Создание базового класса задачи | метод | Формирует абстрактный tenant-aware класс задачи, привязанный к этому приложению. |
| Обновление заголовков | метод | Гарантирует наличие словаря заголовков и добавляет туда текущую схему. |
| Добавление текущей схемы | метод | Кладёт имя схемы (и id тенанта при наличии) из текущего соединения в заголовки. |
| Отправка задачи | метод | Перед постановкой в очередь дописывает схему тенанта в заголовки. |

### Tenant-aware задача

*Базовый класс всех задач: переносит схему тенанта в заголовки и знает, на каких БД переключать схему. Наследует стандартную задачу Celery и объявлен абстрактным.*

**Атрибуты**

| Поле | Тип | Описание |
| --- | --- | --- |
| Абстрактный класс | флаг | Класс не регистрируется как самостоятельная задача. |
| Базы для переключения схемы | список / пусто | Перечень БД, где нужно переключать схему; пусто означает значение по умолчанию. |

**Методы**

| Поле | Тип | Описание |
| --- | --- | --- |
| Получение баз для схемы | метод | Возвращает заданный список баз, иначе значение из конфигурации, иначе только основную БД. |
| Обновление заголовков | метод | Кладёт id тенанта и имя схемы из соединения в заголовки задачи. |
| Синхронный запуск | метод | Для eager/синхронных вызовов тоже прописывает схему в заголовки. |

### Реестр tenant-aware задач

*Реестр Celery, который каждую регистрируемую задачу-класс оборачивает в tenant-aware задачу. Реализовано через динамический класс-наследник, поэтому задачи не обязаны наследовать tenant-aware класс явно.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Регистрация задачи | метод | Если задача-класс ещё не tenant-aware, создаёт наследника с примешанным tenant-aware классом. |

### Определение тенанта задачи

*Функция, извлекающая тенанта из заголовков задачи по имени схемы или id, с кэшированием в Redis. При отсутствии тенанта или заголовков задача прерывается.*

**Источники**

| Поле | Тип | Описание |
| --- | --- | --- |
| Идентификатор тенанта | число | Читается из заголовка/запроса. |
| Имя схемы | текст | Читается из заголовка/запроса. |

**Кэш**

| Поле | Тип | Описание |
| --- | --- | --- |
| Ключ кэша по схеме | текст | Ключ для кэша тенанта в Redis по имени схемы. |
| Ключ кэша по id | текст | Ключ для кэша тенанта в Redis по идентификатору. |

### Переключение схемы перед задачей

*Обработчик сигнала «перед задачей»: определяет тенанта и переключает схему на всех его БД до выполнения задачи, включая public, а также выставляет идентификатор запроса для логов.*

### Сброс схемы после задачи

*Обработчик сигнала «после задачи»: возвращает схему всех задействованных БД в public и сбрасывает идентификатор запроса.*

### Сигнал «перед задачей»

*Сигнал Celery, к которому подключён обработчик переключения схемы. Подключён для всех задач.*

### Сигнал «после задачи»

*Сигнал Celery, к которому подключён обработчик сброса схемы на public.*

### Очереди задач

*Определение очередей Celery с их exchange и routing_key.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Очередь по умолчанию | очередь | Сюда идут все задачи без явной очереди. |
| Очередь сообщений | очередь | Для задач рассылки и уведомлений. |

### Расписание периодических задач

*Набор периодических задач Celery Beat; хранится и редактируется через планировщик на основе БД. Каталог самих задач — на странице [фоновых задач](/ru/logic/background-tasks).*

**Расписание**

| Поле | Тип | Описание |
| --- | --- | --- |
| Автоштрафы по заявкам | периодическая задача | Каждую минуту. |
| Синхронизация Wialon | периодическая задача | Каждые 5 минут. |
| Автосписание | периодическая задача | Ежедневно в 05:00. |
| Удаление дублей OkAuto | периодическая задача | Ежедневно в 00:00. |
