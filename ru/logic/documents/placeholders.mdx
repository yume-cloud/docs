Полный перечень плейсхолдеров по группам — в [глоссарии плейсхолдеров](/ru/logic/documents/placeholders-glossary).

## Логика

Когда документ генерируется из шаблона, система собирает один общий словарь «плейсхолдер → значение» и подставляет его в HTML-содержимое. Плейсхолдер — это текст в двойных фигурных скобках, который менеджер компании вставляет в шаблон при его оформлении.

<Note>
**Одиночные плейсхолдеры** (клиент, точка проката, общие данные заявки/менеджера/сумм) заменяются один раз во всём тексте документа.

**Табличные (построчные) плейсхолдеры** (инвентарь, товар, группа инвентаря, услуга, штраф, доставка) устроены иначе: система ищет в шаблоне строку таблицы с плейсхолдером нужного домена и размножает её — по одной копии на каждый объект, подставляя в каждую копию данные конкретной записи.
</Note>

Если данные для плейсхолдера отсутствуют, подставляется заглушка — строка из двенадцати подчёркиваний, играющая роль «пустой линии для заполнения от руки» (с отдельными исключениями, отмеченными в глоссарии).

<Warning>
Все денежные суммы «прописью» в любой группе плейсхолдеров всегда описывают сумму в казахстанских тенге, независимо от фактической валюты компании. Числовой вариант суммы при этом корректно показывает валюту компании.
</Warning>

### Клиент и точка проката

Плейсхолдеры клиента строятся по объекту клиента заявки и делятся на базовые контактные данные и данные документа физического/юридического лица (заполняются только если у клиента есть соответствующие привязанные реквизиты).

<Info>
Словарь плейсхолдеров клиента умеет строиться с префиксом к именам плейсхолдеров — используется, когда в заявке есть дополнительное настраиваемое поле типа «клиент» (например, «поручитель»): для указанного там клиента строится второй набор тех же плейсхолдеров, но с именем этого поля перед каждым плейсхолдером, без разделителя.
</Info>

Плейсхолдеры точки проката — это отдельный небольшой словарь (ID, название, адрес) точки проката заявки. Механизм с префиксом предусмотрен, но на практике точка проката всегда подставляется без префикса — повторно подставить данные второй, дополнительной точки проката так, как это делается для клиента, сейчас нельзя.

### Построчные таблицы: инвентарь, товар и группа инвентаря

Арендуемый инвентарь и проданные товары строятся почти одинаково: по одной строке на позицию, с идентификацией, сроками аренды и денежными показателями (цена, скидка, штраф, закупочная и балансовая стоимость — в цифрах и прописью). У инвентаря дополнительно есть блок данных автомобиля (заполняется только для инвентаря типа «автомобиль» и только для непустых полей); у товаров этого блока нет.

Формула цены со скидкой за день (только у инвентаря): цена со скидкой по позиции делится на общее число дней аренды всей заявки.

<Tip>
Компания может добавлять собственные настраиваемые поля инвентаря и группы инвентаря — они автоматически становятся дополнительными плейсхолдерами построчных таблиц. Для инвентаря к ним всегда добавляются три встроенных поля (VIN, цвет, общий пробег), даже если компания их не настраивала. Для таблицы проданных товаров такая поддержка не реализована.
</Tip>

Отдельная построчная таблица группирует арендуемый инвентарь не по единицам, а по модели/группе (например, «все велосипеды модели X» одной строкой). Она строится только если в шаблоне действительно есть строка с плейсхолдером группы. Цена за единицу в этой таблице — среднее арифметическое цены со скидкой по единицам группы, округлённое до целого.

### Штраф и доставка

Штрафы заявки подставляются построчно: номер строки, ID, причина, сумма (в цифрах и прописью), дата создания.

<Warning>
В таблицу штрафов попадают только штрафы, добавленные вручную сотрудником. Штрафы, начисленные системой автоматически (просрочка, повреждение и т.п.), в эту построчную таблицу не включаются — они видны только через общие суммы штрафа по заявке и по позиции.
</Warning>

Доставки/вывозы инвентаря заявки подставляются построчно: идентификация, даты и статус (забор, доставка, выдача, отмена), контакты и места, цена доставки (в цифрах и прописью). Тип доставки принимает значение «Доставка» или «Вывоз»; для прочих технически возможных значений выводится заглушка.

<Info>
Итоговая сумма «цена доставки» на уровне всей заявки считается не по этой построчной таблице, а отдельно — как сумма стоимости типизированных дополнительных услуг заявки. Это разные механизмы: построчная таблица отражает логистические записи, а итоговая сумма — сумму выставленных клиенту услуг.
</Info>

### Услуга

Дополнительные услуги заявки подставляются построчно: номер, ID, название, доп. информация, исполнитель, цена и цена со скидкой (в цифрах и прописью), цена по тарифу, длительность тарифа, адрес доставки (из произвольных дополнительных данных услуги, если указан).

<Warning>
Плейсхолдер исполнителя услуги в текущей реализации обращается не к тому полю, которое реально хранит исполнителя — при попытке вывести этот плейсхолдер в документе генерация завершится ошибкой, а не выведет заглушку.
</Warning>

### Общий порядок сборки

1. Строится плоский словарь одиночных плейсхолдеров (клиент, точка проката, данные заявки/менеджера) и подставляется в текст шаблона за один проход.
2. Для каждого построчного домена (инвентарь, товар, группа, услуга, штраф, доставка) строится словарь функций «номер строки + объект → строка»; система находит в шаблоне соответствующие строки таблиц и подставляет данные, размножая строку.
3. Компания может расширять словари клиента, заявки, точки проката, инвентаря и группы инвентаря собственными настраиваемыми полями — они автоматически добавляются при сборке документа.

## Особенности поведения

- Для проданных товаров название и адрес точки проката инвентаря вычисляются без защитной проверки — если у позиции точка проката не задана, подстановка завершится ошибкой вместо вывода заглушки.
- Плейсхолдер состояния инвентаря (и товара) при отсутствии состояния выводит дефис, а не стандартную заглушку из подчёркиваний, используемую во всех остальных полях этих таблиц.
- У части денежных плейсхолдеров таблиц инвентаря и товара нет варианта «прописью»: цена по тарифу, долг и оплаченная сумма — только числом с валютой.
- Плейсхолдер органа выдачи документа физического лица подставляется только если он заполнен вручную в карточке паспорта клиента — при остальных заполненных паспортных данных, но пустом поле органа выдачи, плейсхолдер всё равно станет заглушкой.
- При подстановке построчных плейсхолдеров услуги, штрафа и доставки не проверяется, что найденный в шаблоне плейсхолдер действительно существует в словаре (в отличие от таблиц инвентаря, товара и группы) — опечатка в названии плейсхолдера приведёт к ошибке генерации.
- Механизм префикса словаря плейсхолдеров точки проката реализован, но при генерации документа заявки вызывается всегда без префикса — второй набор плейсхолдеров для дополнительной точки проката так, как это сделано для клиента, сейчас получить нельзя.
