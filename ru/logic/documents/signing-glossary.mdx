## Подписант

*Сторона (клиент или компания), которая подписывает документ. Один подписант закрепляется за парой «компания + клиент» (или самой компанией) и переиспользуется на разных документах.*

| Поле | Тип | Описание |
| --- | --- | --- |
| ID | число | Первичный ключ |
| Компания-арендодатель | связь | Компания, в рамках которой существует подписант |
| Тип подписанта | список | См. «Тип подписанта» ниже |
| Имя/название | текст | ФИО клиента или название компании на момент подписания |
| Телефон | текст | Куда по умолчанию уходит ссылка на подписание и куда всегда уходит SMS-код. У подписанта-компании не заполняется — ссылку для неё отправляют на номер, указанный при отправке |
| Email | текст | — |
| Внешний ID | число | ID связанной сущности вне модуля документов (например, клиента компании) |
| Доп. данные | JSON | Произвольные атрибуты подписанта |
| Дата создания / Дата обновления | дата/время | — |

## Подпись документа

*Запрос на подписание документа конкретным подписантом. На один документ не может быть двух подписей от одного подписанта. Документ считается подписанным, когда все его подписи получили статус «Подписан».*

| Поле | Тип | Описание |
| --- | --- | --- |
| ID | число | Первичный ключ |
| UUID подписи | текст (UUID) | Публичный идентификатор, используется в ссылке для подписания |
| Документ | связь | Документ, который подписывается |
| Подписант | связь | Сторона, которая должна подписать |
| Способ подписания | список | См. «Способ подписания» ниже |
| Разрешённые способы подписания | список | Проверяется сервером при запросе и подтверждении кода и на обоих путях ЕГОВ/ЭЦП; ручное подписание и отправка ссылки его не проверяют. По умолчанию — «ЕГОВ/ЭЦП» и «По SMS-коду»; подпись компании создаётся только с «ЕГОВ/ЭЦП». Задаётся при создании подписи, поэтому подписи компании, созданные раньше, сохраняют прежний список |
| Статус | список | См. «Статус документа/подписи» ниже |
| Дата создания / Дата обновления | дата/время | — |

## Этап подписания

*Запись истории смены статуса подписи (журнал переходов для аудита, не редактируется напрямую).*

| Поле | Тип | Описание |
| --- | --- | --- |
| ID | число | Первичный ключ |
| Подпись | связь | Подпись, к которой относится этап |
| Статус до | список | Проставляется автоматически реальным предыдущим статусом |
| Статус после | список | Новый статус подписи |
| Доп. данные | JSON | Метаданные перехода — IP, ОС, браузер, устройство (см. ниже) |
| Дата создания | дата/время | — |

**Метаданные, сохраняемые в «Доп. данные»:** IP-адрес клиента, операционная система (детали и семейство), браузер (с версией и семейством), тип устройства (мобильное/планшет/десктоп) — определяются по данным запроса. Исключение — подтверждение через мобильное приложение ЕГОВ: там сохраняются только данные сертификата.

## Отправка ссылки на подписание

*Действие сотрудника: SMS со ссылкой на публичную страницу подписи уходит подписанту, подпись переходит в «Готов к подписанию». Документ ищется в активной компании, подпись — внутри этого документа; иначе 404. Оплата и проверка остатка пакета — как у любого сообщения подписания.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Телефон получателя (`phone`) | текст, необязательное | Номер в формате E.164 (`+77001234567`), на который уйдёт ссылка вместо телефона подписанта. Нигде не сохраняется и не влияет на адресата SMS-кода. Нужен прежде всего для подписи компании: у подписанта-компании телефона нет, и ссылку отправляют руководителю или сотруднику с ЭЦП компании. Если номера нет ни здесь, ни у подписанта, запрос отклоняется с «Укажите номер телефона.» |

## Проверка остатка пакета подписей

*Общая проверка, встроенная в сценарии подписания: в режиме биллинга «за документ» она отклоняет операцию с ошибкой «Количество подписей исчерпано», если у компании не осталось свободных слотов в пакетах. В режиме «за SMS» проверка ничего не ограничивает. Подключена к отправке SMS сотрудником, запросу и подтверждению кода клиентом и к загрузке файла с ЭЦП; ручное подписание и подтверждение через мобильное приложение ЕГОВ она не покрывает. Отдельное «Разрешение на подписание по квоте документов» (см. глоссарий пакетов) по-прежнему ничего не проверяет.*

## Статусы и справочники

### Тип подписанта

*Определяет, кем является подписант.*

- Компания
- Клиент

### Способ подписания

*Каким способом подписант подтверждает документ.*

- Вручную
- По SMS-коду
- Через ЕГОВ/ЭЦП

### Статус документа/подписи

*Стадия жизненного цикла одной подписи. Хранится в подписи (не в самом документе); история переходов — в этапах подписания.*

- Черновик
- Готов к подписанию
- Просматривается
- На подтверждении
- Отклонён — определён в системе, но ни один способ подписания фактически в него не переводит
- Подписан
