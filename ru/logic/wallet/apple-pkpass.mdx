## Что делает сборка Apple .pkpass

Этот участок отвечает за создание готового файла `.pkpass` — брендированной карты для Apple Wallet. На вход подаются: компания-владелец (арендатор), тип карты (бонусная или заказ), объект-источник данных (бонус клиента или заказ аренды), серийный номер и токен авторизации. На выходе получается двоичный zip-архив, который клиент устанавливает в Apple Wallet.

Точка входа работает как диспетчер:

1. Если серийный номер не передан, генерируется случайный уникальный номер.
2. По типу карты выбирается один из двух сборщиков — для бонусной карты или для карты заказа. Если тип не распознан, по умолчанию собирается бонусная карта.
3. Выбранный сборщик формирует описание карты, готовит изображения, а затем всё это подписывается и упаковывается в архив.

<Info>
Итоговая карта всегда состоит из трёх обязательных частей: файла описания карты, набора изображений (как минимум иконки) и двух служебных файлов — манифеста и подписи. Без корректной подписи Apple Wallet откажется устанавливать карту.
</Info>

## Общий конверт пропуска

У любой карты (и бонусной, и заказа) есть общая «шапка» — конверт пропуска. В него входят технические идентификаторы, по которым Apple понимает, чья это карта и куда обращаться за обновлениями.

| Поле | Тип | Назначение |
|------|-----|------------|
| Версия формата | число | всегда равна 1 |
| Идентификатор Pass Type | текст | из настроек Apple, определяет вид пропуска |
| Идентификатор команды | текст | Apple Team ID из настроек |
| Серийный номер | текст | уникальный номер именно этой карты |
| Название организации | текст | берётся из настроек |
| URL веб-сервиса | текст | адрес, куда Apple Wallet ходит за обновлениями карты |
| Токен авторизации | текст | токен для запросов к веб-сервису; если не передан, подставляется пустая строка |
| Запрет шаринга | флаг | всегда включён (карту нельзя передать другому) |
| Аннулирован | флаг | всегда выключен при сборке |

<Note>
URL веб-сервиса и токен авторизации нужны для последующих push-обновлений карты: именно по ним устройство запрашивает свежую версию пропуска после того, как в системе что-то изменилось.
</Note>

## Бонусная карта

Бонусная карта собирается как карта магазина (store card) — компактный формат с полосой и логотипом.

### Данные на карте

| Место на карте | Подпись | Значение |
|----------------|---------|----------|
| Верхнее поле | «БАЛАНС» | текущий баланс бонусов клиента с суффиксом «Y», выровнен вправо |
| Второе поле | «владелец карты» | имя клиента |

Верхнее поле баланса имеет сообщение об изменении: при обновлении карты Apple Wallet показывает клиенту уведомление «Ваш баланс обновлён».

### Оформление

Цвета, текст у логотипа и описание карты берутся из Дизайна карты Apple Wallet, привязанного к программе лояльности клиента. Дизайн находится через цепочку: бонус → клиент → пользователь → программа лояльности → дизайн карты. Если у клиента дизайн не задан, применяются значения по умолчанию:

| Параметр | Значение по умолчанию |
|----------|------------------------|
| Цвет фона | тёмно-синий (#141828) |
| Цвет текста | белый (#FFFFFF) |
| Цвет подписей | серо-голубой (#AAAFC8) |
| Текст рядом с логотипом | название организации из настроек |
| Описание карты | описание пропуска из настроек |

Дополнительно:
- Цвет полосы добавляется на карту, только если он явно задан в дизайне (иначе поле вообще не выводится).
- Флаг «убрать блик полосы» добавляется, только если он включён в дизайне.

Все цвета переводятся из формата HEX в формат `rgb(...)`, который ожидает Apple.

### Баркод

На карту помещается QR-код с идентификатором клиента. Под кодом печатается краткая подпись — тот же идентификатор со значком номера. Баркод дублируется в устаревшее одиночное поле — для совместимости со старыми версиями iOS (до 9-й).

## Карта заказа

Карта заказа собирается в универсальном формате (generic) — с несколькими рядами полей и оборотной стороной.

### Данные на карте

| Место на карте | Подпись | Значение |
|----------------|---------|----------|
| Верхнее поле | «ЗАКАЗ» | номер заказа со значком номера, выровнен вправо |
| Главное поле | «СТАТУС» | подпись статуса заказа |
| Второе поле | «НАЧАЛО» | дата и время начала аренды |
| Второе поле | «ОКОНЧАНИЕ» | дата и время окончания аренды, выровнено вправо |
| Доп. поле | «ПОЛУЧЕНИЕ» | название точки выдачи |
| Доп. поле | «ОПЛАТА» | подпись статуса оплаты, выровнено вправо |
| Оборот | «Возврат» | точка возврата |
| Оборот | «К оплате» | сумма к оплате с учётом скидки, в тенге |
| Оборот | «Оплачено» | внесённая сумма, в тенге |

Номер заказа берётся из «плотного» человекочитаемого номера, а если его нет — из внутреннего идентификатора заказа.

Статус заказа переводится в русскую подпись: «Заявка», «Резерв», «В аренде», «Отменён», «Завершён» или «Должник». Если статус не распознан, показывается его числовое значение. Статус оплаты переводится в «Не оплачен», «Оплачен» или «Частично»; при нераспознанном значении поле остаётся пустым.

Точка получения — название точки выдачи заказа, а если она не задана, ставится прочерк. Точка возврата — название точки возврата; если она не указана, дублируется точка получения.

Даты начала и окончания форматируются как «день.месяц часы:минуты»; если дата отсутствует, ставится прочерк.

Поля статуса, начала, окончания и оплаты снабжены сообщениями об изменении, поэтому при push-обновлении клиент видит уведомления вроде «Статус заказа: …» или «Новое время окончания: …».

### Сроки действия

Срок действия карты заказа вычисляется так:

1. По умолчанию — год от текущего момента.
2. Если дата окончания аренды плюс 30 дней оказывается позже — берётся именно она. То есть карта живёт минимум год, но для длинных аренд продлевается до окончания аренды плюс месяц.

Кроме того, если у заказа задана дата окончания аренды, она проставляется как «актуальная дата» — по ней Apple Wallet автоматически выводит карту на экран блокировки в нужный момент.

<Info>
Оформление карты заказа фиксировано в коде и не зависит от дизайна лояльности: тёмно-синий фон, белый текст, серо-голубые подписи. Настройки Дизайна карты Apple Wallet на карты заказа не влияют.
</Info>

### Баркод

На карту помещается QR-код с идентификатором заказа, подпись под кодом — номер заказа. Как и у бонусной карты, баркод дублируется в устаревшее одиночное поле.

## Изображения: иконки, логотип, полоса

Apple различает три вида изображений на карте: иконку, логотип и фоновую полосу-баннер. Для каждого из них система готовит до трёх размеров (для экранов разной плотности): базовый, удвоенный и утроенный.

Логика подготовки такова: для каждого вида сначала пытаются взять изображения из Дизайна карты Apple Wallet (исходник и его автоуменьшенные варианты). Если для вида в дизайне картинки нет, применяется запасной вариант:

| Вид | Если есть в дизайне | Если в дизайне нет |
|-----|---------------------|---------------------|
| Иконка | берутся варианты из дизайна | логотип арендатора приводится к квадрату в трёх размерах (29, 58 и 87 пикселей) |
| Логотип | берутся варианты из дизайна | если у арендатора есть логотип — он так же приводится к квадрату в тех же трёх размерах; иначе логотип не добавляется |
| Полоса | берутся варианты из дизайна | не добавляется вовсе (полоса необязательна) |

<Warning>
Иконка обязательна: без неё карта не соберётся. Если в дизайне нет иконки И у арендатора не загружен логотип, сборка карты завершается ошибкой. Поэтому у арендатора всегда должен быть либо дизайн лояльности с иконкой, либо загруженный логотип.
</Warning>

Когда логотип арендатора используется как запасная иконка, он вписывается в прозрачный квадрат: изображение масштабируется с сохранением пропорций и центрируется, свободные края остаются прозрачными.

<Note>
Карта заказа всегда собирает изображения без учёта дизайна лояльности — она использует только логотип арендатора. Значит, для карт заказа арендатору обязательно нужен загруженный логотип, иначе сборка не пройдёт.
</Note>

## Подпись и упаковка

Готовый набор файлов (описание карты и изображения) подписывается и упаковывается в архив в три шага.

1. **Манифест.** Для каждого файла считается контрольная сумма (SHA1), и составляется список «имя файла → контрольная сумма». Это гарантирует целостность: если хоть один файл изменят, подпись перестанет сходиться.
2. **Подпись.** Манифест подписывается отделённой подписью формата PKCS7 (двоичной, в кодировке DER). В подписи используются два сертификата Apple — рабочий сертификат подписи и промежуточный сертификат Apple WWDR — вместе с приватным ключом. Хеш подписи — SHA256.
3. **Упаковка.** Все файлы, плюс сам манифест, плюс файл подписи складываются в zip-архив со сжатием. Это и есть готовый `.pkpass`.

Материал для подписи (оба сертификата и приватный ключ) хранится в настройках в кодировке base64. Система умеет распознавать зашифрованный приватный ключ и в этом случае расшифровывает его паролем из настроек.

<Tip>
Материал для подписи загружается один раз и кэшируется на всё время работы процесса. Это ускоряет сборку, но означает, что после смены сертификатов или ключа сервис нужно перезапустить — иначе он продолжит подписывать старым материалом.
</Tip>

## Конвертер цвета

Небольшая вспомогательная логика переводит HEX-цвет (например, «#141828») в строку `rgb(...)`, которую требует формат Apple. Она устойчива к разным вводам: пустое значение даёт пустую строку, уже готовая строка `rgb(...)` возвращается без изменений, а короткая трёхсимвольная запись цвета разворачивается в полную.
