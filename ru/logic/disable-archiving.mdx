Единый механизм **«Архивация»** заменил разрозненные поля «удалён»/«дата удаления» на большинстве справочников и каталожных
сущностей: вместо физического удаления строки или булева флага рядом с исходной записью создаётся отдельная связанная запись
«Архивация» со способом (удаление / архивация / списание), автором и комментарием, а действующие записи выбираются по
отсутствию такой связанной записи. Механизм охватывает инвентарь, группы инвентаря, комплекты, услуги, клиентов, категории,
точки проката, периоды времени, скидки, виды/счета/статьи оплат, контрагентов и склад — но **не** затрагивает отдельный флаг
«Удалена» у заявок на аренду, который остаётся самостоятельной легаси-логикой.

Полный перечень моделей и полей — в разделе [«Глоссарий»](/ru/logic/disable-archiving-glossary).

## Логика

### Ядро механизма

#### Общая идея

Вместо того чтобы у каждой справочной модели было своё булево поле «удалён» и своя дата удаления, в системе используется
единая модель **«Архивация»**. Архивация — это отдельная запись, которая фиксирует факт того, что конкретный объект
(единица инвентаря, группа инвентаря, комплект, услуга, клиент, категория, точка проката, период времени, скидка, вид
оплаты, счёт оплаты, статья оплаты, контрагент или склад) выведен из активного оборота. Сама исходная запись при этом
физически не удаляется и не помечается флагом — рядом с ней появляется связанная запись «Архивация», а «действующими»
считаются те записи, у которых такой связанной записи нет.

<Note>
Заявки (аренда/бронирование клиентов) в этот механизм не входят — у них остаётся отдельный, самостоятельный флаг «Удалена»,
унаследованный от старой логики. Подробнее — в разделе [«Легаси-флаг «Удалена» у заявок»](#легаси-флаг-удалена-у-заявок).
</Note>

#### Модель «Архивация»

У записи «Архивация» есть отдельная связь «один-к-одному» на каждый из поддерживаемых типов сущностей: инвентарь, группа
инвентаря, комплект, услуга, клиент, категория, точка проката, период времени, скидка, вид оплаты, счёт оплаты, статья
оплаты, контрагент, склад. По соглашению приложения ровно одна из этих связей заполнена — она указывает, какая именно
сущность заархивирована, — а все остальные остаются пустыми.

<Warning>
Это соглашение на уровне приложения, а не жёсткое ограничение базы данных: ничто не гарантирует техническими средствами,
что заполнена ровно одна связь. Создание записи «Архивация» в обход стандартных сценариев (например, напрямую через
административную панель) теоретически может это правило нарушить.
</Warning>

Помимо связи с архивируемой сущностью, запись «Архивация» хранит:

| Поле | Тип | Назначение |
|---|---|---|
| Автор архивации | связь на пользователя | Кто выполнил архивацию; может быть не указан |
| Способ архивации | список значений | Одно из значений «Способа архивации» (см. ниже); значение по умолчанию — «Списание» |
| Комментарий | текст (до 512 символов) | Произвольная причина архивации, необязателен |
| Доп. данные | JSON | Произвольные дополнительные данные об архивации, по умолчанию — пустой объект |

**Способ архивации** — перечисление из трёх значений:

| Значение | Смысл |
|---|---|
| Удаление | Объект удалён |
| Архивация | Объект перенесён в архив |
| Списание | Объект списан (значение по умолчанию на уровне модели) |

Для инвентаря способ архивации напрямую влияет на отображаемый статус (подробности — в разделе «Каталог» ниже).

**Как выбираются «действующие» записи.** Во всех местах системы, где нужно показать только актуальные (не заархивированные)
объекты, используется один и тот же приём: выбираются записи справочника, у которых связанной записи «Архивация» не
существует. Соответственно, чтобы получить только заархивированные объекты, ищутся записи, у которых такая связанная запись
есть.

<Warning>
Это правило не применяется автоматически ко всем запросам — специального «активного» менеджера, который бы сам исключал
заархивированные записи для любой выборки, нет. Каждый список или детальная выборка сама решает, включать ли заархивированные
записи и как их помечать. Если новый экран обратится к таблице напрямую без явного условия по архивации, в результат попадут и
удалённые, и архивные, и списанные записи.
</Warning>

#### Bulk-эндпоинт архивации и восстановления

Просмотр списка заархивированных записей и массовая архивация/восстановление объектов работают через один и тот же адрес:
чтение выполняется методом получения списка, а изменение — методом создания.

**Просмотр списка.** При чтении возвращается постраничный список записей «Архивация» с развёрнутыми данными той сущности,
которая в конкретной записи заархивирована (у остальных связей будет пусто). Список можно:

- искать по названию/уникальному идентификатору инвентаря, группы или услуги, а также по названию клиента, категории,
  точки проката, периода времени, скидки, вида оплаты, счёта оплаты, статьи оплаты, контрагента и склада (при включённой
  соответствующей функциональной настройке — дополнительно по номеру и техпаспорту автомобиля); поиск по комплекту не
  поддерживается вовсе;
- фильтровать (см. ниже);
- сортировать по дате архивации, названию инвентаря, группы или услуги; по умолчанию — сначала самые недавние архивации.

**Массовая архивация.** При создании передаются: способ архивации (обязателен), комментарий (необязателен), доп. данные
(необязательны), признак «выполнить архивацию» (по умолчанию — да; при значении «нет» выполняется обратное действие —
восстановление, см. ниже), а также до четырёх списков идентификаторов: инвентаря, групп, услуг и комплектов.

При архивации происходит следующее:

1. Из переданных идентификаторов отбираются только ещё не заархивированные группы, услуги и комплекты, а также инвентарь.
2. Набор архивируемого инвентаря — это не только явно переданные идентификаторы, но и **весь действующий инвентарь, входящий
   в архивируемые группы**: архивация группы автоматически «утягивает» за собой весь её инвентарь, даже если он не был
   перечислен отдельно.
3. Выполняется проверка безопасности: если среди отбираемого к архивации инвентаря есть хотя бы одна позиция, у которой
   прямо сейчас идёт активная аренда или действует бронь (период которой покрывает текущий момент), весь запрос
   отклоняется с ошибкой «Нельзя архивировать или удалить инвентарь, который сейчас находится в аренде».
4. Если проверка пройдена, для каждого отобранного инвентаря, группы, комплекта и услуги отдельно создаётся своя запись
   «Архивация» с одним и тем же способом, комментарием и автором из запроса.
5. После завершения — как при архивации, так и при восстановлении (в том числе при восстановлении клиента, точки проката
   или любой другой поддерживаемой сущности через общий список идентификаторов записей архивации) — всегда запускаются три
   фоновые задачи пересчёта лимитов использования по трём категориям транспортного инвентаря: автомобили, скутеры,
   мотоциклы.

**Массовое восстановление.** Если признак «выполнить архивацию» указан как «нет», выполняется снятие архивации:

1. Записи «Архивация», найденные по общему списку идентификаторов самих записей архивации, а также по идентификаторам
   услуг и комплектов, удаляются напрямую.
2. Для каждой снимаемой записи архивации по инвентарю: определяется группа этого инвентаря, и если у этой группы тоже
   есть запись архивации, созданная в пределах 60 секунд от архивации инвентаря, она удаляется вместе с записью по
   инвентарю — предполагается, что если группа и её инвентарь были заархивированы почти одновременно, значит это было одно
   совместное («каскадное») действие, которое нужно отменять целиком.
3. Для каждой снимаемой записи архивации по группе: дополнительно удаляются записи архивации по инвентарю, принадлежащему
   любой из групп, переданных в этом же запросе на восстановление (а не обязательно только той группе, чья запись
   архивации сейчас обрабатывается), у которых совпадает способ архивации и время создания отличается не более чем на
   минуту в любую сторону — это отменяет инвентарь, который был заархивирован вместе с группой.
4. Оставшиеся отобранные записи по группам и инвентарю удаляются.

<Info>
Восстановление связки «группа + её инвентарь» построено на близости времени создания и совпадении способа архивации, а не
на явной технической связи между записями. При операциях с задержкой больше указанных окон автоматическая связка может не
сработать, и часть записей придётся восстанавливать отдельным запросом.
</Info>

**Права доступа.** Действие доступно только аутентифицированным пользователям. Дополнительная проверка права на удаление
конкретного типа (инвентарь/группа/услуга/комплект) применяется только тогда, когда в теле запроса присутствует один из
четырёх специальных списков идентификаторов — причём проверяется только первый по приоритету из присутствующих (инвентарь
→ группа → услуга → комплект), даже если в запросе одновременно указано несколько списков.

<Warning>
Если тело запроса не содержит ни одного из этих четырёх списков — например, при восстановлении клиента, категории, точки
проката, периода времени, скидки, вида/счёта/статьи оплаты, контрагента или склада через общий список идентификаторов
записей архивации — проверка права на удаление полностью пропускается, и действие разрешено любому аутентифицированному
пользователю.
</Warning>

**Фильтр списка заархивированных записей.** Доступны фильтры:

- по способу архивации и по автору архивации (точное совпадение);
- по дате архивации (диапазон «с»/«по»);
- по связанному инвентарю, услуге, комплекту (наличие/отсутствие, точное совпадение, вхождение в список);
- по группе — специальный фильтр находит как записи, заархивированные напрямую как группа, так и записи по инвентарю,
  входящему в эту группу;
- по признаку «группа не указана» — в отличие от фильтра по группе выше, здесь проверяется только прямая связь с группой,
  через инвентарь эта связь не ищется;
- по категории — находит записи по инвентарю, группе или услуге, относящимся к данной категории (но не саму запись об
  архивации категории как таковой);
- по точке проката — находит только записи по инвентарю, привязанному к этой точке проката (группы, услуги и сама запись
  об архивации точки проката этим фильтром не учитываются).

### Каталог: инвентарь, группы, комплекты, услуги

Раньше у единиц инвентаря, групп (продуктов), комплектов и услуг было собственное булево поле «Удалён» (и часто ещё дата
удаления). Теперь ни у одной из этих моделей такого поля нет — вместо этого при архивации создаётся отдельная запись
«Архивация», ссылающаяся ровно на одну сущность.

#### Единица инвентаря

При обычном удалении единицы инвентаря через карточку она физически не удаляется — создаётся запись «Архивация» со
способом «Удаление», автор — текущий пользователь. Строка инвентаря остаётся в базе со всеми связями (историей аренд,
начислениями и т.д.).

В списках и в карточке единицы наружу отдаются два производных признака, вычисляемых на лету при построении выборки, а не
хранимых в таблице: признак способа архивации (пусто, если единица активна) и логический признак «удалена» (истина, если
для единицы существует запись «Архивация», независимо от способа).

Проверка уникальности идентификатора единицы инвентаря включается отдельной настройкой компании (по умолчанию выключена).
Когда настройка включена, проверка учитывает только действующие (не заархивированные) записи — идентификатор освобождается
после удаления, архивации или списания и может быть присвоен новой единице.

**Статус единицы и место архивации в приоритете статусов.** Отображаемый статус вычисляется по цепочке условий, где
архивация — один из факторов наравне с состоянием аренды, склада и ремонта. Порядок проверки (первое сработавшее условие
побеждает):

1. единица сейчас в аренде — статус «В аренде»;
2. единица сейчас забронирована на выбранный период — статус «Забронирован»;
3. по единице просрочен возврат — статус «Просрочен»;
4. есть запись «Архивация» со способом «Списание» — статус «Списан»;
5. есть запись «Архивация» с любым другим способом (Удаление или Архивация) — статус «Отключён»;
6. единица числится на складе — статус «На складе»;
7. по единице есть незавершённая заявка в мастерской — статус «В ремонте»;
8. состояние единицы помечено как неисправное — статус «Сломан»;
9. у единицы проставлена дата продажи — статус «Продан»;
10. иначе — статус «Свободен».

Если единица одновременно заархивирована и, например, находится на складе или в ремонте, приоритет всегда получает
статус, связанный с архивацией (Списан/Отключён).

<Info>
В сводной выборке без учёта конкретного периода аренды порядок незначительно отличается: там нет проверок «в аренде» /
«забронирован» / «просрочен» (они привязаны к выбранному диапазону дат), а незавершённая задача в мастерской даёт статус
«Сломан», а не «В ремонте». Архивация (Списание/иной способ) в этой выборке проверяется первой, то есть имеет наивысший
приоритет.
</Info>

При подборе свободных единиц под конкретный период аренды из выборки исключаются: единицы с пересекающимся расписанием в
статусе «В аренде»/«Забронирован» и с просрочкой; проданные единицы; единицы на складе; единицы с неисправным состоянием;
и **любая единица с записью «Архивация», независимо от способа архивации**. То есть для доступности расписания способ
архивации не важен — Удаление, Архивация и Списание одинаково делают единицу недоступной для бронирования.

#### Группа (продукт)

У группы, как и у единицы инвентаря, отдельного поля «Удалена» больше нет — статус определяется той же связанной записью
«Архивация». При обычном удалении группы через карточку создаётся запись «Архивация» со способом «Удаление» — только для
самой группы, без затрагивания её инвентаря.

При массовой архивации (см. выше) архивация группы — это не «одна запись на группу и всё»: система дополнительно
создаёт отдельную запись «Архивация» для каждой ещё не заархивированной единицы инвентаря, входящей в эту группу. То есть
при массовой архивации группа каскадно архивирует весь свой действующий инвентарь, а не только саму карточку группы — в
отличие от обычного (одиночного) удаления группы через карточку, которое такого каскада не делает.

В списках группы точно так же, как и для инвентаря, наружу отдаются вычисляемые (не хранимые) признаки: способ архивации
и логический признак «удалена».

Число «активных единиц в группе» считается по единицам, у которых одновременно: не проставлена дата продажи, единица не
числится на складе и нет записи «Архивация». Число «свободных на выбранный период» использует то же условие об
отсутствии архивации, но дополнительно учитывает пересечение с текущим расписанием аренды/брони и неисправное состояние
единицы. Признак «есть суб-аренда» в карточке группы считается мягче — он смотрит только на отсутствие архивации, не
исключая при этом проданные или складские единицы.

<Warning>
Из-за разного набора условий признак «есть суб-аренда в группе» теоретически может оказаться истинным даже тогда, когда
единственная единица суб-аренды в группе уже продана или лежит на складе (она не заархивирована, значит попадает под
условие наличия суб-аренды, хотя не попадает в счётчик активных/свободных единиц).
</Warning>

Проверка уникальности идентификатора группы включается той же настройкой компании (по умолчанию выключена); когда она
включена, проверка учитывает только действующие (не заархивированные) группы. Отдельное поле «штрихкод» у группы такой
проверки уникальности не имеет.

#### Комплекты

Комплект (набор единиц инвентаря) архивируется тем же самым образом: собственного поля «Удалён» у комплекта нет, вместо
него — однозначная связанная запись «Архивация». Обычная и массовая архивация комплекта создают запись «Архивация»
только для самого комплекта — в отличие от группы, архивация комплекта не создаёт дополнительных записей для входящих в
него единиц инвентаря.

#### Услуги

При обычном удалении услуги через карточку, как и у инвентаря/групп, физического удаления не происходит — создаётся
запись «Архивация» со способом «Удаление».

Помимо обычного удаления, для услуги есть отдельный переключатель («тумблер») архивации, а не одностороннее действие:

- если у услуги ещё нет ни одной записи «Архивация» — создаётся новая со способом «Архивация»;
- если запись «Архивация» уже есть (**любая**, включая созданную обычным удалением со способом «Удаление») — она
  удаляется, и услуга снова становится действующей.

В отличие от инвентаря и групп (где заархивированные записи по-прежнему возвращаются в списках вместе с признаками
«удалена»/способ архивации, чтобы интерфейс мог показать их как неактивные), стандартные список услуг, карточка услуги и
сводная статистика по услугам **полностью исключают** услуги с любой записью «Архивация» — такие услуги в этих выборках
просто не появляются. Увидеть все заархивированные сущности (в том числе услуги) можно только через отдельный общий
список заархивированных записей.

#### Сводная таблица способов архивации

| Способ | Что означает для бизнеса |
|---|---|
| Удаление | Обычное «мягкое» удаление записи из карточки/списка |
| Архивация | Временное скрытие без потери данных, чаще всего используется для услуг через отдельный переключатель |
| Списание | Вывод физической единицы инвентаря из оборота (для инвентаря именно этот способ даёт отдельный статус «Списан», а не общий «Отключён») |

### Клиенты, категории, точки проката, периоды времени и скидки

Общий принцип тот же: вместо отдельных булевых полей «удалён», архивация клиента, категории, точки проката, периода
времени или скидки оформляется отдельной записью «Архивация» с автором, способом, комментарием и доп. данными.

<Info>
В четырёх из пяти сущностей этой подобласти — категории, точки проката, периоды времени и скидки — удаление через карточку
записи фактически не удаляет сущность физически: создаётся запись «Архивация» со способом «Удаление», а строка справочника
остаётся в базе и только перестаёт считаться активной. Пятая сущность — клиенты — устроена иначе (см. ниже).
</Info>

Поведение списковых и детальных запросов различается по сущностям:

| Сущность | Заархивированные записи скрываются по умолчанию? | Можно ли явно запросить показать заархивированные |
|---|---|---|
| Клиенты | Да, всегда | Нет |
| Категории инвентаря | Да, всегда | Нет |
| Точки проката | Да, всегда | Нет |
| Периоды времени | Нет, показываются все | Нет отдельного параметра — различить можно только по признаку в самой записи |
| Скидки | Нет, показываются все, если не задан отдельный параметр фильтра | Да, отдельным параметром фильтра по признаку архивации |

**Клиенты.** Список и карточка клиента по умолчанию показывают только клиентов без записи «Архивация». Фильтр по
клиентам формально поддерживает параметр «показать только заархивированных / только активных», но поскольку список
клиентов и так всегда жёстко ограничен активными записями, этот параметр на практике ничего не меняет.

<Warning>
В отличие от остальных сущностей этой подобласти, удаление клиента через карточку сегодня не создаёт запись «Архивация» —
оно выполняет настоящее физическое удаление строки клиента из базы. Перед удалением система также удаляет заявки этого
клиента, к которым не прикреплён ни один инвентарь (заявки с инвентарём не трогаются). Если удаление невозможно (например,
из-за оставшихся связанных записей), запрос завершается ошибкой конфликта, и клиент остаётся нетронутым — удаление заявок
и клиента выполняется в рамках одной операции, поэтому при ошибке откатывается всё целиком.
</Warning>

Связь клиента с «Архивацией» в базе существует (и используется в фильтрах списков), но её единственный источник данных
сегодня — разовый перенос исторических данных: клиенты, которые раньше были помечены старым булевым флагом «удалён»,
получили соответствующую запись «Архивация» со способом «Удаление» задним числом. Новых архиваций клиентов через
обычное удаление механизм не создаёт.

**Категории инвентаря.** Список категорий выводится в порядке, заданном вручную, и по умолчанию содержит только категории
без записи «Архивация». Удаление через карточку создаёт запись «Архивация» со способом «Удаление»; сама категория из
базы не удаляется.

<Note>
Архивация родительской категории не архивирует и не скрывает автоматически её дочерние категории — связь «родитель →
дочерние» рвётся только при физическом удалении строки, а «Архивация» физического удаления не делает. Поэтому дочерние
категории заархивированного раздела могут по-прежнему отображаться как активные.
</Note>

Поскольку строка категории при архивации не удаляется, а название-слаг категории должно быть уникальным в рамках
компании, новую категорию нельзя создать с тем же непустым слагом, что и у ранее заархивированной категории.

**Точки проката.** Список и карточка по умолчанию показывают только точки без записи «Архивация». Удаление создаёт
запись «Архивация» (способ — «Удаление») и сразу же, в рамках того же запроса, пересчитывает занятость лимита точек
проката по тарифному плану компании — освобождённое место в лимите сразу становится доступно для создания новой точки.

<Tip>
Создание новой точки проката проверяется относительно того же лимита: если число активных (не заархивированных) точек уже
достигло лимита тарифного плана, запрос на создание новой точки отклоняется с ошибкой превышения лимита подписки.
Архивация точки и создание новой связаны напрямую через один и тот же счётчик.
</Tip>

Привязки сотрудников к точкам проката — отдельный список, который фильтруется только по идентификатору точки и никак не
учитывает, заархивирована точка или нет. Сотрудник может остаться привязанным (или быть заново привязан) к уже
заархивированной точке проката — механизм архивации не запрещает и не разрывает такие привязки автоматически.

**Периоды времени.** В отличие от клиентов, категорий и точек проката, список и карточка периода времени по умолчанию
возвращают все периоды — и активные, и заархивированные. Единственный способ отличить их — признак архивации, который
передаётся в каждой записи ответа; отдельного параметра фильтра для этого списка не предусмотрено. Удаление через
карточку создаёт запись «Архивация» со способом «Удаление»; сам период из базы не удаляется и продолжает попадать в
общий список.

**Скидки.** Список и карточка скидки по умолчанию тоже возвращают все скидки — и активные, и заархивированные, с тем же
признаком архивации в каждой записи. Но, в отличие от периодов времени, для скидок дополнительно доступен параметр
фильтра, позволяющий явно запросить только активные или только заархивированные скидки. Удаление через карточку создаёт
запись «Архивация» со способом «Удаление»; сама скидка из базы не удаляется.

<Info>
У скидки есть отдельный признак «действует / не действует», не связанный с «Архивацией» напрямую: это временный
переключатель, которым можно на время выключить скидку, не убирая её из каталога и не создавая запись «Архивация».
«Архивация», в отличие от этого переключателя, предназначена для окончательного вывода скидки из активного использования.
Отдельно связь клиента со скидкой устроена так, что скидку нельзя физически удалить из базы, пока хотя бы один клиент на
неё ссылается, — использование «Архивации» вместо прямого удаления строки согласуется с этим ограничением: скидку можно
скрыть из активного каталога, не нарушая существующие связи с клиентами.
</Info>

### Финансовые справочники и склад

Виды оплаты, счета, статьи оплат, контрагенты и склады больше не имеют собственного признака «удалён». При архивации
любой из этих записей создаётся отдельная связанная запись «Архивация» со способом архивации, автором и (потенциально)
комментарием. В рамках рассмотренных экранов каждая запись «Архивация» связана ровно с одной сущностью. Однако конкретное
поведение отличается в зависимости от типа справочника: виды/счета/статьи оплат используют «Архивацию» как
**необратимое скрытие**, а контрагенты и склады — как **переключатель архивации/восстановления**.

| Сущность | Способ при архивации | Восстановление через тот же запрос |
| --- | --- | --- |
| Вид оплаты | Удаление | Недоступно |
| Счёт | Удаление | Недоступно |
| Статья оплат | Удаление | Недоступно |
| Контрагент | Архивация | Да — повторный запрос возвращает запись в активное состояние |
| Склад | Архивация | Да — повторный запрос возвращает запись в активное состояние |

Во всех пяти случаях автором архивации записывается пользователь, выполнивший запрос; комментарий и дополнительные
данные не заполняются этими действиями и остаются пустыми по умолчанию.

**Виды оплаты, счета и статьи оплат: архивация без возврата.** Для этих трёх справочников список и карточка одной записи
всегда показывают только действующие записи. Как только запись заархивирована, она пропадает из списка и перестаёт
открываться по прямому запросу карточки. Действие «удалить» на карточке всегда создаёт ровно одну новую запись «Архивация»
со способом Удаление. Поскольку связь между справочником и его «Архивацией» — «один к одному», повторно выполнить это же
действие над уже заархивированной записью через эти экраны нельзя.

<Warning>
Архивация вида оплаты, счёта или статьи оплат необратима: обратной кнопки «восстановить» для них нет ни на этих экранах,
ни где-либо ещё в приложении — запись просто перестаёт быть доступной для выбора и отображения в действующих списках.
</Warning>

<Note>
Список счетов дополнительно добавляет в конец выдачи один синтетический (не хранящийся в базе) элемент «Без счёта» — это
сумма всех оплат, у которых счёт не указан. У этого элемента нет идентификатора, его нельзя ни редактировать, ни
заархивировать — он служит только для наглядного отображения неразнесённого остатка.
</Note>

**Контрагенты и склады: архивация как переключатель.** Для контрагентов и складов список и карточка, наоборот, **не
скрывают** заархивированные записи — обе выдачи включают и активные, и заархивированные записи, но дополнительно
помечают каждую признаком «есть ли архивация». Действие «удалить» на карточке контрагента или склада работает как
переключатель:

1. Если у записи ещё нет связанной «Архивации» — создаётся новая, со способом Архивация. Запись становится архивной, но
   сама запись контрагента/склада и вся связанная с ней история никуда не удаляется.
2. Если связанная «Архивация» уже существует — она удаляется целиком. Это возвращает контрагента или склад в активное
   состояние.

<Note>
Одно и то же действие «удалить» на карточке контрагента или склада по очереди архивирует и восстанавливает запись: первый
вызов архивирует, второй — восстанавливает обратно, третий — снова архивирует и так далее.
</Note>

<Warning>
При восстановлении (втором вызове) старая запись «Архивация» удаляется без сохранения истории — сведения о том, кем и
когда запись была заархивирована ранее, теряются. Если запись заархивируют снова, будет создана новая «Архивация» с новым
автором и текущей датой.
</Warning>

**Права доступа.**

| Группа справочников | Кто может просматривать | Кто может создавать/изменять/архивировать |
| --- | --- | --- |
| Виды оплаты, счета, статьи оплат | Любой аутентифицированный пользователь | Только пользователи с точечным разрешением на добавление/изменение/удаление именно этой модели |
| Контрагенты, склады | Любой аутентифицированный пользователь | Любой аутентифицированный пользователь — отдельного разрешения не требуется |

Дополнительно: список контрагентов можно отфильтровать по признаку «свой/сторонний» (не связано с архивацией); список
статей оплат — по типу (приходная/расходная), также независимо от механизма архивации. Список позиций на складе (остатки
товаров) скрывает позиции, у которых заархивирована сама группа товара, но не проверяет архивацию самого склада.

### Легаси-флаг «Удалена» у заявок

У заявки на аренду мягкое удаление реализовано не через общую запись «Архивация», а через собственное булево поле прямо
на самой заявке — «Удалена» (по умолчанию выключено). Это осознанное исключение: когда остальные справочники и каталоги
были переведены на единый механизм «Архивация» с автором, способом и комментарием, заявки остались на старой схеме и не
были мигрированы.

<Warning>
У флага «Удалена» нет ни автора, ни способа архивации, ни комментария, ни произвольных дополнительных данных — в отличие
от записи «Архивация», это просто «да/нет» на самой заявке.
</Warning>

Рядом с этим флагом на заявке есть отдельное поле «Активна» — оно не про удаление, а про то, содержит ли заявка реальное
наполнение (услуги, взятый в аренду или проданный инвентарь, привязанный клиент, поступившая оплата, депозиты, доставки).
Оно автоматически пересчитывается при каждом сохранении уже существующей заявки. В базе есть специальный индекс, который
считает «действующими» записи, у которых поле «Активна» включено, а поле «Удалена» — выключено; это ближайший аналог
фильтра по действующим записям, применяемого к другим сущностям через отдельную запись «Архивация».

**Как заявка получает и снимает этот статус.** Флаг переключается только из обработчиков запросов — в самой логике
сохранения заявки он не устанавливается автоматически. Основная операция удаления заявки сначала выполняет два общих шага
для любого инициатора, и только потом расходится по разным путям в зависимости от роли:

- у всех проданных в рамках заявки товаров сбрасываются дата и цена продажи (они возвращаются в непроданное состояние) —
  это происходит всегда, независимо от того, кто инициирует обращение;
- если заявка пришла из внешней интеграции (у неё указан идентификатор из системы Plus), обработка на этом останавливается
  для любого инициатора — заявка не удаляется физически, не архивируется, и флаг «Удалена» не выставляется.

Если заявка прошла эту проверку, дальнейшее поведение зависит от роли инициатора.

<Steps>
  <Step title="Полное удаление (только для суперпользователя компании)">
    Происходит настоящее физическое удаление, а не простановка флага: последовательно удаляются все связанные записи
    заявки (позиции инвентаря, услуги, рефералы, депозиты, доставки, действия, паузы, штрафы, записи расписания
    инвентаря, финансовые транзакции), лиды в CRM отвязываются от заявки (а не удаляются), инвентаризации отвязываются, и
    только после этого удаляется сама заявка.
  </Step>
  <Step title="Мягкое архивирование (для остальных пользователей)">
    Заявка не удаляется физически, а «архивируется»: создаётся запись действия по заявке с типом «Архивация» (фиксирует
    пользователя и время), флаг «Удалена» выставляется во включённое состояние, а проданные товары дополнительно
    отвязываются от действия «Выдача» со сбросом фактических дат начала и окончания. Затем заявка пересохраняется целиком
    — это заново запускает весь расчёт статуса, активности и связанные с сохранением автоматические действия.
  </Step>
  <Step title="Отдельная ручка переключения архивации">
    Существует ещё одна, отдельная операция удаления заявки, которая не делает ничего из перечисленного выше: она просто
    инвертирует значение флага «Удалена» на противоположное и сохраняет заявку.
  </Step>
</Steps>

<Note>
Повторный вызов ручки переключения к той же заявке восстанавливает её обратно (снимает флаг). При этом никакая запись
действия с автором и временем не создаётся — в отличие от мягкого архивирования через основную операцию удаления, где
переключение архивации проходит полностью без следа в журнале действий.
</Note>

**На что влияет включённый флаг «Удалена».** Как только флаг включён, заявка исключается из большинства автоматических
процессов и подсчётов:

- не создаётся и не пересчитывается бонусное начисление клиенту по этой заявке, даже если по остальным условиям (статус
  «Завершена», оплата полностью получена) бонус полагался бы;
- не пересчитывается статистика клиента для присвоения меток/уровней;
- не создаются и не обновляются связанные лиды и переходы по воронкам CRM;
- не отправляется уведомление клиенту об изменении статуса заявки;
- пересчёт оплаченной суммы и связанного расписания транзакций по заявке пропускается;
- полный пересчёт состава и автопродления заявки не выполняется;
- при периодическом фоновом расчёте штрафа за просрочку такая заявка пропускается, а любая ранее запланированная задача
  автоштрафа по ней удаляется;
- плановые задачи по проверке и расчёту приближающегося штрафа создаются или обновляются в выключенном состоянии, то
  есть не сработают;
- заявка не рассматривается как «текущая аренда» инвентаря при отправке уведомлений о техобслуживании товара;
- флаг используется практически везде, где нужно показать только действующие заявки: в счётчиках заявок по статусам, в
  статистике по клиентам, в списке рефералов по заявкам, в сводках дашборда и в ряде других выборок.

**Отличия от единого механизма «Архивация»:**

| Параметр | Единый механизм «Архивация» | Легаси-флаг заявки |
| --- | --- | --- |
| Где хранится | Отдельная связанная запись | Булево поле на самой заявке |
| Автор | Фиксируется в записи | Фиксируется только в одном из двух сценариев изменения флага (через запись действия «Архивация»); в другом — не фиксируется вовсе |
| Способ (удаление/архив/списание) | Фиксируется значением из перечня способов | Не фиксируется — есть только «да/нет» |
| Комментарий и доп. данные | Поддерживаются | Отсутствуют |
| Физическое удаление | Заменено архивацией полностью | Всё ещё возможно и используется параллельно (только для суперпользователя компании, и тоже блокируется для заявок из внешней интеграции Plus) |
| Обратимость | Восстановление = удаление записи «Архивация» | Восстановление = отдельная операция, инвертирующая флаг без журнала |

<Tip>
При работе с заявками стоит помнить: единый фильтр «действующая запись» здесь выражается не признаком отсутствия
связанной архивации, а прямой проверкой того, что флаг «Удалена» выключен — эти две проверки не взаимозаменяемы и не
связаны программно.
</Tip>

## Подводные камни

<Warning>
Доп. данные, переданные в запросе на массовую архивацию, никогда не попадают в создаваемые записи «Архивация» — поле
всегда остаётся пустым независимо от того, что было прислано, введённая информация теряется.
</Warning>

<Warning>
Проверка на активную аренду или бронь перед архивацией выполняется только для инвентаря — комплекты и услуги можно
заархивировать без какой-либо проверки на то, используются ли они прямо сейчас.
</Warning>

<Warning>
Проверка права на удаление конкретного типа (инвентарь/группа/услуга/комплект) срабатывает только когда в теле запроса
присутствует одноимённый список идентификаторов. Для клиентов, категорий, точек проката, периодов времени, скидок,
видов/счетов/статей оплаты, контрагентов, складов, а также при восстановлении через общий список идентификаторов записей
архивации — проверка полностью пропускается, и действие доступно любому авторизованному пользователю.
</Warning>

<Warning>
Стандартная выборка ни у одной из моделей не исключает заархивированные записи автоматически — каждый экран и каждый
отчёт обязаны сами добавлять условие «нет связанной архивации». Если новый экран или интеграция обратится к данным без
этого условия, в результат попадут и удалённые, и архивные, и списанные записи.
</Warning>

<Warning>
Удаление клиента через карточку сегодня выполняет настоящее физическое удаление строки клиента (и его заявок без
прикреплённого инвентаря), а не создание записи «Архивация» — в отличие от категорий, точек проката, периодов времени и
скидок, где удаление всегда идёт через архивацию.
</Warning>

<Warning>
Для видов оплаты, счетов и статей оплат архивация необратима во всём приложении: восстановить такую запись нельзя ни
через тот же экран, ни через какой-либо другой раздел системы.
</Warning>

<Warning>
Переключатель архивации услуги не проверяет способ уже существующей архивации: если услугу сначала удалили обычным
способом, а затем вызвали переключатель архивации, результатом будет не архивация поверх удаления, а полное снятие
архивации — услуга снова станет видна и активна, как будто её никогда не удаляли.
</Warning>

<Warning>
Заявки, пришедшие из внешней интеграции (система Plus), нельзя ни физически удалить, ни архивировать через основную
операцию удаления — обработка молча прерывается для любого инициатора, независимо от роли, и флаг «Удалена» не
выставляется.
</Warning>

Дополнительные, менее критичные особенности:

- Массовая архивация группы не ограничивается одной записью на группу — дополнительно создаётся отдельная запись
  «Архивация» для каждой ещё не заархивированной единицы инвентаря внутри этой группы. Обычное (одиночное) удаление
  группы через карточку такого каскада не делает.
- Восстановление связки «группа + её инвентарь» после массовой архивации работает по эвристике близости времени
  создания записей (в пределах минуты), а не по прямой технической связи — при большом разрыве по времени часть записей
  может не восстановиться автоматически или, наоборот, архивация может быть снята не с тех записей.
- Признаки «удалена» и «способ архивации» в ответах по инвентарю и группам — это не поля таблицы, а данные, которые
  добавляет конкретный экран на лету; при обращении к данным в обход этого экрана эти признаки будут недоступны.
- Проверка уникальности идентификатора у единицы инвентаря и у группы включается отдельной настройкой компании (по
  умолчанию выключена); только при включённой настройке проверка учитывает лишь действующие записи, поэтому идентификатор
  ранее удалённой/архивной/списанной записи можно присвоить новой без конфликта.
- Обычные список, карточка и сводная статистика по услугам полностью скрывают заархивированные услуги, тогда как
  инвентарь и группы продолжают возвращаться в списках с пометкой о способе архивации, позволяя интерфейсу показывать их
  как неактивные, а не полностью скрывать.
- У группы нет отдельной проверки уникальности для поля «штрихкод» — она есть только у идентификатора, и то лишь при
  включённой настройке компании.
- У комплекта, в отличие от группы, архивация (как обычная, так и массовая) не создаёт дополнительных записей для
  входящих в него единиц инвентаря — затрагивается только сама запись комплекта.
- Периоды времени и скидки по умолчанию показываются в списках вместе с заархивированными записями — различить их можно
  только по отдельному признаку внутри самой записи; отдельного параметра «скрыть заархивированные» для периодов времени
  нет вовсе, а для скидок он есть.
- Фильтр клиентов формально поддерживает параметр «показать только заархивированных», но поскольку список клиентов и так
  всегда жёстко ограничен активными записями, этот параметр на практике всегда возвращает пустой список.
- Архивация родительской категории не архивирует и не скрывает автоматически дочерние категории — они могут по-прежнему
  отображаться как активные.
- Название (слаг) категории уникально в рамках компании даже для заархивированных записей, поэтому создать новую
  категорию с тем же именем, что и у ранее заархивированной, нельзя, пока со старой записи не снимут этот слаг.
- Архивация точки проката сразу и синхронно (в рамках того же запроса, а не в фоновой очереди) пересчитывает лимит точек
  проката по тарифу компании и сразу освобождает место для создания новой точки; при этом привязки сотрудников к точкам
  проката не проверяют, заархивирована ли точка, — сотрудник может остаться привязанным к уже заархивированной точке.
- У скидки есть отдельный, независимый от архивации переключатель «действует/не действует» для временного скрытия без
  полного вывода из каталога.
- При восстановлении контрагента или склада (повторный вызов «удаления») прежняя запись архивации удаляется без
  сохранения истории — данные о предыдущем авторе и времени архивации теряются безвозвратно.
- Комментарий и дополнительные данные не указываются при архивации/восстановлении контрагентов, складов, видов оплаты,
  счетов и статей оплат — причина в текстовом виде на этих экранах не фиксируется.
- Просмотр списков видов оплаты, счетов и статей оплат разрешён любому авторизованному пользователю независимо от наличия
  у него разрешения на модель, тогда как создание, изменение и архивация требуют точечного разрешения; для контрагентов
  и складов действует единое требование — только факт входа в систему, без разбивки по операциям.
- Список остатков товаров по складам скрывает позиции, у которых заархивирована группа товара, но не проверяет архивацию
  самого склада, — архивация склада сама по себе не прячет его остатки из этого отдельного списка.
- Модель архивации также содержит связи с сущностями воронки продаж (лид и этап воронки), которые не входят в описанный
  для этого раздела перечень поддерживаемых сущностей — фактический охват механизма шире заявленного.
- После любой архивации или восстановления через общий инструмент массовых операций всегда запускаются фоновые задачи
  пересчёта лимитов по количеству техники (автомобили, скутеры, мотоциклы) — даже если менялся только клиент, точка
  проката или другая не связанная с инвентарём сущность, а не сам инвентарь.
- Полнотекстовый поиск по списку заархивированных записей не поддерживает поиск по комплектам — только по инвентарю,
  группам и услугам.
- Полное (физическое) удаление заявки доступно только суперпользователю компании и каскадно удаляет все связанные записи
  (инвентарь, услуги, рефералы, депозиты, доставки, действия, паузы, штрафы, расписание, транзакции).
- Флаг «Удалена» по умолчанию выключен и нигде в общей логике сохранения заявки автоматически не включается — его меняют
  только два отдельных обработчика удаления/архивации, в отличие от единого механизма архивации, где архивация
  создаётся декларативно через общий инструмент массовых операций.
