Полный перечень понятий — в [глоссарии подписей](/ru/logic/audit/labels-glossary).

Журнал хранит **данные**, а не готовый текст строки. Названия действий, полей и объектов подставляются в двух разных
моментах, и от этого зависит их поведение: одни фиксируются навсегда в момент события, другие подбираются каждый раз при
чтении и потому меняются вместе с настройками компании и языком интерфейса.

## Что фиксируется в момент события

| Подпись | Почему записывается сразу |
| --- | --- |
| Подпись инициатора | Пользователь может быть переименован или удалён; строка должна остаться читаемой |
| Подпись объекта | Объект может быть удалён — после этого восстановить его название нечем |
| Подписи значений с фиксированным набором | Набор значений может измениться; журнал обязан показывать то, что было выбрано тогда |
| Названия объектов, на которые ссылаются поля | Связанный объект может быть удалён или переименован |

Эти четыре подписи в журнале уже не меняются — они снимок на момент действия.

## Что подбирается при чтении

| Подпись | Как определяется |
| --- | --- |
| Название действия | Готовая фраза, если она задана для этого действия; иначе складывается из названия справочника и слова «запись создана», «запись обновлена» или «запись удалена» |
| Название поля | Заданное вручную человеческое название поля. Если названия нет, интерфейс показывает имя колонки как есть |
| Название вида объекта | Человеческое название справочника, к которому относится объект события |
| Значения статуса аренды | Названия статусов подставляются с учётом переименований компании |

Подбор на чтении даёт два важных следствия. Во-первых, событие, записанное **до** появления человеческого названия у
поля, всё равно получит это название — журнал не приходится переписывать. Во-вторых, одно и то же событие читается
по-разному на разных языках и в разных компаниях: подписи следуют языку запроса и настройкам той компании, которая их
запрашивает.

## Переименования компании выше системных названий

Компания вправе называть системные сущности своими словами — прокат автомобилей говорит «автомобиль» вместо «инвентарь»
и «водитель» вместо «клиент», сервисный центр — «заказ-наряд» вместо «мастерской». Весь интерфейс это уважает, и журнал
не исключение: если бы он говорил «инвентарь», строка расходилась бы с остальной системой.

Переименования применяются в четырёх местах:

- **Метка объекта события** — «Автомобиль» вместо «Инвентарь» на плашке рядом со строкой.
- **Складное название действия** — «Автомобиль: запись обновлена».
- **Название поля-ссылки**, указывающего на переименованную сущность — поле «Клиент» становится «Водитель».
- **Значения статуса аренды** — если компания переименовала статусы, в изменении статуса будут её слова.

Переименовать можно восемь сущностей: инвентарь, группу инвентаря, комплект, услугу, точку проката, клиента, залог и
мастерскую. Плюс семь статусов аренды: запрос, бронь, в прокате, отменено, завершено, должник, просрочено.

Правило выбора значения повторяет экран наименований: **строка компании перекрывает общую строку** для её типа бизнеса.
В отличие от того экрана здесь дополнительно учитывается язык: подпись обязана следовать языку запроса, а не той строке,
которая окажется последней.

<Note>
Готовые формулировки действий переименованиям **не** подчиняются. «Клиент изменён» — это законченная фраза, согласованная
по роду; подстановка чужого существительного дала бы «Машина продан». Поэтому переименования достают только те подписи,
где существительное стоит отдельно: метку объекта, складное название и название поля-ссылки. По той же причине не
переименовываются и названия разделов журнала.
</Note>

## Поля, сохраняющие своё название

Поле-ссылка получает название переименованной сущности только тогда, когда оно действительно означает эту сущность.
Есть поля, у которых смысл уже, чем сущность, на которую они ссылаются, и подстановка сделала бы их
неотличимыми от соседних:

| Поле | Почему сохраняет своё название |
| --- | --- |
| Точка возврата в аренде | Ссылается на точку проката, но означает именно точку **возврата**; иначе она слилась бы с точкой выдачи |
| Заказ мастерской в платеже | Ссылается на мастерскую, но означает конкретный заказ, к которому относится платёж |

Система следит за этим сама: если после подстановки переименований у двух полей одного справочника получились бы
одинаковые названия, это считается ошибкой конфигурации.

## Подстановка названий на стороне интерфейса

Названия связанных объектов журнал начал сохранять в саму строку не с самого начала. Для событий, записанных раньше,
интерфейс подставляет названия из справочников, которые он и так держит загруженными: сотрудники, способы оплаты, точки
проката, категории инвентаря, источники привлечения клиентов. Если и это не помогло, показывается номер объекта, а для
поля без человеческого названия — имя колонки с заглавной буквы.

## Язык

Язык определяется по запросу; если он не задан, берётся язык системы по умолчанию. Русский язык основной, остальные
подписи подставляются из переводов интерфейса. Названия, введённые компанией, языком не переводятся — они хранятся по
языкам отдельно, и подбирается строка нужного языка.
