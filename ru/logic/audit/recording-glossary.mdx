Справочник к странице [«Как события попадают в журнал»](/ru/logic/audit/recording).

## Понятия

| Понятие | Значение |
| --- | --- |
| Контекст запроса | Набор сведений об обращении, собираемый один раз и наследуемый всеми событиями запроса: инициатор, его тип и подпись, карточка клиента, адрес, устройство, идентификатор запроса. |
| Буфер запроса | Накопитель событий на время обработки запроса. Сохраняется одной операцией в конце обработки, а не по событию. |
| Ключ склейки | Тройка «компания, действие, основной объект». Второе событие с тем же ключом не создаёт новую строку, а сливается с накопленным. |
| Слияние событий | Правило объединения двух событий с одним ключом: у изменённого поля остаётся самое раннее «было» и самое позднее «стало», дополнительные данные и объекты дополняются, подпись объекта берётся последняя непустая. |
| Автоматическое событие | Событие, созданное наблюдением за полями: «создана», «обновлена», «удалена». Может быть поглощено смысловым. |
| Смысловое событие | Событие, записанное кодом бизнес-процесса под собственным именем: выдача аренды, возврат залога, подписание документа, вход в систему. |
| Поглощение | Передача изменений полей от автоматического события смысловому событию того же основного объекта. Хозяин ищется только по объекту, действие не учитывается. |
| Отбрасывание пустого события | Автоматическое событие без изменений и без дополнительных данных в журнал не попадает. |
| Запись вне запроса | Режим без контекста: событие пишется сразу и по одному, инициатора нет, тип — «Система», реквизиты запроса пустые. |
| Компания события | Обязательная привязка события. Берётся из текущего подключения, может быть передана явно, а на страницах без компании выводится из единственного места работы пользователя. |
| Изоляция сбоев | Ошибка при записи журнала перехватывается и не прерывает основную операцию: теряется строка, а не запрос. |

## Порядок определения типа инициатора

| Шаг | Условие | Тип |
| --- | --- | --- |
| 1 | Пользователь не авторизован | Анонимно |
| 2 | Пользователь — глобальный администратор платформы | Платформа |
| 3 | У пользователя есть действующее место работы в компании | Пользователь |
| 4 | Ни одно из условий выше не выполнено | Клиент (с запоминанием карточки клиента) |

## Что попадает в контекст

| Сведение | Источник |
| --- | --- |
| Инициатор | Пользователь запроса; анонимный запрос инициатора не даёт |
| Тип инициатора | Права пользователя, в порядке из таблицы выше |
| Подпись инициатора | Текстовое представление пользователя на момент запроса, до 255 символов |
| Карточка клиента | Заполняется, только если инициатор определён как клиент и компания известна |
| Идентификатор запроса | Входящий заголовок запроса либо значение, сгенерированное системой |
| Адрес | Первый адрес из цепочки прокси, иначе адрес соединения |
| Устройство | Строка браузера или приложения, до 512 символов |

## Правила слияния

| Что сливается | Правило |
| --- | --- |
| Изменения полей | Самое раннее «было» и самое позднее «стало»; промежуточные значения теряются |
| Дополнительные данные | Более позднее значение перекрывает более раннее по совпадающим ключам |
| Объекты события | Объединение списков; роль закрепляется за первым упоминанием объекта |
| Подпись объекта | Последняя непустая |
