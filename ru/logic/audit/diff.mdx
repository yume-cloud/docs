Полный перечень видов изменения — в [глоссарии изменений](/ru/logic/audit/diff-glossary).

Изменения хранятся построчно: одно поле — одна запись. Поле, значение которого не изменилось, не попадает в журнал
вообще, поэтому длина списка изменений равна числу реально затронутых полей. Как именно показать изменение, решает
**вид изменения** — он выбирается по типу поля и по размеру значений.

## Как выбирается вид

Проверки идут строго по порядку, и первая подошедшая определяет вид.

1. **Имя поля в списке чувствительных** — изменение записывается как скрытое, значения не сохраняются.
2. **Поле хранит файл** — записывается смена имени файла.
3. **Поле хранит структуру** — записывается список операций над отдельными ключами.
4. **Поле хранит длинный текст, либо одно из значений длиннее 200 символов** — записывается построчное сравнение.
5. **Всё остальное** — записывается парой «было → стало».

Из-за четвёртого правила одно и то же поле может в разных событиях выглядеть по-разному: короткий комментарий покажется
парой значений, а разросшийся до нескольких абзацев — построчным сравнением.

## Значение

Самый частый вид: пара «было → стало». Кроме самих значений журнал сохраняет **готовые подписи** к ним, чтобы строка
читалась без обращения к справочникам:

- **Поле с фиксированным набором значений** получает подписи из этого набора: вместо числа в журнале видно «Не выдано →
  Выдано». Подписи сохраняются в момент записи события.
- **Ссылка на другой объект** хранится номером, поэтому рядом сохраняется название объекта. Названия подбираются одним
  запросом на каждый вид объекта, а не по одному на строку. Если объект к моменту записи уже удалён, подписи не будет и
  в журнале останется номер.

Значения приводятся к виду, пригодному для длительного хранения: суммы записываются текстом, чтобы не потерять
копейки, даты и время — в стандартном виде, ссылки на объекты — номерами, всё непонятное — текстовым представлением.

## Текст

Для длинных текстов пара «было → стало» бесполезна, поэтому записывается **построчное сравнение** в привычном виде
«минус» и «плюс» с одной строкой контекста вокруг изменения. Дополнительно сохраняются размеры обеих версий и их
контрольные суммы — по ним видно, что текст менялся, даже если само сравнение не сохранилось.

| Условие | Что записывается |
| --- | --- |
| Обычный случай | Построчное сравнение, размеры и контрольные суммы обеих версий |
| Сравнение вышло больше 8 КБ | Сравнение обрезается, ставится отметка об обрезке |
| Любая из версий больше 20 КБ | Сравнение не строится вовсе: остаются только размеры и контрольные суммы |

В интерфейсе построчное сравнение показывается свёрнутым до шести строк с кнопкой раскрытия; при отметке об обрезке
выводится предупреждение, что показана только часть изменения.

## Структура

Поля, хранящие структуру — дополнительные поля клиента, параметры интеграции, служебные блоки, — сравниваются не целиком,
а по ключам. Обход рекурсивный: вложенные разделы сравниваются так же, как верхний уровень, а путь до изменившегося
ключа собирается целиком.

| Операция | Смысл |
| --- | --- |
| Добавление | Ключа не было, появился, записывается новое значение |
| Удаление | Ключ был, исчез, записывается прежнее значение |
| Замена | Ключ есть в обеих версиях, значение изменилось; записываются оба значения |

Ключи с чувствительными именами обрабатываются отдельно: если значение изменилось, записывается замена с отметкой
«скрыто», а сами значения — нет. Если список операций превышает 8 КБ, сохраняются первые 50 операций и ставится отметка
об обрезке.

## Файл

Для файловых полей сравниваются только **имена**: было такое имя, стало такое. Содержимое файлов журнал не хранит и не
сравнивает. Если имя не изменилось, изменения нет, даже если файл перезаписан другим содержимым.

## Скрытое

Чувствительные поля фиксируются самим фактом изменения: в журнале остаётся отметка «Значение скрыто», без прежнего и
нового значения. Список имён закрыт и включает пароли, токены и секреты, ключи доступа и приватные ключи, токены карт,
номера карт, номера документов, ИИН, БИН и расчётные счёта.

<Note>
Маскирование работает **по имени поля**, а не по содержимому. Это сделано намеренно: новое поле с именем из списка
маскируется автоматически, без правки журнала. Обратная сторона в том, что чувствительное значение, попавшее в поле с
безобидным именем — например в комментарий, — будет записано в журнал полностью.
</Note>

## Что не попадает в изменения

- Поля, исключённые из наблюдения как производные — итоговые суммы, оплаченные суммы, поисковый индекс и другие; полный
  перечень в [«Автоматическом отслеживании»](/ru/logic/audit/tracking).
- Поля, значение которых не изменилось: сравнение возвращает пустоту, и строки не будет.
- Изменения, сделанные массовыми операциями и прямыми запросами к базе — они не проходят через сравнение вообще.
