Полный перечень понятий — в [глоссарии просмотра журнала](/ru/logic/audit/access-glossary).

Журнал открывается **панелью из бокового меню** — кнопкой с часами, рядом с уведомлениями. Панель показывает ленту от
новых событий к старым и подгружает следующие по мере прокрутки, порциями по 30 событий. Строка свёрнута до одной
линии: значок раздела, название действия, объект и инициатор, время. Раскрытие показывает инициатора с его типом, адрес,
плашки затронутых объектов и построчное сравнение изменённых полей. Действия, которые что-то удаляют, отменяют или
отзывают, отмечаются красной полосой слева — вид действия определяется по его названию.

## Фильтры

| Фильтр | Что делает |
| --- | --- |
| Поиск | Ищет по подписи объекта и подписи инициатора |
| Все разделы | Один из одиннадцати разделов журнала |
| Тип инициатора | Пользователь, клиент, анонимно, система, интеграция, платформа |
| Все действия | Одно или несколько действий из каталога заранее заданных формулировок |
| Сотрудник | Конкретный инициатор из списка сотрудников компании |
| Период | Диапазон дат и времени по моменту события |

Помимо фильтров панели журнал умеет отбирать события **по конкретному объекту**: по виду объекта и его номеру, а также
по роли, в которой объект участвовал. Именно так собирается история одной аренды или одной единицы инвентаря. Есть и
отбор по идентификатору запроса — он собирает всё, что произошло в рамках одного обращения к системе.

<Warning>
Поиск покрывает только подпись объекта и подпись инициатора. Найти событие по **изменившемуся значению** — например все
события, где сумма стала равна конкретному числу, — нельзя: содержимое изменений в поиск не входит.
</Warning>

## Порядок и постраничная выдача

Лента всегда упорядочена от новых событий к старым. Выдача **курсорная**: следующая порция запрашивается не по номеру
страницы, а по метке продолжения из предыдущего ответа. Это то, что нужно постоянно пополняемому журналу — при
добавлении новых событий уже показанные не сдвигаются и не дублируются. Размер порции можно задать запросом; панель
запрашивает 30.

Отбор по объекту требует соединения с таблицей объектов, поэтому к результату применяется устранение дублей — иначе
событие, у которого подошли сразу два объекта, попало бы в список дважды.

## Плашки объектов

В раскрытой строке показываются плашки затронутых объектов со ссылками на их карточки. Ссылки построены для шести видов
объектов: аренда, клиент, единица инвентаря, группа инвентаря, документ и шаблон документа. Повторы схлопываются, и на
каждый объект приходится одна плашка.

<Note>
Объекты остальных видов — платёж, счёт, роль доступа, подключение интеграции, настройки — в панели **не отображаются
вовсе**, поскольку ссылки на них не заданы. Через выборку по объекту они по-прежнему доступны, а вот увидеть их в самой
строке нельзя.
</Note>

## Права на просмотр

Доступ к журналу устроен так же, как к любому справочнику системы, и требует одновременно трёх условий:

1. Запрос авторизован.
2. Пользователь — **сотрудник компании**, в которой выполняется запрос: журнал недоступен клиентам и посторонним
   пользователям, даже если они авторизованы.
3. У пользователя есть право **просмотра** журнала. Роль без этого права не видит кнопку истории в боковом меню, а запрос
   к журналу получает отказ.

Выборка **всегда ограничена текущей компанией** — независимо от прав, сотрудник видит только события своей компании.
Права на изменение или удаление событий не существует ни у одной роли: журнал доступен только на чтение.

## Служебный экран платформы

В административной панели платформы есть отдельный экран журнала. Он доступен **только суперпользователям** — не просто
сотрудникам платформы, а именно суперпользователям, потому что показывает события всех компаний сразу. Экран полностью
на чтение: добавление, изменение и удаление событий отключены на уровне самого экрана.

Экран показывает время, компанию, действие, инициатора, его тип и подпись объекта; фильтры — раздел, тип инициатора и
дата, с навигацией по датам; поиск — по действию, подписи объекта, подписи инициатора и идентификатору запроса. Объекты
события выводятся вложенной таблицей, тоже без возможности правки.

## Справочник значений фильтров

Значения выпадающих списков панель получает отдельным запросом — он отдаёт три набора: действия, разделы и типы
инициаторов, каждый парой «значение и человеческое название». Названия приходят на языке запроса, поэтому список фильтра
переводится вместе с интерфейсом. Права на этот справочник те же, что на сам журнал.
