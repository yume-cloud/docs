## Модели и поля

### Кастомная JWT-аутентификация

*DRF-класс аутентификации по умолчанию: извлекает пользователя из access-токена, применяет remap old→new и кэширует объект пользователя на 5 минут. Наследует базовую JWT-аутентификацию; ключ кэша namespaced по схеме через ключ вида `пользователь_{id}`.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Получение пользователя по токену | метод | Читает идентификатор пользователя из клейма токена, при непубличной схеме применяет remap артефактов миграции, берёт пользователя из кэша или БД, проверяет активность и кэширует. |
| Флаг remap артефактов | флаг (константа модуля) | Включает поиск remap old→new для непубличных схем. |

### Middleware разрешения тенанта по JWT

*Middleware, которое после разрешения тенанта по хосту определяет компанию для API/мобильных клиентов без сабдомена: при псевдо-тенанте берёт тенант из JWT-пользователя и переключает схему БД. Работает только когда соединение ещё на псевдо-тенанте или без тенанта; при отсутствии привязки к компании возвращает 403.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Следующий обработчик | вызываемый объект | Ссылка на следующий middleware или представление в цепочке. |

**Разрешение**

| Поле | Тип | Описание |
| --- | --- | --- |
| Пользователь запроса | связь | Аутентифицированный пользователь; при пустом идентификаторе лениво догружается через ленивое получение JWT-пользователя. |
| Идентификатор тенанта | число | Результат определения тенанта у пользователя; при отсутствии — ответ 403 «Пользователь не подключён к компании». |
| Тенант (компания) | связь | Компания-тенант, полученная из кэша или БД; передаётся в переключение соединения и в объект запроса. |
| Тенант запроса | связь | Разрешённый тенант, проставляемый в объект запроса. |

**Кэш**

| Поле | Тип | Описание |
| --- | --- | --- |
| Ключ кэша тенанта | текст | Формат `тенант_{id}`, под которым компания-тенант кэшируется на 60 секунд. |

### Ленивое получение JWT-пользователя

*Функция, аутентифицирующая запрос через кастомную JWT-аутентификацию и возвращающая пользователя (или анонимного пользователя при ошибке). Ошибки аутентификации подавляются; используется как ленивый резолвер пользователя запроса.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Запрос | связь | HTTP-запрос, из которого извлекается JWT-токен. |

### Тенант (компания-арендатор)

Внешняя сущность — определена в модуле тенантов; здесь используется только для поиска по идентификатору и кэширования. См. справочник тенантов.

### Псевдо-тенант (public)

Внешняя сущность — служебный объект django-tenants, признак того, что middleware должно разрешить тенант из JWT.
