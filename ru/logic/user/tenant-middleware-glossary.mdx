## Модели и поля

### Кастомная JWT-аутентификация

*DRF-класс аутентификации по умолчанию: извлекает пользователя из access-токена, применяет remap old→new и кэширует объект пользователя на 5 минут. Наследует базовую JWT-аутентификацию; ключ кэша namespaced по компании через ключ вида `пользователь_{id}`.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Получение пользователя по токену | метод | Читает идентификатор пользователя из клейма токена, при выставленном контексте компании применяет remap артефактов миграции, берёт пользователя из кэша или БД, проверяет активность и кэширует. |
| Флаг remap артефактов | флаг (константа модуля) | Включает поиск remap old→new для запросов с выставленным контекстом компании. |

### Middleware разрешения компании по JWT

*Middleware, которое после разрешения компании по хосту определяет компанию для API/мобильных клиентов без сабдомена: если компания ещё не определена, берёт её из JWT-пользователя и устанавливает как активную для соединения. Работает только когда RLS-контекст соединения ещё пуст; при отсутствии привязки к компании возвращает 403.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Следующий обработчик | вызываемый объект | Ссылка на следующий middleware или представление в цепочке. |

**Разрешение**

| Поле | Тип | Описание |
| --- | --- | --- |
| Пользователь запроса | связь | Аутентифицированный пользователь; при пустом идентификаторе лениво догружается через ленивое получение JWT-пользователя. |
| Идентификатор компании | число | Результат определения компании у пользователя; при отсутствии — ответ 403 «Пользователь не подключён к компании». |
| Компания | связь | Компания, полученная из кэша или БД; передаётся в установку RLS-контекста и в объект запроса. |
| Компания запроса | связь | Разрешённая компания, проставляемая в объект запроса. |

**Кэш**

| Поле | Тип | Описание |
| --- | --- | --- |
| Ключ кэша компании | текст | Формат `tenant_{id}`, под которым компания кэшируется на 60 секунд. |

### Ленивое получение JWT-пользователя

*Функция, аутентифицирующая запрос через кастомную JWT-аутентификацию и возвращающая пользователя (или анонимного пользователя при ошибке). Ошибки аутентификации подавляются; используется как ленивый резолвер пользователя запроса.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Запрос | связь | HTTP-запрос, из которого извлекается JWT-токен. |

### Компания

Внешняя сущность — определена в модуле компаний; здесь используется только для поиска по идентификатору и кэширования. См. справочник компаний.

### Компания не определена

Внешняя сущность — состояние RLS-контекста соединения, признак того, что middleware должно разрешить компанию из JWT.
