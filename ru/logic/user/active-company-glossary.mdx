Справочник к странице [«Как система определяет вашу компанию»](/ru/logic/user/active-company).

## Понятия

| Понятие | Значение |
| --- | --- |
| Аккаунт | Учётная запись человека. Одна и та же учётная запись может участвовать сразу в нескольких компаниях. |
| Компания | Организация, которой принадлежат данные: аренды, клиенты, инвентарь, оплаты. Все данные в системе привязаны к одной компании. |
| Участие в компании | Связь аккаунта с компанией. Задаёт роль человека и его права внутри этой компании. |
| Заголовок компании (`X-Tenant-Id`) | Идентификатор компании, который приложение передаёт в обращении. Имеет приоритет над адресом сайта; объявлен в справочнике API у каждого запроса как необязательный параметр. |
| Адрес компании (поддомен) | Собственный адрес компании. Если заголовка нет и вы заходите по этому адресу, компания определяется сразу из него. |
| Список компаний аккаунта | Ответ `GET /v1/tenant/`: компании, где у человека есть роль сотрудника, субарендатора или суперпользователя компании. Из него приложение берёт идентификатор для заголовка. |
| Активная компания | Компания, в контексте которой выполняется текущее обращение. От неё зависит, какие данные вы видите. |
| Аккаунт без компании | Нормальное состояние сразу после регистрации: аккаунт создан, компании ещё нет. Обычные разделы в этом состоянии недоступны. |
| Проверка участия | Проверка того, что вошедший человек действительно состоит в активной компании. Выполняется после определения компании и до выполнения самого обращения. |
| «Нет доступа к выбранной компании» | Отказ, который возвращается вошедшему человеку, если он не состоит в активной компании. Данные при этом не читаются и не изменяются. |
| «Компания не найдена» | Отказ, который возвращается, если в обращении указана несуществующая компания. Обращение не выполняется в компании самого человека. |
| Сотрудник платформы | Работник Yume с глобальными полномочиями (поддержка, администрирование). Проверку участия проходит, потому что его права заданы не внутри компании. Сотрудник поддержки (глобальный признак персонала) при этом работает в любой компании с правами владельца и видит все компании в переключателе. |
| Разделы без обязательного участия | Список разделов, доступных не участникам компании: витрина и публичный сайт, кабинет клиента, вход и регистрация, создание компании и онбординг, клиентская часть Yume Plus, карты в кошельке, публичные ссылки подписания документов. |
| «Нужно создать компанию» | Признак в ответе системы, по которому приложение понимает, что человека надо направить на форму создания компании, а не показать обычную ошибку доступа. |
| Сессия | Подтверждение того, что вы вошли в систему. Предъявляется при каждом обращении; см. [«Сессии и срок действия входа»](/ru/logic/user/sessions). |

## Как это связано

Компания определяется одним из трёх способов, в порядке приоритета: по заголовку `X-Tenant-Id`, по адресу сайта, по аккаунту. Заголовок передаёт веб-приложение с выбранной компанией, адрес работает для входа через браузер по адресу компании, аккаунт — запасной путь для мобильного приложения и внешних интеграций, которые обращаются к общему адресу.

Если аккаунт участвует в нескольких компаниях, выбирается одна из них; правила выбора описаны в разделе [«Аккаунт и участие в компании»](/ru/logic/user/model).

После того как компания определена, для вошедшего человека проверяется участие в ней: нет участия — отказ «нет доступа к выбранной компании», указана несуществующая компания — отказ «компания не найдена». Сотрудники платформы проходят проверку, обращения без входа в систему она не затрагивает. Правило действует по умолчанию для всех разделов, кроме перечисленных как доступные не участникам.

Если у аккаунта нет ни одной компании и запрошен обычный раздел, система отвечает отказом с признаком «нужно создать компанию». Разделы, которые обязаны работать до её появления — вход, регистрация, создание компании, проверка занятости адреса, справочник сфер деятельности и заявка на демо — остаются доступны.
