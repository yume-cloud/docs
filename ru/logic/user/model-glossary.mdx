Композитная уникальность задана по тройке логин + телефон + почта, а не по каждому полю отдельно; из-за NULL в базе данных это допускает дубли телефонов и логинов, реальная защита для них — только сервис проверки. ## Модели и поля

### Пользователь

*Кастомная телефон-центричная модель пользователя (AUTH_USER_MODEL), общая (глобальная) и не привязанная к компании, наследует AbstractUser; один глобальный пароль на человека. Композитная уникальность задана по тройке логин + телефон + почта — не по каждому полю; из-за NULL в базе данных допускает дубли телефонов и логинов, реальная защита для них — только сервис проверки пользователя. Непустая почта уникальна без учёта регистра отдельным ограничением базы данных.*

**Идентификация**

| Поле | Тип | Описание |
| --- | --- | --- |
| Идентификатор | число | первичный ключ |
| Имя пользователя (логин) | текст (до 150) | необязательное, может быть пустым; проверяется валидатором имени пользователя |
| Телефон | текст | основной идентификатор для входа; может быть пустым |
| Электронная почта | текст | уникальна без учёта регистра; при сохранении обрезается по краям и приводится к нижнему регистру, пустая строка — к пустому значению |
| Пароль (хэш) | текст | единый глобальный пароль пользователя; наследуется из базовой модели |
| Имя | текст | обязательное при создании |
| Фамилия | текст | обязательное при создании |

**Профиль**

| Поле | Тип | Описание |
| --- | --- | --- |
| Дата рождения | дата | |
| Аватар | изображение | при изменении генерируется миниатюра |

**Глобальные роли**

| Поле | Тип | Описание |
| --- | --- | --- |
| Активен | флаг | стандартный флаг активности учётной записи |
| Персонал (глобально) | флаг | глобальный доступ в админку; для доступа в рамках компании смотри роль персонала в членстве |
| Суперпользователь (глобально) | флаг | глобальные права; роль в компании — в членстве |

**Связи**

| Поле | Тип | Описание |
| --- | --- | --- |
| Программа лояльности | связь | связь на лояльность; при создании клиента ставится самый дешёвый тариф |
| Группы | связь (многие-ко-многим) | стандартные группы прав; изменение сбрасывает кэш пользователя |
| Права пользователя | связь (многие-ко-многим) | стандартные индивидуальные права |

**Даты**

| Поле | Тип | Описание |

| Последний вход | дата/время | обновление игнорируется при инвалидации кэша |
| Дата регистрации | дата/время | сортировка пользователей по убыванию |

**Вычисляемые**

| Поле | Тип | Описание |
| --- | --- | --- |
| Полное имя | вычисляется | имя плюс фамилия |
| Суперпользователь компании | вычисляется (флаг) | читает членство текущей компании с кэшированием на 5 минут, кэш гасится при любом изменении членства; вне компании возвращает глобальный признак суперпользователя; у сотрудника поддержки Yume (глобальный признак персонала) — всегда «да», в любой компании |
| Персонал компании | вычисляется (флаг) | читает членство текущей компании с кэшированием на 5 минут, кэш гасится при любом изменении членства; вне компании возвращает глобальный признак персонала; у сотрудника поддержки Yume — всегда «да», в любой компании |
| Субарендатор компании | вычисляется (флаг) | читает членство с кэшированием на 5 минут, кэш гасится при любом изменении членства; вне компании возвращает отрицательный ответ — глобального признака больше нет |
| Группа в компании | вычисляется (связь) | группа из членства текущей компании с кэшированием на 5 минут, кэш гасится при любом изменении членства; вне компании — пусто, глобальной роли больше нет |
| Определение компании пользователя | вычисляется (метод) | используется при аутентификации; вне компании берёт членство с наибольшим идентификатором компании — при нескольких компаниях детерминированно, но может маршрутизировать в неожиданную компанию |
| Проверка списка прав | вычисляется (метод) | возвращает истину, если есть любое из перечисленных прав |

### Менеджер пользователей

*Кастомный менеджер для создания пользователей, обычных клиентов и суперпользователей. Создание клиента назначает самый дешёвый тариф лояльности; получение пользователя — обёртка над выборкой с ошибкой 404 при отсутствии.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Получить пользователя | метод | выборка по переданным данным с ошибкой 404 при отсутствии |
| Создать пользователя | метод | простое создание без лояльности |
| Создать клиента | метод | создание с назначением дешёвого тарифа лояльности |
| Создать суперпользователя | метод | активность, персонал и суперпользователь — истина |

### Пользователь компании (членство)

*Членство пользователя в конкретной компании и его роли/права в рамках этой компании. Источник ролей для вычисляемых свойств персонала, суперпользователя, субарендатора и группы; уникальна пара компания + пользователь — одно членство на человека в компании (раньше — тройка с группой; дубли слиты миграцией). Принадлежность к компании наследуется из базовой модели с областью видимости компании.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Компания | связь | принадлежность к компании |
| Пользователь | связь | связь на пользователя |
| Суперпользователь компании | флаг | полные права в рамках компании |
| Персонал компании | флаг | сотрудник компании (доступ к CRM); независим от признака субарендатора |
| Субарендатор | флаг | признак субаренды в компании; независим от признака персонала |
| Группа (роль) | связь | связь на группу; роль пользователя внутри компании |
| Доп. данные | JSON | произвольные дополнительные поля членства, в том числе сохранённые настройки интерфейса сотрудника в этой компании |

### Группа компании

*Расширение стандартной группы платформа для привязки роли к компании и её отображаемого названия. Связь один-к-одному с группой; принадлежность к компании наследуется из базовой модели с областью видимости компании.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Группа | связь | связь один-к-одному на группу |
| Название | текст | отображаемое название роли |

### Доверенность

*Документ-доверенность, связанный один-к-одному с пользователем. Иерархия через ссылку на родительскую доверенность. Принадлежность к компании наследуется из базовой модели с областью видимости компании.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Родительская доверенность | связь | ссылка на саму себя, с защитой от удаления |
| Пользователь | связь | связь один-к-одному на пользователя |
| Номер | текст | уникальный номер документа |
| Дата | дата | дата доверенности |

### Сигнал: создание/привязка клиента

*Сигнал после сохранения пользователя: в контексте компании создаёт или привязывает CRM-клиента к пользователю по нормализованному телефону. Пропускается вне компании, для персонала и субарендаторов; нормализует телефон, убирая скобки, пробелы и дефисы.*

### Сигнал: обновление кэша пользователей

*Сигнал после сохранения пользователя: инвалидирует кэш пользователя и пересобирает список активного персонала. Игнорирует изменение только последнего входа. Список активного персонала хранится 15 секунд и в коде сейчас не читается. Массовое обновление пользователей в обход сохранения гасит кэш затронутых пользователей само, без сигнала.*

### Сигнал: сброс кэша при смене групп

*Сигнал при изменении групп пользователя: инвалидирует кэш затронутых пользователей при добавлении, удалении и очистке.*

### Сигнал: сброс кэша при удалении пользователя

*Пара сигналов вокруг удаления пользователя. До удаления запоминает, в каких компаниях он состоит, пока членства ещё не удалены каскадом; после удаления гасит его кэш аутентификации вне компании, в текущем контексте и во всех этих компаниях.*

### Сигнал: сброс кэша ролей

*Сигнал после сохранения и удаления членства: гасит пять ключей пары «компания + пользователь» — суперпользователь, персонал, субаренда, группа и участие в компании. Массовое обновление членств в обход сохранения гасит те же ключи для каждой затронутой строки. Ключи ролей живут 5 минут, положительный ответ об участии — минуту.*

### Сигнал: сброс кэша прав роли

*Сигнал при изменении состава прав группы: при добавлении, удалении и очистке гасит кэш набора прав этой роли. Кэш общий для всех участников роли и живёт сутки. Срабатывает независимо от того, где меняли права — в редакторе роли в CRM, в админке или в коде.*

### Админка пользователя

*Настройка отображения пользователя в админке: список, порядок, наборы полей и отдельный менеджер для выборки. Использует формы админки для изменения и создания, а также смены пароля; последний вход и дата регистрации доступны только для чтения.*
