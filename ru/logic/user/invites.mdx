## Три способа добавить человека в компанию

| Способ | Пароль | Когда подходит |
| --- | --- | --- |
| Приглашение по ссылке | Человек задаёт сам: новый аккаунт — при принятии, существующий подтверждает свой | Основной путь: человек входит сам, пароль никому не передают |
| Заведение сотрудника в карточке | Задаёт суперпользователь компании при создании | См. [«Профиль и управление сотрудниками»](/ru/logic/user/profile) |
| Добавление существующего аккаунта по почте | Не меняется: у человека остаётся свой | Почта уже зарегистрирована в Yume — например, человек работает в другой компании |

Все три пути дают одно и то же — членство человека в компании с ролью, признаками и пунктами проката (см. [«Модель пользователя и членство в компании»](/ru/logic/user/model)). Аккаунт и пароль у человека по-прежнему одни на всю систему.

## Приглашение

### Что хранит приглашение

Приглашение принадлежит компании: строка несёт компанию, и каждая компания видит и меняет только свои приглашения.

| Поле | Тип | Назначение |
| --- | --- | --- |
| Токен | UUID | Уникальный, выдаётся при создании и не меняется; из него строится ссылка |
| Почта | текст | Необязательна. Сохраняется без пробелов по краям и в нижнем регистре |
| Роль | связь | Роль компании, которую получит человек; при удалении роли обнуляется |
| Сотрудник, Субарендатор | флаги | По умолчанию «сотрудник — да», «субарендатор — нет»; признаки независимы |
| Пункты проката | список | Пункты компании, к которым человека привяжут |
| Сумма зарплаты | число (2 знака) | Необязательна |
| Истекает | дата/время | Момент создания плюс 7 дней |
| Отправлено | дата/время | Когда письмо в последний раз поставлено в очередь отправки |
| Принято, Кем принято | дата/время, связь | Заполняются при принятии |
| Отозвано | дата/время | Заполняется при отзыве |
| Кем создано, Создано | связь, дата/время | Кто и когда пригласил |

<Note>
Признака «суперпользователь компании» в приглашении нет: по ссылке человек получает роль и признаки сотрудника или субарендатора, но не полные права. Их выдают позже, в карточке сотрудника.
</Note>

### Статусы

Статус не хранится, а вычисляется при каждом чтении — проверки идут в таком порядке:

| Статус | Код | Когда |
| --- | --- | --- |
| Принято | `accepted` | Проставлено время принятия |
| Отозвано | `revoked` | Проставлено время отзыва |
| Истекло | `expired` | Наступил срок действия |
| Ожидает | `pending` | Во всех остальных случаях |

Принять приглашение и отправить его повторно можно только в статусе «ожидает». Фоновой задачи нет: приглашение становится истёкшим само, в момент наступления срока.

### Срок жизни и ссылка

Приглашение действует **7 дней** с момента создания. Повторная отправка срок не продлевает, отдельного продления нет: вместо истёкшего создают новое приглашение — истёкшее этому не мешает.

Ссылка имеет вид `<адрес веб-приложения>/invite/<токен>/`. Адрес веб-приложения — настройка развёртывания `APP_BASE_URL`, по умолчанию `https://account.<окружение>`. Токен не меняется, поэтому повторная отправка присылает ту же ссылку. После принятия ссылка больше не срабатывает.

## Создание приглашения

Приглашение создаётся запросом `POST /v1/crm/invites/`: почта (можно не указывать), роль, признаки сотрудника и субарендатора, пункты проката, сумма зарплаты.

| Проверка | Ответ при нарушении |
| --- | --- |
| Почта принадлежит человеку, который уже состоит в компании | Ошибка поля «Этот пользователь уже работает в вашей компании.» |
| На эту почту уже есть открытое приглашение этой компании | «Приглашение на эту почту уже отправлено.» Истёкшие, отозванные и принятые не мешают |
| Роль не из ролей компании | «Роль не найдена.» |
| Пункт проката не из пунктов компании | «Пункт проката не найден: …» с перечнем чужих номеров |
| Лимит сотрудников исчерпан | Отказ `subscription_limit` с типом `staff` — как при заведении сотрудника, см. [«Лимиты и тарификация»](/ru/logic/company-billing/limits) |

В ответе — само приглашение с готовой ссылкой и признак `sent`: ушло ли письмо.

### Письмо или ссылка без почты

- **Почта указана** — ставится в очередь письмо с темой «Приглашение в компанию `<название>` — Yume»: ссылка, роль и срок действия. При успехе проставляется время отправки, `sent` — «да».
- **Почта не указана** — письма нет, `sent` — «нет». Ссылку отправляют вручную: веб-приложение сразу копирует её в буфер обмена.
- **Очередь отправки недоступна** — приглашение всё равно создаётся и ссылка работает, `sent` — «нет»; ссылку можно скопировать из списка.

Как устроена отправка писем — в [каталоге писем](/ru/logic/notifications/emails).

### Повторная отправка и отзыв

**Повторная отправка** (`POST /v1/crm/invites/<id>/resend/`) присылает ту же ссылку ещё раз и обновляет время отправки. Отказ — если у приглашения нет почты («У приглашения нет адреса — отправьте ссылку вручную.») или оно не в статусе «ожидает» («Приглашение недействительно.»).

**Отзыв** (`DELETE /v1/crm/invites/<id>/`) не удаляет запись, а проставляет время отзыва: ссылка перестаёт работать сразу, а след остаётся в списке. Принятое или уже отозванное приглашение отзыв не меняет, хотя запрос отвечает успехом.

### Список приглашений

`GET /v1/crm/invites/` отдаёт все приглашения компании во всех статусах, новые сверху, без разбивки на страницы; в каждой строке — готовая ссылка.

## Принятие приглашения

Ссылка открывает страницу веб-приложения. Она сначала запрашивает `GET /v1/auth/invite/<токен>/` — без входа и без компании в запросе: приглашение ищется по токену среди всех компаний. В ответе — название компании, роль, почта, статус, срок и признак `user_exists`: есть ли уже аккаунт с почтой приглашения. По нему страница решает, что спросить: имя, фамилию и новый пароль или пароль существующего аккаунта. Неизвестный токен — `404`.

Затем приглашение принимается запросом `POST /v1/auth/invite/<токен>/accept/`:

<Steps>
<Step title="Проверка приглашения">
Статус должен быть «ожидает». Иначе — ошибка «Приглашение недействительно.»: принятое, отозванное или истёкшее приглашение второй раз не срабатывает.
</Step>
<Step title="Почта">
Берётся из приглашения, присланная в запросе при этом не учитывается. Если в приглашении почты нет, её нужно прислать («Укажите электронную почту.»).
</Step>
<Step title="Аккаунт">
Аккаунта с этой почтой нет — нужны имя, фамилия и пароль; пароль проверяется стандартными правилами (не короче 8 символов и встроенные проверки надёжности). Аккаунт есть — нужен его текущий пароль («Неверный пароль от аккаунта Yume.»); имя и фамилия не нужны, пароль не меняется.
</Step>
<Step title="Лимит сотрудников">
Если места для сотрудников в компании закончились — отказ `402` «В компании закончились места для сотрудников.», ничего не создаётся.
</Step>
<Step title="Выдача доступа">
В контексте компании приглашения, одной транзакцией: создаётся аккаунт, если его не было, выдаётся членство с ролью, признаками, пунктами и зарплатой из приглашения, приглашение помечается принятым — со временем и тем, кто принял.
</Step>
<Step title="Вход">
В ответе — пара токенов входа, идентификатор и название компании. Человек сразу оказывается в системе, а приложение выбирает эту компанию.
</Step>
</Steps>

<Note>
Владение почтой при принятии отдельно не подтверждается — доказательством служит сама ссылка. У приглашения без почты адрес выбирает тот, кто открыл ссылку.
</Note>

<Info>
Если к моменту принятия человек уже состоит в компании — например, его успели добавить иначе, — членство не меняется: роль, пункты и зарплата из приглашения не применяются, а приглашение всё равно гасится.
</Info>

Частота ограничена по адресу запроса: не больше 30 открытий приглашения и 10 попыток принятия в минуту. Новому аккаунту, созданному по приглашению, приветственное письмо не отправляется.

## Добавление существующего аккаунта по почте

Почта уникальна на всю систему без учёта регистра, поэтому второй аккаунт с той же почтой завести нельзя. При заведении сотрудника (`POST /v1/crm/users/`) почта проверяется до создания:

| Кому принадлежит почта | Ответ |
| --- | --- |
| Никому | Сотрудник заводится как обычно |
| Человеку, который уже состоит в этой компании | `400`, ошибка поля «Пользователь с такой почтой уже существует.» |
| Аккаунту Yume, который в этой компании не состоит | `409` с кодом `user_exists`, текстом «Пользователь с такой почтой уже зарегистрирован в Yume.» и краткой карточкой аккаунта: идентификатор, имя, фамилия, почта, аватар |

<Check>
Заведение сотрудника с почтой, которая уже есть в Yume, теперь отвечает отказом `409` с карточкой найденного аккаунта, и дубль не создаётся. Раньше такой запрос упирался в ограничение уникальности почты в базе данных и падал ошибкой сервера.
</Check>

При правке сотрудника почта другого аккаунта — всегда обычная ошибка поля `400`: человек уже в компании, добавлять некого.

Получив `409`, интерфейс предлагает добавить найденного человека: `POST /v1/crm/users/attach/` с почтой, ролью, признаками (по умолчанию «сотрудник — да», «субарендатор — нет»), пунктами проката и суммой зарплаты.

| Проверка | Ответ при нарушении |
| --- | --- |
| Аккаунта с такой почтой нет | `400` «Пользователь с такой почтой не найден.» |
| Человек уже в компании | `400` «Этот пользователь уже работает в вашей компании.» |
| Лимит сотрудников исчерпан | Отказ `subscription_limit` с типом `staff` |

Человек попадает в компанию сразу — без ссылки и без подтверждения с его стороны, письмо не отправляется. Его аккаунт, пароль и членства в других компаниях не меняются. В ответе (`201`) — карточка человека в формате списка сотрудников.

## Что получает человек при добавлении

Принятие приглашения и добавление существующего аккаунта выдают доступ одной и той же функцией:

1. Членство создаётся, только если его ещё нет. Уже существующее не меняется — вызов ничего не делает.
2. Роль и признаки сотрудника и субарендатора берутся из приглашения или запроса; «суперпользователь компании» — всегда «нет».
3. Каждый пункт проката привязывается неактивным. Затем, если активного пункта в этой компании у человека нет, активным становится первый привязанный.
4. Зарплата записывается, только если сумма указана и не нулевая.
5. Пересчитывается число сотрудников для лимита.

<Warning>
Запись о зарплате у аккаунта одна на все компании. Сумма из приглашения или из добавления по почте перезаписывает зарплату, которую человеку завела другая компания; компания у записи остаётся прежней.
</Warning>

## Права

| Действие | Кто может |
| --- | --- |
| Смотреть список приглашений | Сотрудник компании |
| Открыть одно приглашение | Сотрудник или субарендатор компании |
| Создать, отправить повторно, отозвать | Суперпользователь компании |
| Добавить существующий аккаунт по почте | Суперпользователь компании |
| Открыть и принять ссылку | Кто угодно, без входа |

## Адреса API

| Адрес | Метод | Что делает |
| --- | --- | --- |
| `/v1/crm/invites/` | GET | Список приглашений компании |
| `/v1/crm/invites/` | POST | Создать приглашение; отправляет письмо, если указана почта |
| `/v1/crm/invites/<id>/` | GET | Одно приглашение |
| `/v1/crm/invites/<id>/` | DELETE | Отозвать приглашение |
| `/v1/crm/invites/<id>/resend/` | POST | Отправить письмо повторно |
| `/v1/auth/invite/<токен>/` | GET | Что видит приглашённый; без входа |
| `/v1/auth/invite/<токен>/accept/` | POST | Принять приглашение; без входа, отвечает токенами входа |
| `/v1/crm/users/attach/` | POST | Добавить в компанию существующий аккаунт по почте |

## Журнал действий

| Событие | Когда пишется |
| --- | --- |
| `staff.invited` («Сотрудник приглашён») | Создание приглашения. Аккаунта у приглашённого ещё нет, поэтому объектом записи служит сам пригласивший; в записи — номер приглашения, почта и ушло ли письмо |
| `staff.invite_accepted` («Сотрудник принял приглашение») | Принятие приглашения; действует сам принявший |
| `staff.attached` («Существующий пользователь добавлен в компанию») | Добавление существующего аккаунта по почте |

Как эти события подписаны в истории действий — в [перечне действий журнала](/ru/logic/audit/actions).
