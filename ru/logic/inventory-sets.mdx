**Комплект** — это набор из *разных* товаров, которые сдаются вместе как единое целое, со своей ценой и своими тарифами. Например «фотозона»: стойка + свет + фон.

<Note>
Комплект отвечает на вопрос «какие разные штуки нужно выдать вместе». Внутри комплекта позиции ссылаются именно на [Товары](/ru/logic/inventory-groups), а не на отдельные единицы. Доступность комплекта вычисляется через доступность входящих в него товаров, а его цена собирается из тарифов позиций.
</Note>

Смежные страницы: [Товары (группы единиц)](/ru/logic/inventory-groups), [Инвентарь](/ru/logic/inventory), [Тарифы и расчёт стоимости](/ru/logic/tariffs-pricing), [Аренда: заявка и жизненный цикл](/ru/logic/rent-lifecycle).

## Модель данных

### Комплект

| Поле | Назначение |
| --- | --- |
| Название, Артикул, Фото, Категория | Идентификация комплекта |
| Скидка (промокод), Период тарификации | Привязанная скидка и период |
| Фиксированная стоимость комплекта | «Жёсткий» комплект: при удалении позиции цена перераспределяется на остальные |
| Опубликован | Видимость |
| Архивация | Мягкое удаление / архивация / списание комплекта (единая запись «Архивация», см. [Инвентарь](/ru/logic/inventory#архивация-вместо-жёсткого-удаления)) |

### Позиция комплекта

| Поле | Назначение |
| --- | --- |
| Комплект | Родительский комплект |
| Товар | Какой товар входит в позицию |
| Количество | Сколько единиц товара нужно на один комплект (по умолчанию 1) |
| Обязательная | Обязательна ли позиция для сборки комплекта |
| Цена тарифа, Условие подбора | Цена позиции и условие подбора единиц по доп. данным |

### Цена комплекта

Одна строка = один период тарификации. Поле «Цена за период» хранит суммарную цену комплекта за этот период. При каждом сохранении цены её порядок отображения сдвигает остальные строки того же порядка вверх, чтобы избежать дублирования очерёдности.

**Тариф инвентаря** — общая таблица тарифов. Одна и та же сущность обслуживает и одиночную единицу инвентаря, и товар, и позицию комплекта. Тариф всегда привязан ровно к одному из этих объектов:

- тариф конкретной единицы инвентаря;
- тариф товара;
- тариф позиции комплекта (с указанием, к какой цене комплекта за период он относится).

## Как это работает

### Цена комплекта vs сумма позиций

Цена комплекта **не** хранится как ручная сумма — она собирается из тарифов позиций. При массовом сохранении тарифов комплекта цена каждого периода пересчитывается суммированием по всем позициям этого периода.

То есть для одного периода:

> **Цена комплекта за период = сумма по всем позициям ( Цена тарифа позиции × Количество в позиции )**

<Tip>
Множитель — именно количество в позиции. Если в комплект входит товар с количеством 3, его тариф войдёт в цену комплекта трижды. Это единственное место, где количество в позиции влияет на цену.
</Tip>

**Числовой пример.** Комплект «Фотозона», период «сутки»:

| Позиция | Товар | Количество | Тариф за сутки | Вклад |
| --- | --- | --- | --- | --- |
| Стойка | Стойки | 2 | 1 000 | 2 000 |
| Свет | Софтбоксы | 1 | 3 000 | 3 000 |
| Фон | Фоны | 1 | 500 | 500 |

Цена комплекта за сутки = 2×1000 + 1×3000 + 1×500 = **5 500** за сутки.

### Доступность и «количество комплектов»

Сколько целых комплектов можно собрать — ограничено самой дефицитной позицией комплекта. Сводка по доступности считает это по **всем** комплектам из отфильтрованной выборки и возвращает суммарный портфель, а не карточку одного комплекта.

Для каждой позиции комплекта:

- **сколько комплектов можно собрать по этой позиции** = число единиц товара, делённое нацело на количество в позиции;
- **сколько доступно сейчас** = число свободных единиц, делённое нацело на количество в позиции.

Затем по каждому комплекту берётся минимум этих значений среди его позиций, а итоговая сводка — это сумма таких минимумов по всем комплектам выборки.

То есть для одного комплекта:

> **Комплектов по комплекту = минимум по позициям ( число единиц товара, делённое нацело на количество в позиции )**

Возвращаемые «всего комплектов» и «доступно комплектов» — это сумма этих минимумов по всем комплектам в выборке. Сводка также отдаёт число комплектов и суммарную прибыль по этим комплектам.

**Пример (для одного комплекта).** Комплект требует 2 стойки (в наличии 10 → 5 комплектов) и 1 софтбокс (в наличии 3 → 3 комплекта). Собрать этот комплект можно min(5, 3) = **3** раза. Если в выборке несколько комплектов, сводка вернёт сумму таких минимумов по всем комплектам.

### Выдача комплекта в аренду

При добавлении комплекта в заявку система выдаёт единицы под каждую позицию комплекта.

<Steps>
<Step title="Ключи экземпляров комплекта">
На каждый запрошенный экземпляр комплекта генерируется случайный ключ. Их количество равно числу запрошенных комплектов. Этот ключ связывает разнородные единицы в один «физический» комплект.
</Step>
<Step title="Обход только базовых позиций">
Берутся базовые позиции комплекта (не являющиеся альтернативой к другой позиции). Для каждой из них собирается набор альтернативных товаров, которыми её можно заменить.
</Step>
<Step title="Подбор единиц под позицию">
Нужное число единиц: количество в позиции × число запрошенных комплектов. Единицы ищутся среди основного товара позиции и его альтернативных товаров, с учётом занятости на интервал.
</Step>
<Step title="Проверка обязательности">
Если свободных меньше нужного **и** позиция обязательная — возникает ошибка «Недостаточно свободного инвентаря». Необязательные позиции при дефиците просто выдаются частично.
</Step>
<Step title="Распределение по экземплярам комплекта">
Из отобранного набора единицы распределяются по экземплярам комплекта по порядку: единицы заполняют первый экземпляр, затем следующий и т. д. Каждой единице проставляется ключ соответствующего экземпляра комплекта.
</Step>
</Steps>

Итоговые строки инвентаря заявки хранят ссылку на комплект, ключ конкретного экземпляра и позицию комплекта — так система знает, что несколько разных единиц выданы как один комплект.

### Особый случай: удаление позиции из «жёсткого» комплекта

Если у комплекта включена фиксированная стоимость, то при удалении части его единиц из заявки цена не пропадает, а перераспределяется на оставшиеся, чтобы сумма экземпляра комплекта осталась прежней.

Логика перераспределения:

1. Вычисляется множитель = старая сумма комплекта, делённая на новую сумму оставшихся строк.
2. Цена тарифа каждой оставшейся строки умножается на этот множитель.
3. Если из-за округления итог не совпадает со старой суммой, разница добавляется к последней строке.

<Warning>
Механика применяется только при включённой фиксированной стоимости комплекта. Для обычных комплектов удаление позиции просто убирает её стоимость из заявки. Также при удалении единиц типа «Продажа» у соответствующей единицы инвентаря сбрасываются дата и цена продажи.
</Warning>
