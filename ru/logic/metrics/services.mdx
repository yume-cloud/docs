Полный перечень полей — в [глоссарии услуг](/ru/logic/metrics/services-glossary).

## Что показывает этот раздел

Раздел «Услуги» в метриках отвечает на вопрос: сколько компания зарабатывает на дополнительных услугах (мойка, доставка с установкой, чистка, любые платные работы, оформленные как позиция «услуга» в заявке аренды) — в целом, по каждому виду услуги и по каждому сотруднику, который эти услуги оказывал.

Раздел состоит из четырёх представлений одних и тех же исходных данных:

- **Общая сводка** — один агрегированный объект по всем услугам сразу за выбранный период.
- **Список услуг** — таблица, где одна строка — один вид услуги (сгруппировано по услуге).
- **Обзор по исполнителям** — таблица, где одна строка — пара «вид услуги + сотрудник».
- **История начислений** — построчный журнал: каждая строка — одно начисление за один день оказания одной услуги в рамках одной заявки.

<Info>
Все четыре представления читают одни и те же дневные записи прибыли и различаются только уровнем группировки: без группировки (история), группировка по услуге (список), группировка по услуге и исполнителю (обзор), либо полное схлопывание в одну строку (общая сводка).
</Info>

## Источник данных

Данные берутся из общего журнала начислений прибыли компании — таблицы, в которую фоновый пересчёт заявки записывает по одной строке на каждый день оказания каждой услуги, инвентарной позиции, доставки, штрафа, работы мастерской или продажи. Раздел «Услуги» интересуется только теми строками, где заполнена ссылка на позицию услуги в заявке — то есть строками, которые описывают именно дополнительную услугу, а не аренду инвентаря, доставку или штраф.

### Какие заявки попадают в выборку

Прежде чем что-либо считать, весь раздел применяет общий для всех метрик компании фильтр «пригодности» заявки. В расчёт попадают только начисления, у которых:

- заявка не удалена, **и**
- заявка находится в одном из статусов «в аренде», «завершена» или «должник», **либо** заявка отменена, но по ней уже была внесена оплата (сумма оплаты больше нуля).

<Warning>
Отменённые заявки без единого тенге оплаты полностью исключаются из всех отчётов по услугам — даже если по ним формально были назначены услуги. Если ожидается, что «услуга должна была принести доход», но она не отменена оплаченно и не активна/завершена/просрочена — она не попадёт ни в один из четырёх экранов раздела.
</Warning>

Дополнительно ко всем четырём представлениям применяется ещё одно обязательное условие: у строки начисления должна быть заполнена ссылка на позицию услуги (иначе это была бы, например, инвентарная строка того же журнала).

## Общая логика фильтрации периода и исполнителя

Все четыре представления принимают один и тот же набор параметров фильтрации:

| Поле | Тип | Назначение |
|---|---|---|
| Услуга | связь | ограничить выборку одним видом услуги, списком видов услуг, либо, наоборот, выбрать только начисления без указанной услуги |
| Дата | дата/время | ограничить выборку диапазоном дат начисления (от и/или до) |
| Исполнитель | связь | оставить только начисления, где услугу оказывал указанный сотрудник |

<Note>
Фильтр по дате применяется к дате самого начисления (то есть к конкретному дню оказания услуги), а не к дате создания или дате начала/окончания всей заявки. Многодневная услуга даёт по одной строке начисления на каждый день, и фильтр по датам может «срезать» часть дней услуги, не исключая её целиком.
</Note>

Списковые представления (список услуг, обзор по исполнителям, история) дополнительно поддерживают текстовый поиск и сортировку:

- **Список услуг** — поиск по названию услуги и по имени/фамилии исполнителя; сортировка по виду услуги, названию, количеству, прогнозу или фактической выручке.
- **Обзор по исполнителям** — поиск только по названию услуги; та же сортировка, что и в списке услуг.
- **История начислений** — поиск по названию услуги и по имени/фамилии исполнителя; сортировка по номеру записи, дате, услуге, заявке или статусу заявки (в системе для истории технически заявлен ещё один пункт сортировки, но он не соответствует ни одному из полей, реально показанных в этом представлении, поэтому полагаться на него не стоит).

## Общая сводка по услугам

Это единственный объект (а не список), агрегирующий все начисления по услугам, прошедшие через фильтр периода/исполнителя/услуги, в четыре числа:

| Поле | Тип | Назначение |
|---|---|---|
| Количество услуг | число | сколько уникальных позиций услуги (конкретных строк «услуга в заявке») попало в выборку |
| Дней | число | сколько всего дневных начислений было — то есть суммарное число дней, в которые оказывалась хоть какая-то услуга |
| Прогноз выручки | число (2 знака) | сумма плановых/ожидаемых начислений по услугам за период, без учёта того, была ли услуга фактически оплачена |
| Фактическая выручка | число (2 знака) | сумма реально распределённых на услуги денег — то есть доля выручки, которая была фактически покрыта поступившей оплатой |

<Note>
«Количество услуг» и «Дней» — разные по смыслу числа: количество услуг считает уникальные позиции услуги в заявках, а «Дней» считает строки начислений. Одна и та же услуга, оказываемая три дня подряд, даёт одну позицию услуги, но три строки начисления — соответственно в сводке она даст «Количество услуг» = 1 и «Дней» = 3.
</Note>

Если под выбранные фильтры не попало ни одной строки, все четыре значения равны нулю (запрос не возвращает ошибку и не возвращает пустой объект — суммы просто нулевые).

## Список услуг (сводка по каждой услуге)

Та же общая сводка, но не схлопнутая в одно число, а построчно раскрытая по видам услуг: каждая строка — один вид услуги, встретившийся в выборке.

| Поле | Тип | Назначение |
|---|---|---|
| Название услуги | текст | название вида услуги |
| Исполнители | список | уникальный перечень сотрудников (без повторов), которые в выбранном периоде оказывали именно эту услугу |
| Количество | число | число уникальных позиций услуги этого вида, попавших в выборку |
| Дней | число | суммарное число дней, когда эта услуга оказывалась (сумма по всем позициям и всем исполнителям) |
| Прогноз выручки | число (2 знака) | плановая сумма по этому виду услуги за период |
| Фактическая выручка | число (2 знака) | фактически поступившая сумма по этому виду услуги за период |

<Info>
Если у части начислений вид услуги не указан (такое в принципе допускает модель данных), они образуют отдельную групповую строку без названия услуги, а не пропадают из отчёта. Такую строку можно явно выделить или, наоборот, исключить через фильтр «услуга не задана».
</Info>

Поле «Исполнители» в этой сводке — это список сотрудников по конкретному виду услуги в целом, без разбивки на то, сколько дней или сколько денег принёс каждый из них. Для разбивки по вкладу конкретного сотрудника нужен «Обзор услуг по исполнителям».

## Обзор услуг по исполнителям

То же построчное разбиение, что и в списке услуг, но с более мелкой группировкой: строка соответствует не просто виду услуги, а паре «вид услуги + сотрудник, который её оказывал». Это представление отвечает на вопрос «кто сколько заработал компании на какой услуге».

| Поле | Тип | Назначение |
|---|---|---|
| Исполнитель | связь | сотрудник, оказывавший услугу |
| Название услуги | текст | вид услуги |
| Количество | число | число уникальных позиций услуги по этой паре услуга/исполнитель |
| Дней | число | суммарное число дней оказания услуги именно этим сотрудником |
| Прогноз выручки | число (2 знака) | плановая сумма по этой паре услуга/исполнитель |
| Фактическая выручка | число (2 знака) | фактическая сумма по этой паре услуга/исполнитель |

<Note>
Если один и тот же вид услуги оказывали три разных сотрудника за период, «Список услуг» покажет одну строку с суммой по всем троим и списком из трёх исполнителей, а «Обзор по исполнителям» покажет три отдельные строки — по одной на каждого сотрудника, с индивидуальными суммами. Это две разные проекции одних и тех же денег: сумма всех строк обзора по конкретной услуге равна сумме, показанной для неё в списке услуг.
</Note>

Если позиция услуги не имеет привязанного исполнителя, такая пара группируется как «услуга без исполнителя» и тоже попадает отдельной строкой, а не отбрасывается.

## История начислений по услугам

Самый детальный уровень: каждая строка — это одно фактическое дневное начисление по одной услуге в рамках одной заявки. Ничего не агрегируется и не группируется — это журнал, а не сводка.

| Поле | Тип | Назначение |
|---|---|---|
| Название услуги | текст | вид услуги, к которой относится начисление |
| Заявка | связь | заявка аренды, в рамках которой оказана услуга |
| Статус заявки | число | статус заявки на момент выгрузки (числовой код: например, «в аренде», «завершена», «должник», «отменена» и т.д.) |
| Дата | дата/время | конкретный день, за который сделано начисление |
| Клиент | связь | клиент по заявке, показан кратким набором полей (не полная карточка клиента) |
| Исполнитель | связь | сотрудник, который в этот день оказывал услугу |
| Прогноз выручки | число (2 знака) | плановая сумма начисления именно за этот день |
| Фактическая выручка | число (2 знака) | фактическая сумма начисления именно за этот день |

<Tip>
История — это единственное из четырёх представлений, где можно увидеть статус заявки на конкретный момент и понять, почему по ней есть (или нет) фактическая выручка при ненулевом прогнозе: например, заявка ещё «в аренде» и оплата пока не покрывает эти дни, либо заявка «должник» и оплата распределена лишь частично.
</Tip>

Строка истории существует независимо от того, привязан ли к ней исполнитель или указан ли вид услуги — оба поля могут быть пустыми, и такие строки всё равно отображаются.

## Как соотносятся «Прогноз» и «Фактическая выручка» во всех представлениях

Оба показателя считаются на уровне отдельного дневного начисления и затем просто суммируются при группировке (по услуге, по паре услуга/исполнитель или по всей выборке целиком):

- **Прогноз выручки** — плановая (ожидаемая) сумма по услуге за день, рассчитанная исходя из цены и продолжительности услуги, без учёта того, оплачена она клиентом или нет.
- **Фактическая выручка** — доля прогнозной суммы, которая уже подтверждена фактическим поступлением денег по заявке; если заявка оплачена не полностью, фактическая сумма может быть меньше прогнозной (в том числе равна нулю), но не может быть отрицательной величиной.

<Warning>
Прогноз и фактическая выручка не гарантированно совпадают даже по завершённой заявке — если клиент недоплатил, «Фактическая выручка» останется меньше «Прогноза» и после завершения аренды, пока долг не будет погашен (либо заявка не перейдёт в статус «должник»/не будет скорректирована).
</Warning>

## Права доступа

Доступ к экранам раздела «Услуги» регулируется отдельным правом доступа к метрикам услуг — оно не совпадает с правами на просмотр других разделов метрик (продажи, клиенты, бонусы, заявки и т.д.). Если у сотрудника нет именно этого права, все четыре эндпоинта раздела возвращают отказ в доступе независимо от прочих его прав в системе.

## Как это используется

Типичный сценарий разбора: сначала смотрят **общую сводку**, чтобы понять суммарный вклад допуслуг в выручку за период и долю фактически собранных денег от плана. Затем открывают **список услуг**, чтобы понять, какие именно виды услуг дают основной объём — например, сравнить прогноз и факт по каждому виду и найти услуги с большим разрывом (признак проблем с оплатой или с исполнением). После этого переходят к **обзору по исполнителям**, чтобы посчитать вклад и загрузку конкретных сотрудников по услугам — это тот же материал, что используется при расчёте бонусов и премий за услуги. Наконец, **история начислений** используется для точечной проверки: найти конкретную заявку и день, чтобы объяснить расхождение между прогнозом и фактом, увидеть статус заявки на тот момент и клиента, которому услуга оказывалась.

## Подводные камни

<Warning>
- **Отменённые заявки без оплаты полностью выпадают из отчётов.** Если заявка отменена и по ней не внесено ни одной оплаты, все её услуги исключаются из всех четырёх представлений раздела — даже если услуги формально были назначены или фактически оказаны.
- **Один и тот же фильтр пригодности заявки действует везде одинаково.** Общая сводка, список услуг, обзор по исполнителям и история начислений применяют совершенно одинаковое условие отбора заявок, ещё до пользовательских фильтров по дате, услуге или исполнителю.
</Warning>

<Info>
- Фильтр по исполнителю смотрит на сотрудника, привязанного к самой позиции услуги в заявке; если у позиции услуги исполнитель не указан, отфильтровать такую запись по конкретному сотруднику не получится ни при каком значении фильтра.
- В «Списке услуг» и «Обзоре по исполнителям» показатель «Количество» считает уникальные позиции услуги, а не строки начислений — поэтому многодневная услуга увеличивает только показатель «Дней», но не «Количество».
- Поле «Исполнители» в «Списке услуг» — это объединённый перечень сотрудников по всей группе услуги; если у части позиций исполнитель не указан, в перечне может встретиться пустое значение как один из элементов.
- Поиск по имени и фамилии исполнителя работает в «Списке услуг» и в «Истории начислений», но в «Обзоре по исполнителям» поиск ограничен только названием услуги — хотя сама таблица сгруппирована именно по исполнителю. Это легко упустить при сравнении экранов.
- В настройках «Истории начислений» заявлен ещё один вариант сортировки, который на деле не соответствует ни одному полю, реально присутствующему в этом отчёте, — рассчитывать на него как на рабочую сортировку не стоит.
- Статус заявки в истории начислений передаётся числовым кодом, а не готовой текстовой надписью — расшифровка происходит на стороне интерфейса.
- Клиент в истории начислений показан кратким набором полей, а не полной карточкой клиента.
</Info>
