## Что показывает раздел «Транзакции»

Раздел «Транзакции» — это финансовый журнал компании: список всех денежных операций (оплаты аренды, продаж, работ мастерской, обслуживания техники, депозитов, штрафов и произвольных проводок по счетам) плюс два вида готовых сводок над этим списком — по видам оплаты и по дням. Все три представления работают над одним и тем же набором операций и используют одинаковые фильтры, поэтому применённый фильтр (период, точка проката, клиент и т.д.) одинаково влияет и на список, и на обе сводки.

<Info>
В основе раздела лежит единая запись финансовой операции: одна и та же таблица хранит и поступления, и списания, различая их по направлению операции. Списание всегда хранится как отрицательное число, поступление — как положительное; это происходит автоматически при сохранении операции, независимо от того, как сумма была введена изначально.
</Info>

## Какие операции попадают в отчёты

Прежде чем данные окажутся в любом из трёх представлений раздела, применяются два обязательных условия отбора — они действуют всегда, до всех остальных фильтров:

1. **Учитываются только успешные операции.** Операции со статусом «Ожидает оплаты», «Ошибка» или «Истёк срок» в отчёты не попадают — это актуально прежде всего для онлайн-оплат, которые могут повиснуть в ожидании или завершиться неудачей.
2. **Операции с нулевой суммой исключаются полностью.**

<Warning>
Финансовые операции, которые являются строкой ведомости учёта (например, привязаны к приходу/расходу по инвентарю или к контрагенту в рамках сверки), из раздела «Транзакции» исключаются полностью — они не попадают ни в список операций, ни в одну из сводок. Это отдельный контур учёта, не пересекающийся с метриками.
</Warning>

## Общая сводка транзакций по дням

Эта сводка отвечает на вопрос «сколько денег прошло по компании и откуда именно» в разрезе каждого дня. Операции группируются по дате создания (без времени), и для каждого дня отдельно суммируются операции, связанные с:

| Источник операции | Что суммируется |
| --- | --- |
| Аренда | Все операции, привязанные к заявке на аренду |
| Продажа | Все операции, привязанные к продаже |
| Мастерская | Все операции, привязанные к задаче мастерской |
| Обслуживание | Все операции, привязанные к обслуживанию инвентаря |

Отдельным полем показывается итоговая сумма — сумма вообще всех операций за день, включая те, что не привязаны ни к одному из четырёх источников выше (например, произвольная операция по счёту).

<Note>
Суммы по каждому источнику и итоговая сумма считаются независимо друг от друга. Если у операции нет ни аренды, ни продажи, ни мастерской, ни обслуживания, она не войдёт ни в одну из четырёх колонок-источников, но попадёт в итоговую сумму. Из-за этого сумма четырёх колонок-источников не обязана совпадать с итоговой суммой.
</Note>

Дни без единой подходящей операции в сводке не появляются — строится только по датам, где реально была хотя бы одна операция. Список сортируется по дате в обратном порядке (сначала последние дни), но сортировку можно переключить на любую из сумм (по аренде, по продажам, по мастерской, по обслуживанию или по итоговой сумме) — как по возрастанию, так и по убыванию.

## Сводка по видам оплаты

Эта сводка отвечает на вопрос «в разрезе способа оплаты и направления операции — сколько операций и на какую сумму». Операции группируются одновременно по виду оплаты (наличные, карта и т.п.) и по направлению операции (поступление или списание). Для каждой такой группы отчёт показывает:

| Поле | Назначение |
| --- | --- |
| Вид оплаты | Название вида оплаты из справочника (может отсутствовать, если у операции вид оплаты не указан) |
| Направление операции | Поступление или списание (может отсутствовать по той же причине) |
| Количество операций | Сколько операций попало в эту группу |
| Сумма | Суммарная сумма операций группы (с учётом знака — списания уменьшают сумму) |

Эта сводка не постраничная — отдаётся сразу целиком, без ограничения на количество строк, и не поддерживает сортировку (порядок групп определяется базой данных).

## Список операций

Постраничный список отдельных операций — самый детальный уровень раздела. Каждая строка списка содержит:

| Поле | Назначение |
| --- | --- |
| Направление операции | Поступление или списание |
| Сумма | Сумма операции (со знаком) |
| Вид оплаты | Ссылка на справочник видов оплаты |
| Дата и время создания | Момент создания операции |
| Создал | Сотрудник, оформивший операцию |
| Статус операции | Всегда «Успешно» — иные статусы в этот список не попадают (см. правило отбора выше) |
| Аренда / Продажа / Задача мастерской / Обслуживание / Депозит | Связанный бизнес-объект, если операция к нему привязана |
| Имя клиента | Определяется автоматически: сначала ищется клиент через аренду, если её нет — через продажу, если и её нет — через задачу мастерской |
| Статус аренды | Статус связанной заявки на аренду (если операция связана с арендой) |
| Точка проката | Определяется по той же логике, что и клиент: аренда → продажа → мастерская |

<Note>
Имя клиента, точка проката и телефон клиента в списке операций — это не хранимые поля самой операции, а значения, «подтянутые» на лету через связанные аренду, продажу или задачу мастерской, в порядке приоритета: сначала проверяется аренда, затем продажа, затем мастерская. Если операция не связана ни с одним из этих трёх объектов (например, это произвольная операция по счёту или операция по обслуживанию), эти поля останутся пустыми.
</Note>

Список поддерживает сортировку по виду оплаты, сумме, сотруднику-создателю и дате создания, а также полнотекстовый поиск по имени и телефону клиента (ищет одновременно по клиенту аренды, продажи и мастерской).

## Фильтрация

Все три представления раздела — общая сводка, сводка по видам оплаты и список операций — используют общий набор фильтров, применяемых поверх правил отбора из раздела выше:

| Фильтр | Как работает |
| --- | --- |
| Клиент | Оставляет операции, где клиент найден через аренду, продажу или задачу мастерской |
| Точка проката | Оставляет операции, где точка проката найдена через аренду, продажу или задачу мастерской |
| Источник операции | Оставляет только операции, привязанные к выбранному типу объекта: аренда, продажа, мастерская или обслуживание |
| Признак возврата | Если включён — оставляет только операции, по которым оформлен возврат оплаты; если выключен — фильтр не применяется вообще (не исключает операции с возвратом) |
| Наличие связи с арендой / продажей / мастерской / обслуживанием | Отдельные да/нет-фильтры на присутствие каждой из этих связей |
| Вид оплаты, Создал | Точное значение или список значений |
| Статус аренды | Точное значение или список значений (для операций, связанных с арендой) |
| Дата создания | Диапазон «с даты» / «по дату» |
| Направление операции, Статус операции | Точное значение или список значений |

<Tip>
Фильтр по клиенту и по точке проката не требует, чтобы источник операции был задан явно — они сами проверяют все три возможные связи (аренда, продажа, мастерская) через «или», поэтому клиента можно найти независимо от того, через какой именно тип операции он связан.
</Tip>

## Как это используется

Общая сводка по дням даёт быстрый ответ на вопрос «что происходило с деньгами компании за период и по каким направлениям бизнеса», сводка по видам оплаты — «через какие способы оплаты и в каком направлении шли деньги», а постраничный список — детализацию до конкретной операции с привязкой к клиенту и точке проката. Благодаря общим правилам отбора и общим фильтрам все три отчёта всегда согласованы между собой: если применить один и тот же фильтр (например, по точке проката и периоду), суммы в общей сводке будут ровно суммой сумм в списке операций за тот же период.

## Подводные камни

<Warning>
- Операции, которые являются строкой ведомости учёта (сверка с контрагентами, приход/расход по инвентарю), полностью исключаются из всех трёх отчётов раздела — это легко упустить при сверке итоговых сумм с другими источниками.
- В отчётах учитываются только операции со статусом «Успешно»; операции в статусах «Ожидает оплаты», «Ошибка» и «Истёк срок» никогда не появятся ни в списке, ни в сводках, даже если задать по ним фильтр по статусу — исходные данные уже отфильтрованы по успешному статусу до применения любых остальных фильтров.
</Warning>

- Операции с нулевой суммой полностью исключаются из всех отчётов раздела.
- В общей сводке по дням сумма четырёх колонок-источников (аренда, продажа, мастерская, обслуживание) может не совпадать с итоговой суммой за день: итоговая сумма включает операции без привязки ни к одному из четырёх источников (например, произвольные операции по счёту), а колонки-источники — нет.
- Имя клиента, телефон, аватар и точка проката в списке операций вычисляются по фиксированному приоритету связей: сначала аренда, затем продажа, затем задача мастерской; операции, связанные только с обслуживанием техники (или вовсе ни с чем), не получают клиента — обслуживание не участвует в этой цепочке подстановки.
- Фильтр «Признак возврата» действует только когда включён; при выключенном значении он не убирает и не оставляет ничего специально — операции с возвратом также остаются в общей выборке.
- Сводка по видам оплаты не поддерживает постраничность и сортировку — все группы отдаются одним ответом сразу.
- В сводке по видам оплаты вид оплаты и направление операции могут быть пустыми, если у операции они не заданы — такие операции образуют отдельную группу с пустыми значениями, а не исключаются.
- Сумма операции автоматически приводится к отрицательному значению для списания и к положительному для поступления при сохранении, независимо от знака, с которым сумма была передана изначально — это происходит на уровне самой записи операции, а не в отчётах.
