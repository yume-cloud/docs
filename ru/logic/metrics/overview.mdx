## Что показывает эта страница

«Обзор и общая сводка» — это точка входа в раздел «Метрики и аналитика». Здесь компания видит, сколько дохода и по каким источникам она заработала по дням: аренда инвентаря, услуги, доставки, штрафы, продажи и работы мастерской. Раздел строится не поверх «сырых» заявок и сделок напрямую, а поверх отдельной денормализованной таблицы «Прибыль» — построчного журнала начислений, где каждая запись — это один источник дохода (аренда конкретной единицы инвентаря, услуга, доставка, штраф, продажа или работа мастерской) за один конкретный день.

Обзор состоит из трёх слоёв данных:

1. **Дневная сводка** — одна строка на каждый день: сколько было аренд/услуг/доставок/штрафов/задач мастерской/продаж и на какую сумму.
2. **Детализация сводки** — построчный список записей «Прибыли» за период, с привязкой к клиенту, инвентарю, услуге и фактической оплате.
3. **Детализация по заявкам** — то же самое, но агрегированное не по отдельным начислениям, а по конкретной аренде за день (сколько заявка принесла в этот день суммарно).

<Note>
Все три отчёта читают данные из одной и той же таблицы «Прибыль». Они не пересчитывают начисления на лету — «Прибыль» уже содержит готовые дневные суммы, которые эти отчёты только группируют, фильтруют и подтягивают к ним сопутствующую информацию (клиент, инвентарь, оплата).
</Note>

## Модель данных

### Прибыль (запись начисления)

Каждая запись «Прибыли» относится ровно к одному дню и ровно к одному источнику дохода. У записи есть связь с одной из сущностей: аренда инвентаря в рамках заявки, услуга в рамках заявки, доставка, штраф, продажа или работа мастерской (а также техническая связь с обслуживанием инвентаря, которая в дневной сводке отражается только суммой, без отдельного счётчика).

| Поле | Тип | Назначение |
|---|---|---|
| Дата | дата | День, за который начислена сумма |
| Единица инвентаря | связь | Инвентарь, к которому относится начисление (для аренды и продаж) |
| Заявка (аренда) | связь | Аренда, к которой относится начисление |
| Прогноз (начислено) | число (2 знака) | Сумма, причитающаяся за день по графику, независимо от факта оплаты |
| Прибыль (получено) | число (2 знака) | Фактически зачтённая сумма за день с учётом того, что клиент реально оплатил |

<Info>
«Прогноз» и «Прибыль» — разные числа. «Прогноз» — это то, что должно быть начислено за день по графику (например, дневная ставка аренды за вычетом скидки). «Прибыль» — это то, что фактически покрыто оплатой клиента: если клиент оплатил не полностью, «Прибыль» может быть меньше «Прогноза» за тот же день, а на более поздние дни аренды может уже не хватить оплаченной суммы вовсе (тогда «Прибыль» по этим дням будет нулевой, пока клиент не доплатит).
</Info>

### Тип источника прибыли

Каждая запись «Прибыли» относится к одному из типов источника дохода. Тип не хранится как отдельное поле — он вычисляется по тому, какая из связей (с арендой инвентаря, услугой, доставкой, штрафом, продажей, работой мастерской или обслуживанием) заполнена у записи, и дополнительно проверяется статус связанной сущности:

- **Аренда (инвентарь)** — запись относится к аренде конкретной единицы инвентаря; сама аренда не удалена и находится в одном из статусов «в аренде», «завершена», «должник», либо отменена, но по ней уже была получена оплата.
- **Услуга** — то же условие по статусу аренды, но запись относится к услуге в рамках заявки.
- **Доставка** — то же условие по статусу аренды, запись относится к доставке.
- **Штраф** — то же условие по статусу аренды, запись относится к штрафу.
- **Мастерская (работа)** — запись относится к задаче мастерской, которая находится в статусе «в работе» или «завершена».
- **Продажа** — запись относится к продаже, которая находится в статусе «продано».
- **Обслуживание** — отдельная категория без дополнительных условий по статусу; в дневной сводке отражается только суммой, без счётчика количества.

<Warning>
Если аренда отменена и по ней не было оплаты (нулевая оплаченная сумма), связанные с ней записи «Прибыли» по аренде, услугам, доставке и штрафам **не считаются** доходом ни в одном из отчётов «Обзора» — они полностью выпадают из сумм и счётчиков. Также не учитываются записи по удалённым заявкам.
</Warning>

## Дневная сводка

Дневная сводка — это список из одной строки на каждый день, за который есть хотя бы одна засчитываемая запись «Прибыли». Список отсортирован от самой поздней даты к самой ранней.

Для каждого дня отдельно считаются:

**Счётчики** (количество уникальных источников дохода за день):
- Количество аренд — число заявок, по которым в этот день было начисление за инвентарь.
- Количество услуг, количество доставок, количество штрафов — аналогично, по своим типам.
- Количество задач мастерской — число задач мастерской с начислением в этот день.
- Количество продаж — число продаж с начислением в этот день.

**Суммы** (сумма поля «Прогноз», то есть плановая сумма начислений, а не фактически полученная оплата):
- Сумма по аренде, сумма по услугам, сумма по доставкам, сумма по штрафам, сумма по мастерской, сумма по обслуживанию, сумма по продажам — сумма прогноза по каждому типу за день отдельно.

**Итоги**:
- Итоговый прогноз — сумма прогноза по всем годным типам (аренда, услуги, доставки, штрафы, мастерская, продажи — без обслуживания) за день.
- Итоговая прибыль — сумма фактически зачтённой прибыли по тем же типам за день.

<Info>
Суммы по отдельным типам («Сумма по аренде», «Сумма по услугам» и т. д.) считаются от поля «Прогноз» — то есть это плановая, начисленная сумма, а не то, что клиент реально заплатил. Единственное место, где видна именно фактически зачтённая сумма на уровне дня — поле «Итоговая прибыль».
</Info>

<Warning>
Сумма по обслуживанию входит в построчную разбивку сумм, но не входит ни в «Итоговый прогноз», ни в «Итоговую прибыль», ни в какой-либо счётчик количества. Это единственный тип, который отображается в сводке только суммой без числа операций и не учитывается в итогах — это может создать впечатление ошибки при сверке (сумма всех строк не сойдётся с итогом ровно на сумму по обслуживанию).
</Warning>

### Итоги по всему периоду (не только по странице)

Список сводки выводится постранично. Помимо самих строк, ответ содержит блок с итогами — но эти итоги считаются не по текущей странице, а заново, по всей выборке с учётом применённых фильтров (по всем дням, которые подходят под фильтр, а не только по тем, что показаны на экране). В этот блок дополнительно попадает общее количество уникальных заявок с любым засчитываемым начислением за весь отфильтрованный период, независимо от типа.

<Note>
Итоги пересчитываются отдельным запросом по всей отфильтрованной выборке. Это значит, что при переключении между страницами блок итогов не меняется — он одинаков для любой страницы одного и того же набора фильтров.
</Note>

## Детализация дневной сводки

Детализация — это построчный список записей «Прибыли» (без группировки по дню), с подтянутыми данными по инвентарю, услуге, клиенту и фактической оплате. Используется, когда нужно провалиться из сводки в конкретные операции за день.

К каждой записи подтягивается:

| Поле | Тип | Назначение |
|---|---|---|
| Прогноз | число (2 знака) | Начисленная за день сумма по этой записи |
| Прибыль | число (2 знака) | Фактически зачтённая сумма по этой записи |
| Оплачено клиентом | число (2 знака) | Сумма оплат клиента за этот день |
| Имя клиента | текст | Клиент, связанный с арендой, продажей или задачей мастерской |
| Статус заявки | число (код статуса) | Статус связанной аренды, если запись относится к аренде |

Клиент, его имя, телефон и аватар определяются по цепочке: сначала проверяется клиент аренды, если его нет — клиент продажи, если и его нет — клиент задачи мастерской. Берётся первое найденное значение.

<Warning>
Сумма «Оплачено клиентом» в детализации считается по клиенту и дню, а не по конкретной аренде, продаже или задаче мастерской. Если у одного клиента в один и тот же день есть несколько записей (например, начисления по двум разным арендам), в поле «Оплачено клиентом» у обеих записей подставится одна и та же сумма — общая сумма всех оплат клиента за этот день, а не оплата именно по этой аренде. Это может визуально задваивать сумму оплаты при просмотре нескольких строк одного клиента за один день.
</Warning>

В детализации доступна отдельная сортировка по дате, прогнозу, прибыли, инвентарю (в том числе по номеру автомобиля), группе инвентаря, услуге, категории, аренде, доставке, задаче мастерской, продаже, обслуживанию, имени клиента и сумме оплаты.

## Детализация по заявкам

Третий отчёт агрегирует записи «Прибыли» не по отдельным начислениям, а по паре «день + заявка»: сколько конкретная аренда принесла в этот день суммарно (по всем её составляющим — инвентарю, услугам, доставке, штрафам вместе). Сюда попадают только записи, у которых заполнена связь с арендой; продажи и задачи мастерской в этот отчёт не входят.

| Поле | Тип | Назначение |
|---|---|---|
| ID заявки | число | Аренда, по которой считается сумма |
| Статус заявки | число (код статуса) | Статус аренды |
| Сумма прогноза | число (2 знака) | Сумма прогноза по заявке за день (по всем её начислениям в этот день) |
| Сумма прибыли | число (2 знака) | Сумма прибыли по заявке за день |
| Оплачено клиентом | число (2 знака) | Сумма оплат клиента по этой заявке за этот день |

<Info>
В отличие от общей детализации, здесь «Оплачено клиентом» считается строго по конкретной заявке и дню, а не по клиенту в целом — то есть суммы уже не задваиваются между разными арендами одного клиента.
</Info>

## Фильтры

Все три отчёта используют общий набор фильтров дат: точная дата, дата "с" и дата "по". Дневная сводка и построчная детализация дополнительно поддерживают:

- **Тип источника прибыли** — сузить выборку до одного типа: инвентарь (аренда), услуга, доставка, штраф, мастерская, обслуживание или продажа.
- **Точка проката** — ограничить выборку одной точкой; точка ищется через аренду, задачу мастерской или продажу (в зависимости от того, что заполнено у записи).
- **Клиент** — ограничить выборку одним клиентом; клиент ищется через аренду, продажу или задачу мастерской.

Детализация по заявкам поддерживает точку проката и клиента, но только через связь с арендой (продажи и задачи мастерской в этот отчёт и так не попадают).

<Warning>
У фильтра «Тип источника прибыли» в списке значений формально присутствует ещё один пункт — «аренда» — отдельно от пункта «инвентарь». На деле он ничего не фильтрует: если выбрать именно «аренда», отчёт вернёт все записи без сужения по типу, как будто фильтр вообще не применялся. Реально работающее значение для отбора аренд инвентаря — «инвентарь». Это фактическое поведение фильтра в текущем коде, а не задуманная особенность — стоит иметь в виду при интеграции.
</Warning>

<Tip>
Если фильтр по дате не передан, отчёты не ограничивают период сами — вернутся все дни, за которые вообще есть данные. Диапазон по умолчанию для интерфейса (например, «текущий месяц») задаётся на уровне запроса, а не сервера.
</Tip>

## Права доступа к аналитике (кратко)

Каждый раздел аналитики защищён отдельным правом доступа: продажи, клиенты, бонусы сотрудников, обслуживание, заявки (аренды), штрафы по заявкам, депозиты по заявкам, скидки по заявкам, финансы (включая отдельные права на прибыли и убытки, движение денежных средств, историю операций), зарплаты сотрудников, активность сотрудников, смены сотрудников, доходность инвентаря, эффективность инвентаря, амортизация инвентаря, субаренда инвентаря.

Эти права не образуют отдельную страницу — они выдаются сотруднику индивидуально или через роль в общей модели прав доступа компании, там же, где настраиваются права на остальные разделы CRM (заявки, клиенты, инвентарь и т. д.).

<Warning>
Дневная сводка (как и большинство других отчётов раздела «Метрики и аналитика») не проверяет какое-то одно конкретное право доступа к своему разделу — вместо этого она требует от сотрудника **одновременно все** права из общего списка прав доступа к метрикам (продажи, клиенты, бонусы, обслуживание, заявки, штрафы, депозиты, скидки, финансы и все их подпункты, зарплаты, активность, смены, доходность, эффективность, амортизация, субаренда). Если сотруднику не выдано хотя бы одно из этих прав, он получит отказ в доступе к дневной сводке и ко всем остальным отчётам этого списка, даже если формально ему разрешена только часть аналитики. Практический вывод: чтобы у сотрудника вообще открылся раздел «Метрики и аналитика» (включая обзор), ему нужно выдать полный набор прав аналитики целиком, а не выборочно.
</Warning>

## Как это используется

Типичный сценарий: руководитель открывает обзор за текущий месяц и видит по дням, сколько заявок было закрыто, сколько принесли услуги и доставки, где просели продажи. Если суммы по дню выглядят подозрительно (например, прогноз есть, а прибыли нет), он проваливается в детализацию за этот день, чтобы увидеть, по какому клиенту и какой аренде висит неоплаченный остаток — для этого сравниваются поля «Прогноз» и «Прибыль» на уровне отдельной записи, а сумма «Оплачено клиентом» показывает, сколько клиент вообще внёс в этот день.

Детализация по заявкам используется, когда нужно оценить конкретную аренду целиком за день, не разбираясь по отдельности в её инвентаре, услугах и доставке — например, чтобы быстро увидеть, какие заявки в этот день недополучили оплату.

## Особенности поведения

<Info>
- Детализация по заявкам считает оплату клиента строго по конкретной заявке и дню, поэтому там суммы не задваиваются между разными арендами одного клиента.
- Сумма по обслуживанию отображается в построчной разбивке сводки, но не входит ни в итоговый прогноз, ни в итоговую прибыль, ни в какой-либо счётчик количества — а счётчик количества операций обслуживания вообще не отдаётся наружу.
- Отменённая аренда без оплаты полностью исключается из всех трёх отчётов — по инвентарю, услугам, доставке и штрафам, независимо от выбранного фильтра типа.
- Фильтр по точке проката и по клиенту ищет совпадение через аренду, продажу или задачу мастерской — то есть указанный ID может относиться к любой из этих трёх сущностей.
- Если фильтр по дате не передан, отчёты возвращают данные за весь доступный период, без ограничения по умолчанию на стороне сервера.
</Info>
