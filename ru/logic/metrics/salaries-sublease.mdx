Полный перечень полей — в [глоссарии](/ru/logic/metrics/salaries-sublease-glossary).

## Что показывает эта страница

Страница объединяет два независимых, но родственных отчёта:

1. **Зарплаты сотрудников** — сколько компания должна начислить сотруднику за период: фиксированный оклад плюс бонусы за фактически выполненные действия по заявкам аренды (создание, бронирование, сбор, выдача, приём, доставка).
2. **Субаренда инвентаря сотрудникам** — если сотруднику передана в личное пользование («в субаренду») часть инвентаря компании, отчёт показывает, сколько на этом инвентаре заработала компания и сколько из этой прибыли причитается самому сотруднику-владельцу.

Оба отчёта строятся «на лету» по запросу (это не хранимые таблицы, а вычисляемые выборки за выбранный период) и требуют обязательных параметров периода — начала и конца.

<Note>
Период задаётся включительно с обеих сторон: и начальная, и конечная дата целиком входят в выборку (сравнение идёт по календарной дате создания записи, без учёта времени суток). Формат дат: `ГГГГ-ММ-ДД` или `ГГГГ-ММ-ДД ЧЧ:ММ:СС`. Если период не передан явно, по умолчанию берётся текущий календарный месяц — с 1-го числа текущего месяца по 1-е число следующего месяца включительно.
</Note>

## Модель данных

### Оклад сотрудника

У каждого сотрудника может быть ровно один оклад — фиксированная сумма за один календарный месяц.

| Поле | Тип | Назначение |
|---|---|---|
| Сотрудник | связь (1:1) | владелец оклада |
| Сумма оклада | число (2 знака) | сумма за один месяц |

В отчёте оклад умножается на количество календарных месяцев, попавших в выбранный период (например, за период в два с половиной месяца оклад будет умножен на 3, так как считается количество начал месяцев в диапазоне). Если оклад сотруднику не назначен, в отчёте используется 0.

В сводный список по зарплатам попадают только пользователи, у которых есть запись о членстве в текущей компании с признаком «сотрудник» (штатный персонал); отдельного признака «активное/неактивное членство» в этой записи не предусмотрено — учитывается сам факт наличия такой записи с этим признаком.

### Действие по заявке

Каждый раз, когда сотрудник выполняет значимое действие над заявкой аренды, создаётся отдельная запись действия: кто выполнил, по какой заявке, какого типа и когда. К действию может быть привязано несколько единиц инвентаря заявки (используются для расчёта суммы бонуса), а для доставок — связанная запись доставки.

Типы действий, за которые начисляется бонус:

| Тип действия | Описание |
|---|---|
| Создание заявки | заявка аренды создана |
| Бронирование | инвентарь по заявке забронирован |
| Сбор (комплектация) | инвентарь физически подготовлен к выдаче |
| Выдача | инвентарь передан клиенту |
| Приём (возврат) | инвентарь принят обратно от клиента |
| Доставка: забор инвентаря | инвентарь забран у клиента при доставке |
| Доставка: выдача инвентаря | инвентарь доставлен клиенту |

Есть и служебные типы действий («отмена», «архивация»), которые фиксируются в истории, но бонусов за них не начисляется.

### Проценты вознаграждения

У каждой заявки при её создании автоматически заводится собственный набор процентов вознаграждения (по одному значению на каждый из пяти типов действий, кроме доставки) — со значениями, равными общим настройкам компании на момент создания заявки. Именно эти проценты, привязанные к конкретной заявке, и используются при расчёте бонусов по её действиям.

Если по каким-то данным такой набор процентов у заявки отсутствует, используются текущие общие настройки компании по умолчанию как запасной вариант.

<Info>
Поскольку набор процентов заводится для заявки автоматически при её создании, более позднее изменение общих настроек компании не пересчитывает проценты уже существующих заявок — они сохраняют те значения, что действовали в момент создания заявки.
</Info>

Общие настройки компании по умолчанию: за создание заявки — 0%, за бронирование — 4%, за сбор — 0%, за выдачу — 3%, за приём — 3%, за доставку — 10%.

## Логика расчёта зарплаты

### Формула бонуса за действие (кроме доставки)

Для каждого из пяти типов действий (создание, бронирование, сбор, выдача, приём) бонус сотрудника за период считается так:

1. Берутся все действия этого типа, выполненные сотрудником, у которых заявка попадает в период по дате создания заявки, имеет один из статусов, разрешённых для учёта в метриках (по умолчанию — только «завершена»), и статус оплаты из разрешённого списка (по умолчанию — только «оплачено полностью»).
2. Для каждого такого действия берётся прогнозируемая прибыль (без вычета скидок и с учётом графика оплаты) по всем единицам инвентаря, затронутым этим действием, и суммируется.
3. Полученная сумма (это и есть «оборот» по действиям этого типа) умножается на процент вознаграждения этой заявки для данного типа действия (см. раздел выше про проценты вознаграждения).
4. Если сотрудник за период не выполнял действий этого типа, бонус по нему равен 0.

Эта же логика (шаги 1–3) идентична, будь то сводная строка по сотруднику или детализация по типам действий одного сотрудника — отличается только группировка результата.

### Формула бонуса за доставку

Бонус за доставку считается отдельно и по другой формуле, так как в доставке участвует не прогноз прибыли по инвентарю, а параметры самой доставки:

1. Берутся все записи доставки со статусом «выполнена», где связанная заявка попадает в период по дате создания и удовлетворяет тем же фильтрам по статусу заявки и статусу оплаты, что и остальные действия.
2. Для каждой такой доставки бонус сотрудника-исполнителя доставки равен: фиксированная цена этой доставки **плюс** доля (процент доставки по настройкам компании) от разницы между итоговой суммой к оплате по заявке (после скидки) и суммарной стоимостью всех доставок по этой заявке, **делённая** на количество дней исходной (запланированной при создании) длительности аренды, округлённое вверх до целого.
3. Суммы по всем доставкам сотрудника за период складываются.

<Warning>
В знаменателе формулы используется исходная (изначально запланированная при создании заявки) длительность аренды, а не фактическая длительность на текущий момент — если заявка позже была продлена или сокращена, на бонус за доставку это не влияет.
</Warning>

### Итоговые суммы по сотруднику

| Поле | Формула |
|---|---|
| Итого бонусов | сумма бонусов за создание, бронирование, сбор, выдачу, приём и доставку за период |
| Итого к начислению | оклад за период (уже умноженный на число месяцев) плюс итого бонусов |

### Детализация по типам действий

Отдельный отчёт позволяет посмотреть по одному сотруднику расшифровку: сколько раз он выполнил действия каждого типа за период, какой оборот (сумма прогноза прибыли по затронутому инвентарю) этот тип действий принёс и какой бонус из этого оборота причитается сотруднику. Здесь дополнительно можно фильтровать по типу действия, статусу заявки, статусу оплаты и точной дате действия — в отличие от сводного отчёта, где период и статусы задаются один раз для всех типов сразу.

Есть также построчный вид — каждое отдельное действие сотрудника с рассчитанным процентом, суммой бонуса и списком инвентаря, который был затронут именно этим действием (полезно для проверки, из чего конкретно сложилась сумма).

<Info>
В детализации по типам действий и в построчном списке действий фильтр по периоду и по разрешённым статусам заявки/оплаты **не применяется автоматически** — эти отчёты по умолчанию показывают действия сотрудника без ограничения по бизнес-статусам компании (только по явно переданным фильтрам в запросе). Из-за этого суммы в детализации могут не совпадать один в один со сводной строкой по сотруднику, если не задать одинаковые фильтры вручную.

Кроме того, эти два отчёта считают процент и бонус только для пяти обычных типов действий (создание, бронирование, сбор, выдача, приём). Действия по доставке в них тоже видны (попадают в счётчик количества действий), но их бонус в этих двух отчётах всегда показывается как 0 — реальный бонус за доставку рассчитывается по отдельной формуле и виден только в сводном отчёте по сотруднику.
</Info>

## Логика расчёта субаренды

### Что такое субаренда инвентаря

Любая единица инвентаря компании может быть помечена как переданная в субаренду конкретному сотруднику с указанием процента субаренды — доли прибыли от аренды этой единицы, которая причитается сотруднику-владельцу. Остаток (100% минус процент субаренды) остаётся доходом компании.

### Кто попадает в отчёт по субаренде

В отчёт включаются пользователи, которые: во-первых, состоят в текущей компании (есть соответствующая запись о членстве), и во-вторых, у которых в этой записи о членстве в компании включён признак «сотрудник-субарендатор».

<Warning>
Наличие признака «сотрудник-субарендатор» определяется отдельно для каждой компании, в которой состоит пользователь (это свойство самой записи о членстве, а не роль вроде администратора). Если сотруднику передан инвентарь в субаренду, но признак «сотрудник-субарендатор» у него в этой компании не включён, такой сотрудник не появится ни в сводном списке по субаренде, ни в общей сводке — его инвентарь и доход как бы «теряются» для этого отчёта, хотя сама передача в субаренду на уровне инвентаря сохранена корректно.
</Warning>

### Факт и прогноз

Отчёт по субаренде всегда считает две параллельные суммы:

- **Факт** — прибыль по дням аренды, которая приходится на заявки со статусом «завершена» или «должник», за выбранный период (по дате начисления прибыли, а не по дате создания заявки).
- **Ожидаемый доход** — прогнозируемая прибыль по дням аренды для заявок, которые ещё находятся в процессе: «в аренде», «забронирована» или «должник».

<Note>
Статус «должник» участвует одновременно и в факте, и в прогнозе, потому что по такой заявке часть прибыли уже фактически получена, а часть ещё ожидается.
</Note>

Для каждой из этих двух сумм считается доля сотрудника (сумма прибыли за период, умноженная на процент субаренды и делённая на 100) и доля компании (та же сумма прибыли, умноженная на «100 минус процент субаренды» и делённая на 100).

### Уровни детализации субаренды

1. **По сотрудникам** — для каждого сотрудника-субарендатора: сколько единиц инвентаря он держит в субаренде, их суммарная цена покупки, факт и прогноз дохода — общий, доля сотрудника и доля компании. Есть необязательный фильтр по точке аренды: при его использовании он применяется одновременно и к количеству/стоимости инвентаря, и к суммам дохода (факт/прогноз, включая доли сотрудника и компании) — то есть при выбранной точке все показатели строки считаются только по инвентарю этой точки.
2. **Итоговая сводка** — агрегат по всем сотрудникам-субарендаторам сразу: количество сотрудников, суммарное количество единиц инвентаря, суммы и средние значения факта и прогноза (общие, по сотрудникам, по компании).
3. **По единицам инвентаря одного сотрудника** — список конкретных единиц инвентаря, которые сотрудник держит в субаренде, с ценой покупки, процентом субаренды и теми же четырьмя суммами дохода (факт/прогноз × сотрудник/компания) для каждой позиции. Здесь фильтр по точке аренды ограничивает сам список единиц инвентаря.
4. **История начислений** — построчная история по дням: для каждой единицы инвентаря в субаренде и каждой заявки, в которой она участвовала, отдельная запись с датой начала и конца учитываемого дня, фактической и прогнозируемой прибылью за этот конкретный день, статусом и точкой заявки. Позволяет проверить, из каких именно дней аренды сложилась итоговая сумма по сотруднику или по единице инвентаря.

### Права доступа к отчёту по субаренде

Если у обращающегося пользователя в текущей компании включён признак «сотрудник-субарендатор», отчёт по субаренде доступен ему в режиме чтения без специального разрешения на модели метрик (то есть субарендатор может посмотреть показатели, доступные через эти эндпоинты). Всем остальным пользователям нужно обычное разрешение на доступ к модели метрик.

## Как это используется

<Tip>
Сводный отчёт по зарплатам обычно используется руководителем или бухгалтером для расчёта выплат за месяц: сначала смотрят общий список сотрудников с итоговыми суммами, затем при необходимости проваливаются в детализацию конкретного сотрудника, чтобы понять, из каких действий и заявок сложилась сумма бонуса.
</Tip>

Отчёт по зарплате одного сотрудника (детализация по типам действий и построчная история) также доступен самому сотруднику применительно к собственным данным — это позволяет сотруднику видеть, за что именно он получил вознаграждение, не имея общего доступа к разделу метрик.

Отчёт по субаренде используется для двух разных сценариев: администратор компании контролирует, сколько инвентаря роздано в субаренду и сколько компания зарабатывает на нём сверх доли сотрудников; сам сотрудник-субарендатор (если ему открыт доступ) может проверить свой ожидаемый и фактический доход по переданному ему инвентарю.

## Подводные камни

<Warning>
- В отчёт по субаренде попадают не администраторы компании, а любые пользователи, у которых в записи о членстве в текущей компании включён признак «сотрудник-субарендатор» — отдельной проверки на роль администратора нет.
- Признак, определяющий доступность субаренды, — это персональный признак конкретного сотрудника в конкретной компании, а не общая настройка компании: отдельного общего выключателя субаренды на уровне всей компании не существует.
- При использовании фильтра по точке аренды в отчёте по сотрудникам-субарендаторам он ограничивает не только количество и стоимость инвентаря, но и все суммы дохода (факт/прогноз, доля сотрудника и доля компании) — они считаются только по инвентарю выбранной точки, а не по всему инвентарю сотрудника.
- Индивидуальные проценты вознаграждения заявки нигде не редактируются после её создания — они выставляются один раз автоматически и с тех пор действуют без изменений, даже если общие настройки компании позже меняются.
</Warning>

<Info>
- В детализации по типам действий и в построчном списке действий сотрудника фильтр по разрешённым статусам заявки и оплаты и по периоду не применяется автоматически (в отличие от сводного отчёта по зарплате) — суммы могут расходиться со сводкой, если явно не задать те же фильтры.
- В этих же двух отчётах бонус за действия по доставке всегда показывается как 0 (сами действия при этом видны в счётчике количества) — реальный бонус за доставку виден только в сводном отчёте по сотруднику.
- Период в обоих отчётах включает обе границы целиком — конечная дата учитывается полностью, а не частично.
- Бонус за доставку делится на исходную длительность аренды, запланированную при создании заявки, а не на фактическую текущую длительность — более позднее продление или сокращение аренды на этот бонус не влияет.
- Оклад за период считается как оклад, умноженный на количество календарных месяцев в диапазоне — при периодах длиной не в целое число месяцев пропорциональная часть может получаться завышенной или заниженной.
- Статус «должник» одновременно учитывается и в фактической, и в ожидаемой сумме дохода по субаренде — для таких заявок часть прибыли по смыслу может задваиваться (частично уже получена, частично ещё ожидается), это ожидаемое поведение.
- Общая сводка по зарплатам сотрудников учитывает только пользователей с записью о членстве в компании и признаком «сотрудник» — отдельного признака «активности» такой записи не существует, поэтому речь именно о наличии самой записи.
</Info>
