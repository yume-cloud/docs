## Как это устроено

Проверки живут в `scripts/audit/checks/` в репозитории фронтенда и запускаются
командой `npm run audit`. Каждая проверка описывает одно машинно-проверяемое правило:
часть смотрит на код (`src/`), часть — на целостность самой документации
(`docs.json`, ссылки, изображения, `llms.txt`).

Проверки, которые нельзя сделать надёжно, сознательно не добавлены — например, сопоставление
маршрутов с `PAGE_TITLES`: `resolveDocumentTitle` использует `matchPath({end: false})`,
то есть заголовок подхватывается по префиксу, а часть маршрутов генерируется из массивов,
а не объявляется литералами. Любая регулярка здесь даёт ложные срабатывания.
