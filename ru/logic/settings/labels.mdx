Полный перечень полей — в [глоссарии переименования](/ru/logic/settings/labels-glossary).

Раздел «Переименование сущностей» позволяет компании называть системные объекты своими словами: прокат самокатов может говорить «самокат» вместо «инвентарь», автопрокат — «автомобиль», а сервисный центр — «заказ-наряд» вместо «мастерская». Переименование задаётся не одной строкой, а полным набором форм — единственное и множественное число во всех шести падежах, — чтобы интерфейс мог корректно строить фразы вида «нет свободных самокатов» или «добавить к автомобилю».

## Что можно переименовать

Ключ переименования — это закрытый список из семнадцати позиций: девять справочных сущностей и восемь статусов аренды.

| Группа | Ключи переименования |
| --- | --- |
| Справочные сущности | Инвентарь, Комплект, Продукт, Точка проката, Услуга, Клиент, Депозит, Мастерская, Инвентаризация |
| Статусы аренды | Запрос, Забронировано, В прокате, Отменено, Завершено, Должник, Просрочено, Удалено |

<Note>
Список ключей фиксирован на уровне системы. Добавить в него новую сущность из интерфейса нельзя — переименовать можно только то, что уже перечислено выше.
</Note>

<Check>
**Добавлен ключ «Инвентаризация»** (`inventorization`). Теперь компания может переименовать и раздел инвентаризации.

Для типов компаний с кодами `auto` и `taxi` платформа завела глобальный русский набор «осмотр» во всех двенадцати формах — от «осмотр» и «осмотра» до «осмотрами» и «об осмотрах». Компании этих типов видят «Осмотр» без собственных настроек, пока не заведут своё наименование. Набор создаётся один раз: если у этих типов уже есть глобальный русский набор по этому ключу, новый не добавляется.

Раньше интерфейс подставлял «Осмотр» жёстко — по типу «такси» или по включённой поддержке транспорта, — а остальным писал «Инвентаризация». Теперь подпись инвентаризации в меню, заголовках, форме и окне инвентаризации в карточке аренды берётся из наименования.
</Check>

<Info>
В том же обновлении интерфейс перестал писать «Автомобили», «Водители» и «СТО» напрямую. Эти слова теперь строятся из наименований компании по ключам «Инвентарь», «Клиент» и «Мастерская», с нужным падежом и числом. Например, бывшая подпись «Кол-во автомобилей» собирается из «Кол-во» и родительного падежа множественного числа наименования инвентаря.
</Info>

Переименование статусов аренды — чисто визуальное: смысл статуса, переходы между ними, расчёты и отчётность не меняются. То же верно и для сущностей: система продолжает работать с прежними объектами, меняется только то, как они называются на экране.

## Модель данных

Одна запись наименования — это связка «ключ переименования + язык» и двенадцать форм слова: шесть падежей единственного числа и шесть падежей множественного.

### Идентификация и область действия

| Поле | Тип | Назначение |
| --- | --- | --- |
| Идентификатор | число | Номер записи; используется, чтобы обратиться к конкретному наименованию для изменения или удаления |
| Ключ переименования | выбор из списка | Какую сущность или какой статус аренды переименовывает запись |
| Язык | выбор из списка | Язык, для которого заданы формы. Доступны языки, поддерживаемые системой, — русский и английский |
| Компания | связь | Владелец записи. Пусто — это глобальный набор платформы; заполнено — собственное наименование компании |
| Типы компаний | связь (много) | Типы бизнеса, которым достаётся глобальный набор (прокат авто, самокаты и т. д.). Заполняется только у глобальных наборов |

### Формы слова

| Поле | Тип | Назначение |
| --- | --- | --- |
| Именительный падеж (ед. ч.) | текст | Базовая форма: кто? что? — «Инвентарь» |
| Родительный падеж (ед. ч.) | текст | Кого? чего? — «инвентаря» |
| Дательный падеж (ед. ч.) | текст | Кому? чему? — «инвентарю» |
| Винительный падеж (ед. ч.) | текст | Кого? что? — «инвентарь» |
| Творительный падеж (ед. ч.) | текст | Кем? чем? — «инвентарем» |
| Предложный падеж (ед. ч.) | текст | О ком? о чём? — «об инвентаре» |
| Именительный падеж (мн. ч.) | текст | Базовая форма множественного числа — «Инвентари» |
| Родительный падеж (мн. ч.) | текст | Кого? чего? — «инвентарей» |
| Дательный падеж (мн. ч.) | текст | Кому? чему? — «инвентарям» |
| Винительный падеж (мн. ч.) | текст | Кого? что? — «инвентари» |
| Творительный падеж (мн. ч.) | текст | Кем? чем? — «инвентарями» |
| Предложный падеж (мн. ч.) | текст | О ком? о чём? — «об инвентарях» |

Все двенадцать форм необязательны: запись сохранится, даже если заполнена только часть падежей или не заполнено ничего. Система не достраивает недостающие формы автоматически и не проверяет их согласованность — что записали, то интерфейс и покажет.

<Tip>
Справочник падежей в системе существует отдельно и служит только описанием: сами формы хранятся в перечисленных выше полях, а не выбираются из списка падежей.
</Tip>

## Два уровня: глобальные наборы и наименования компании

Наименования живут в двух слоях.

**Глобальные наименования** заводит платформа. У такой записи не указана компания, зато перечислены типы компаний, которым она предназначена. Это заготовки «из коробки»: например, для типа «прокат самокатов» платформа заранее описывает инвентарь как «самокат» во всех падежах.

**Наименования компании** — записи с указанной компанией. Они перекрывают глобальные значения для этой конкретной компании и ни на кого больше не влияют.

Ограничение уникальности «компания + язык + ключ» действует только для записей компании: у одной компании не может быть двух наименований одного ключа на одном языке. Глобальные наборы этим правилом не ограничены — платформа технически может завести несколько записей на один ключ и язык.

<Info>
Копирования при подключении компании не происходит: глобальные наборы не переносятся в компанию при регистрации. Компания видит их «сквозь» свои записи, а собственная запись появляется только тогда, когда компания сама что-то переименует.
</Info>

## Как формируется итоговый список

Выдача списка наименований работает так:

1. Отбираются записи, принадлежащие текущей компании.
2. К ним добавляются глобальные наборы, привязанные к типу текущей компании. Если у компании тип не указан, глобальные наборы в отбор не попадают вовсе, и список состоит только из собственных записей.
3. Отобранное сортируется так, чтобы записи без компании шли первыми, а записи компании — следом.
4. Результат сворачивается по ключу переименования: на каждый ключ остаётся одна запись, и побеждает та, что встретилась последней, — то есть наименование компании.

Именно шаг 4 обеспечивает правило «компания перекрывает платформу». Он же задаёт важное свойство выдачи: в списке ровно один элемент на ключ переименования. Список отдаётся целиком, без постраничной разбивки.

<Warning>
Свод выполняется только по ключу переименования — язык в нём не участвует, и выбрать язык при запросе списка нельзя. Если по одному ключу заведено несколько языков (например, русский и английский), в итоговый список попадёт лишь один из них, а остальные будут вытеснены. То же касается смешанных случаев: собственная запись на одном языке перекроет глобальную запись на другом.
</Warning>

Каждый элемент списка содержит свой идентификатор, ключ переименования, язык и все формы. Принадлежность компании и привязка к типам компаний в выдаче не показываются, поэтому по ответу нельзя отличить глобальный набор от собственного, кроме как по факту, что компания его сама сохраняла.

## Сохранение: «создать или обновить»

Сохранение нового наименования устроено как идемпотентная операция по паре «ключ переименования + язык» в рамках текущей компании:

- если у компании такой записи ещё нет — она создаётся;
- если запись уже есть — у неё обновляются переданные формы.

Дубликатов повторная отправка не создаёт, а компания и типы компаний в запросе не участвуют: принадлежность подставляется по текущей компании автоматически, а привязка к типам остаётся зоной ответственности платформы. В ответ возвращается сохранённая запись с идентификатором — со статусом «создано» независимо от того, была запись создана или обновлена.

Сохранение всегда порождает запись **компании**. Глобальный набор при этом остаётся нетронутым: он просто перестаёт быть виден в списке, потому что его вытеснила запись компании.

### Изменение и удаление одной записи

Отдельное наименование можно посмотреть, изменить и удалить по его идентификатору, но работает это только с записями текущей компании. Глобальные наборы через этот механизм недоступны: попытка обратиться к ним по идентификатору отвечает «не найдено», хотя в общем списке они видны.

<Warning>
При изменении отдельной записи смена ключа переименования или языка на пару, которая у этой компании уже занята, не отсекается заранее понятным сообщением — сохранение обрывается ошибкой на уровне базы. Безопаснее менять наименования через общий список, где работает режим «создать или обновить».
</Warning>

Удаление записи компании — это и есть «сброс к значению по умолчанию»: после удаления в общем списке снова появляется глобальный набор соответствующего типа компании (если он существует).

<Note>
Отдельной кнопки «вернуть исходное название» в логике нет. Возврат к умолчанию — это именно удаление собственной записи.
</Note>

## Наименования по умолчанию

Помимо общего списка задумана отдельная выдача значений по умолчанию: она возвращает все глобальные наборы — без учёта типа компании и без учёта языка — как справочник «к чему можно вернуться», и по замыслу открыта любому авторизованному пользователю, а не только сотрудникам компании.

<Warning>
На практике эта выдача недостижима: её адрес объявлен позже адреса отдельного наименования и выглядит для маршрутизатора как обращение к записи, у которой вместо номера стоит слово. Запрос уходит в обработчик одной записи и завершается ошибкой, а не списком значений по умолчанию. Опираться на неё в интерфейсе нельзя.
</Warning>

## Права доступа

| Действие | Кому доступно |
| --- | --- |
| Просмотр списка наименований, просмотр отдельной записи | Сотрудникам компании и субарендаторам |
| Сохранение, изменение, удаление наименований | Только пользователю с правами владельца компании |
| Просмотр наименований по умолчанию | По замыслу — любому авторизованному пользователю (фактически адрес недоступен) |

## Управление со стороны платформы

В административной панели переименования разложены на два раздела, работающих поверх одних и тех же данных.

**Глобальные наименования** — раздел платформы. В нём видны только записи без компании, поле компании в форме отсутствует и всегда остаётся пустым, зато можно выбрать типы компаний, которым набор предназначен, и увидеть их перечень в списке. Есть фильтр по ключу переименования. Формы слова сгруппированы в два блока — падежи единственного и множественного числа.

**Наименования компании** — раздел для разбора конкретных ситуаций. В нём видны только записи с указанной компанией, компанию можно выбрать через поиск, а список фильтруется по компании (фильтра по ключу здесь нет). Набор полей тот же, что и в глобальном разделе.

<Warning>
Глобальный набор без указанных типов компаний не попадёт ни в один список компаний: отбор глобальных записей идёт строго по типу компании. Такая запись останется видимой только в административной панели.
</Warning>

## Где наименования использует сервер

Наименования читает не только интерфейс. Серверная часть сама подставляет их туда, где собирает текст:

| Где | Что подставляется |
| --- | --- |
| Журнал действий | Названия справочников в подписях событий, объектов и связанных полей, названия статусов аренды — см. [«Подписи в журнале»](/ru/logic/audit/labels) |
| Сводка активности компании в админ-панели платформы | Названия действий в последних событиях компании |
| Связи задач и сессий ассистента | Название типа связанного объекта — в самих связях, в каталоге целей для связи и в подсказке поиска объекта |
| Ассистент | Весь список переименований компании попадает в инструкции модели, чтобы ассистент называл сущности так же, как интерфейс |

Сервер берёт из записи только именительный падеж единственного числа, а если он пуст — множественного. В журнале и связях название пишется с заглавной буквы, а в список переименований для ассистента попадает как записано. Остальные падежные формы использует только интерфейс.

Правило перекрытия то же, что в общем списке: запись компании побеждает глобальный набор её типа. Но язык здесь учитывается — берутся только записи на языке запроса. Поэтому серверные подписи не страдают от потери языка, описанной выше.

### Кэш серверных подписей

Итоговое соответствие «ключ переименования → название» для пары «компания + язык» кэшируется на сутки. Общий список и отдельная запись этим кэшем не пользуются и читаются из базы при каждом обращении.

- Сохранение или удаление записи компании через раздел настроек сбрасывает кэш этой компании на языке записи.
- Сохранение или удаление глобальной записи через основную модель сдвигает номер версии, который входит в ключ кэша, — устаревают разом соответствия всех компаний, читающих этот номер. Как и все ключи кэша, номер делится по служебному имени (`schema_name`) компании запроса: он общий для запросов без компании и для компаний с общим служебным именем `public`. Компания со своим служебным именем читает свой номер, и сдвиг, сделанный вне её контекста, до неё не доходит.
- Если у отдельной записи сменить язык, сбрасывается только кэш нового языка. На прежнем языке серверные подписи держат старое название до истечения суток.

<Warning>
Правка в административной панели кэш не сбрасывает — ни в разделе глобальных наименований, ни в разделе наименований компании. Оба раздела работают через прокси-модели `GlobalLabel` и `TenantLabel`, а сброс подписан на сохранение и удаление основной модели `Label`. Для прокси-модели сигнал уходит с другим отправителем и до сброса не доходит. Раздел настроек покажет новое название сразу, а журнал, связи задач и ассистент — только после истечения суток.
</Warning>

## Границы применения

- Общий список наименований и отдельная запись кэшем не пользуются: раздел настроек видит изменение при следующем обращении. Серверные подписи идут через суточный кэш — см. [«Кэш серверных подписей»](#кэш-серверных-подписей).
- Каждая запись несёт ссылку на компанию (у глобального набора она пустая), и все выборки наименований фильтруют по ней явно. Поэтому переименования одинаково видны всем пользователям компании.
- Внутренняя логика по-прежнему оперирует исходными сущностями и статусами. Падежные формы в тексты подставляет интерфейс, который получает наименования из общего списка; сервер сам подставляет только именительный падеж в журнал, связи и ассистента.

## Подводные камни

<Warning>
**Выдача значений по умолчанию фактически недоступна.** Её адрес объявлен после адреса отдельного наименования и выглядит для системы как обращение к записи, у которой вместо номера стоит слово. Запрос уходит в обработчик одной записи и обрывается ошибкой, а не списком умолчаний, — строить на этой выдаче интерфейс нельзя.
</Warning>

<Warning>
**Язык теряется при сборке списка.**

- Записи сворачиваются только по ключу переименования, без учёта языка, и выбрать язык при запросе нельзя.
- Если по одному ключу заведены и русский, и английский наборы, в выдачу попадёт лишь один из них.
- Собственная запись компании на одном языке перекроет глобальную запись на другом.
</Warning>

<Warning>
**Правка отдельной записи может оборваться технической ошибкой.** Смена ключа переименования или языка на пару, которая у компании уже занята, заранее не проверяется: вместо понятного сообщения о конфликте сохранение прерывается ошибкой базы. Через общий список, где работает режим «создать или обновить», такой ситуации не возникает.
</Warning>

<Warning>
**Глобальную строку из списка нельзя изменить по её идентификатору.** В общем списке видны идентификаторы глобальных наборов, но обращение к отдельному наименованию работает только с записями текущей компании — правка или удаление такой строки отвечает «не найдено». Чтобы перекрыть глобальное значение, нужно сохранить новую запись компании через общий список.
</Warning>

<Warning>
**Правка из административной панели доходит до серверных подписей только через сутки.** Разделы глобальных наименований и наименований компании не сбрасывают кэш серверных подписей. Интерфейс увидит новое название сразу, а журнал, связи задач и ассистент — после истечения суточного кэша. Подробнее — в [«Кэш серверных подписей»](#кэш-серверных-подписей).
</Warning>

Менее критичные особенности:

- Компания без указанного типа бизнеса не получает ни одного глобального набора: отбор умолчаний идёт строго по типу компании, поэтому в списке будут только те наименования, которые компания завела сама.
- Ограничение уникальности «компания + язык + ключ» распространяется только на записи компании. Платформа может завести несколько глобальных записей на один ключ и язык, и тогда в списке компании победит непредсказуемая из них — порядок среди глобальных записей не задан.
- Все падежные формы необязательны, включая базовую именительную: наименование можно сохранить с пустыми полями, и система не достроит недостающие формы и не предупредит об этом.
- Глобальный набор, у которого не указаны типы компаний, не увидит ни одна компания — он останется доступен только в административной панели.
- Список языков ограничен языками системы — русским и английским; завести наименование на другом языке нельзя.
- В разделе наименований компании административной панели фильтр по ключу переименования объявлен, но перекрыт фильтром по компании, поэтому доступен только отбор по компании. В глобальном разделе фильтр по ключу работает.

<Info>
Что полезно помнить о поведении раздела:

- Сохранение через общий список всегда отвечает статусом «создано», даже когда фактически обновило уже существующую запись компании.
- Возврат к названию по умолчанию выполняется удалением собственной записи компании: отдельного действия «сбросить» нет, а после удаления в списке снова появляется глобальный набор соответствующего типа компании.
- Читать наименования могут сотрудники компании и субарендаторы, изменять — только пользователь с правами владельца компании. Выдача значений по умолчанию по правам открыта любому авторизованному пользователю, но её адрес недоступен из-за порядка объявления адресов.
- Общий список и отдельная запись каждый раз читаются из базы, поэтому раздел настроек видит переименование сразу. Серверные подписи идут через суточный кэш: правка через раздел настроек сбрасывает его сразу, правка из административной панели — нет.
- В разделе глобальных наборов административной панели поле компании в форму не выводится и остаётся пустым, поэтому создать через него переопределение для конкретной компании невозможно — для этого есть отдельный раздел наименований компании.
- Серверная часть сама подставляет именительный падеж наименования в журнал действий, сводку активности в админ-панели, связи задач и сессий ассистента и в инструкции ассистента. Внутренние сущности и статусы аренды при этом остаются прежними.
- Список наименований и выдача значений по умолчанию отдаются целиком, без постраничной разбивки.
</Info>
