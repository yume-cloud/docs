## Что такое лид и зачем эта страница

Лид — это карточка потенциальной сделки внутри воронки продаж: конкретный клиент, стоящий на конкретном этапе воронки, с назначенным менеджером, источником привлечения, ожидаемой суммой и ручным порядком в колонке. Из лида можно вырастить заявку на аренду и, в итоге, продажу.

Эта страница описывает саму карточку лида: какие данные она хранит, как работает ручное упорядочивание внутри этапа, как список лидов фильтруется по менеджеру и задачам, какие вычисляемые поля и итоги показываются в списке, и как из лида одной кнопкой создаётся заявка.

## Модель данных

Карточка лида хранит связи с другими сущностями и собственные данные. Клиент, источник привлечения, заявка и продажа при удалении связанной записи не рушат лид — ссылка на них просто обнуляется. Этап и воронка удаляются вместе с лидом (лид не может существовать без воронки и этапа). Менеджер — особый случай: при удалении сотрудника его связь с лидом автоматически не переустанавливается и не обнуляется, на существование самого лида это не влияет.

### Связи

| Поле | Тип | Назначение |
|------|-----|-----------|
| Клиент | связь | Клиент, к которому относится лид. При удалении клиента ссылка обнуляется, лид остаётся. |
| Этап воронки | связь | Текущий этап, на котором стоит лид. Удаляется вместе с этапом. |
| Воронка | связь | Воронка, которой принадлежит лид. Удаляется вместе с воронкой. |
| Менеджер | связь | Ответственный сотрудник. Может быть не назначен. При удалении сотрудника связь автоматически не обрабатывается. |
| Источник привлечения | связь | Канал или метод привлечения клиента. При удалении источника ссылка обнуляется. |
| Заявка на аренду | связь | Заявка на аренду, созданная из лида. При удалении заявки ссылка обнуляется. |
| Продажа | связь | Связанная продажа. При удалении продажи ссылка обнуляется. |

### Собственные данные

| Поле | Тип | Назначение |
|------|-----|-----------|
| Сумма лида | число (2 знака) | Ожидаемая сумма сделки. По умолчанию 0. Суммируется в итоге списка. |
| Порядок в колонке | число | Ручной порядок лида внутри этапа. По умолчанию 0. |
| Причина отмены | текст | Комментарий при отмене лида. Участвует в текстовом поиске по списку. |
| Доп. данные | JSON | Произвольные дополнительные поля лида. По умолчанию пусто. |
| Дата создания | дата/время | Проставляется автоматически при создании. Доступна для сортировки и фильтрации. |
| Дата изменения | дата/время | Обновляется автоматически при каждом сохранении. |

<Info>
Карточка лида изолирована по компании: каждая компания видит только свои лиды. Даты создания и изменения проставляются и обновляются автоматически.
</Info>

## Логика и побочные эффекты

При каждом сохранении лида срабатывают два независимых автоматических действия, а при удалении — третье.

### Ручное упорядочивание внутри этапа

Порядок лидов в колонке этапа задаётся вручную числом «Порядок в колонке». Чтобы вставить лид на нужную позицию, система при сохранении сдвигает все остальные лиды того же этапа, у которых порядок не меньше нового значения этого лида, на одну позицию вниз (прибавляет к их порядку единицу). Так освобождается место под перемещённый лид, а относительный порядок остальных сохраняется.

<Warning>
Этот сдвиг выполняется при **каждом** сохранении лида, а не только при явном перемещении. Даже если вы меняете в карточке что-то не связанное с порядком (например, сумму или менеджера), но значение «Порядок в колонке» осталось прежним, все лиды этапа с таким же или большим порядком всё равно сдвинутся вниз. Со временем это раздувает числовые значения порядка. На видимую сортировку это обычно не влияет (относительный порядок сохраняется), но полагаться на конкретные числовые значения порядка не стоит.
</Warning>

### Синхронизация сделки с Wazzup

Кроме упорядочивания, при каждом сохранении лида в фоне (в отдельном потоке, не задерживая ответ) запускается синхронизация соответствующей сделки в Wazzup: если у компании настроено подключение Wazzup с ключом доступа, сделка выгружается и обновляется. При выгрузке сделка всегда помечается как закрытая, независимо от фактического этапа лида. При удалении лида соответствующая сделка удаляется в Wazzup — тоже в фоне. Если подключение Wazzup не настроено или нет ключа, синхронизация тихо пропускается.

<Note>
Синхронизация с Wazzup выполняется в фоновом потоке и её результат не влияет на ответ API: сохранение лида считается успешным независимо от того, удалась ли выгрузка в Wazzup.
</Note>

## Список лидов

Список лидов — основной экран работы с воронкой. Он поддерживает текстовый поиск, фильтры, сортировку, постраничную выдачу и показывает итоговую сумму.

### Вычисляемые поля в списке

Помимо собственных полей карточки, каждый лид в списке (и в детальном просмотре) отдаёт дополнительные поля, вычисляемые прямо в запросе. Они доступны только для чтения.

| Поле | Тип | Назначение |
|------|-----|-----------|
| Дата ближайшей задачи | дата/время | Самая ранняя дата среди незавершённых задач по лиду. |
| Статус заявки | число | Статус связанной заявки на аренду. |
| Сумма заявки со скидкой | число (2 знака) | Итоговая цена связанной заявки с учётом скидки. |
| Телефон клиента | текст | Телефон связанного клиента. |
| Имя клиента | текст | Имя связанного клиента. |

### Поиск, сортировка и итог

Текстовый поиск ведётся по имени клиента, телефону клиента и причине отмены. Сортировка доступна по порядку в колонке и по дате создания; по умолчанию список упорядочен по «Порядку в колонке». Пустые значения при сортировке уходят в конец.

Вместе с постраничной выдачей возвращается общий итог — сумма ожидаемых сумм всех лидов, попавших под текущие фильтры.

### Фильтрация

Список поддерживает фильтры по стандартным полям (идентификатор, телефон клиента, источник, дата создания, сумма, воронка, этап, наличие заявки, наличие продажи), а также несколько особых фильтров.

**Фильтр по менеджеру.** Фильтр по менеджеру намеренно шире, чем «менеджер лида»: лид попадает в выборку, если указанный сотрудник является либо менеджером самого лида, либо менеджером хотя бы одной задачи по этому лиду. Отдельный флаг «Без менеджера» позволяет отобрать лиды с назначенным или неназначенным менеджером.

**Фильтр по задачам.** Два флага управляют отбором по задачам:

- «Без задач» — оставляет только лиды, у которых нет ни одной задачи.
- «С просроченными задачами» — оставляет лиды, у которых есть задача с датой в прошлом (раньше текущего момента).

<Warning>
Фильтр «С просроченными задачами» смотрит только на дату задачи относительно текущего момента и не проверяет, завершена ли задача. То есть лид с уже выполненной, но просроченной по дате задачей тоже попадёт в эту выборку.
</Warning>

<Warning>
Фильтр по менеджеру и фильтр «С просроченными задачами» связывают лид с его задачами. Из-за этого один лид может «размножиться» на несколько строк по числу подходящих задач. В самом списке дубликаты убираются, но итоговая сумма считается по «размноженным» строкам, поэтому при активном фильтре по менеджеру или по просроченным задачам общая сумма в итоге может оказаться завышенной (сумма лида учитывается столько раз, сколько у него подходящих задач).
</Warning>

## Создание заявки из лида

Из карточки лида можно создать заявку на аренду одним действием. Система берёт лид и создаёт по нему заявку общей логикой создания заявки для лида (см. отдельную страницу про триггеры и создание заявки).

Результат:

- если у лида есть клиент — создаётся заявка, в ответе возвращается её идентификатор (статус «создано»);
- если у лида нет клиента — заявка не создаётся, возвращается ошибка «клиент не найден».

<Tip>
Перед созданием заявки из лида убедитесь, что у лида указан клиент. Без клиента запрос завершится ошибкой, а заявка не будет создана.
</Tip>

## Как это используется

Типичный жизненный цикл лида на этой странице:

1. Лид создаётся в воронке на стартовом этапе с клиентом, менеджером и ожидаемой суммой.
2. Внутри этапа лиды упорядочиваются вручную — при сохранении система освобождает нужную позицию, сдвигая соседей.
3. Менеджеры фильтруют список по себе (учитываются и лиды, и их задачи), отбирают лиды без задач или с просроченными задачами и ориентируются на дату ближайшей задачи и итоговую сумму.
4. Когда лид дозревает, из него создаётся заявка на аренду, и в карточке появляется связь с этой заявкой (её статус и сумма со скидкой видны прямо в списке).
5. Все изменения и удаление лида фоново отражаются в сделке Wazzup, если интеграция подключена.
