## Что это за раздел

«Задачи по лидам» — это поручения менеджерам, привязанные к конкретному лиду (или напрямую к клиенту). У каждой задачи есть срок, ответственный менеджер, тип (метод) и место для результата. Раздел состоит из двух связанных сущностей:

- **Задача по лиду** — само поручение с датой, описанием и отметкой о завершении.
- **Метод задачи по лиду** — справочник типов задач (например, «Позвонить», «Отправить КП»), который может быть привязан к конкретной воронке.

Дополнительно раздел автоматически уведомляет ответственного менеджера при каждом сохранении задачи.

## Модель данных

### Задача по лиду

| Поле | Тип | Назначение |
|------|-----|------------|
| Лид | связь | Лид, к которому относится задача. Может быть пустым (задача может висеть только на клиенте). При удалении лида его задачи удаляются вместе с ним. |
| Клиент | связь | Клиент, к которому относится задача. Может быть пустым. При удалении клиента его задачи удаляются вместе с ним. |
| Метод | связь | Тип (метод) задачи. Может быть пустым; если метод удаляют из справочника, у задачи ссылка на метод просто обнуляется, сама задача остаётся. |
| Менеджер | связь | Ответственный за задачу. Именно ему уходит уведомление. |
| Описание | текст | Текст поручения. Попадает в тело уведомления менеджеру. |
| Результат | текст | Итог выполнения задачи. |
| Дата задачи | дата/время | Плановый срок. Обязательное поле — задача не может существовать без даты. |
| Дата завершения | дата/время | Момент фактического завершения. Пусто, пока задача не выполнена. |
| Доп. данные | JSON | Произвольные дополнительные данные, по умолчанию пустой объект. |
| Дата создания / Дата изменения | дата/время | Служебные отметки, проставляются автоматически. |
| Компания | связь | Компания-владелец записи. |

<Note>
Задача может ссылаться и на лида, и на клиента одновременно, либо только на одного из них, либо (технически) ни на кого. Обязательна только дата.
</Note>

### Метод задачи по лиду

| Поле | Тип | Назначение |
|------|-----|------------|
| Название | текст | Наименование типа задачи. |
| Воронка | связь | Воронка, к которой относится метод. Может быть пустой — тогда метод считается общим. При удалении воронки её методы удаляются вместе с ней. |
| Дата создания / Дата изменения | дата/время | Служебные отметки. |
| Компания | связь | Компания-владелец записи. |

Привязка метода к воронке позволяет на фронте показывать в конкретной воронке только релевантные типы задач.

## Логика и побочные эффекты

### Автоматическое уведомление менеджера

При каждом сохранении задачи (и при создании, и при любом изменении) система в фоне создаёт или обновляет уведомление ответственному менеджеру.

Поведение уведомления:

- **Получатель** — менеджер, указанный в задаче.
- **Тело уведомления** — описание задачи.
- **Доп. содержимое** — идентификатор лида, метод и плановая дата задачи.
- Если описание пустое, уведомление вообще не отправляется — фоновая задача завершается сразу.
- Уведомление привязывается не к самой задаче, а к лиду. При повторном сохранении система находит уже существующее уведомление по этому лиду и обновляет его (перезаписывает тело, доп. данные и список получателей), а не плодит новые.

<Warning>
Уведомление идентифицируется по лиду, а не по конкретной задаче. Это значит, что несколько задач на одном лиде делят одно и то же уведомление: сохранение второй задачи перезапишет уведомление, созданное первой. Для задач, привязанных только к клиенту (без лида), идентификатор лида пустой, а поле связанного объекта в уведомлении обязательно и не может быть пустым — поэтому при непустом описании фоновое создание уведомления завершается ошибкой и уведомление по такой задаче вообще не сохраняется (а при пустом описании фоновая задача просто завершается сразу, ничего не создавая).
</Warning>

### Видимость задач по роли

Список задач фильтруется в зависимости от роли смотрящего:

- **Суперпользователь компании** видит все задачи компании без ограничений.
- **Обычный менеджер** видит только те задачи, где он назначен ответственным, либо где он является менеджером самого лида.

Список всегда отсортирован от новых к старым (по дате создания). К каждой задаче в списке дополнительно подтягивается воронка её лида — как вычисляемое значение, только для чтения.

<Warning>
Ограничение видимости по роли применяется только к списку задач. Получение, изменение и удаление отдельной задачи по её идентификатору доступно любому аутентифицированному пользователю компании — роль и принадлежность задачи там не проверяются.
</Warning>

### Фильтры списка

Список задач можно сузить по параметрам:

| Фильтр | Возможности |
|--------|-------------|
| Лид | точное совпадение; отдельно — «есть лид / нет лида» |
| Клиент | точное совпадение |
| Менеджер | точное совпадение или список нескольких менеджеров |
| Дата завершения | признак «завершена / не завершена» (по наличию отметки завершения) |
| Дата задачи | «раньше указанного момента» или точное совпадение |

Комбинация «фильтр по менеджеру + признак незавершённости + срок раньше текущего момента» даёт типовой сценарий «просроченные задачи конкретного менеджера».

## Как это используется

### Создание и редактирование задач

- **Создание задачи** и её **изменение/удаление** используют одну «полную» форму со всеми полями задачи. Здесь можно свободно проставить и лида, и клиента, и менеджера, и метод, и срок.
- **Чтение** (список и карточка) отдаёт облегчённое представление: в нём дополнительно показываются имя ответственного менеджера и воронка лида, а поле лида в этом представлении помечено как только для чтения.

<Info>
Требование «метод и менеджер обязательны» задано на представлении для чтения, а не на форме записи. Практически это значит, что при создании/изменении задачи через API их отсутствие не блокируется на уровне этих правил — задачу можно сохранить без метода и без менеджера.
</Info>

### Справочник методов

- Список методов возвращается **целиком, без постраничной разбивки**, отсортированным от новых к старым.
- Его можно отфильтровать по воронке (точное совпадение) или по признаку «привязан к воронке / общий».
- Метод содержит только название и (необязательно) воронку — это лёгкий справочник для категоризации задач.

<Tip>
Чтобы в интерфейсе конкретной воронки показывать только подходящие типы задач, запрашивайте методы с фильтром по этой воронке; общие методы (без воронки) при этом отбираются отдельным признаком.
</Tip>
