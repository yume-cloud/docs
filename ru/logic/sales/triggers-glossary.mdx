## Понятия

Сквозные механизмы автоматизации — сигналы, движок исполнения и вспомогательные функции, которые связывают смену этапа лида с действиями триггеров.

| Понятие | Значение |
| --- | --- |
| Кэширование прежнего этапа | Обработчик перед сохранением лида: запоминает прежний этап до сохранения, чтобы после сохранения можно было определить факт смены этапа. |
| Запуск автоматизации при смене этапа | Обработчик после сохранения лида: при изменении этапа вызывает исполнение триггеров и создаёт запись лога для авторизованного пользователя. Ничего не делает, если этап не изменился. |
| Исполнение триггеров этапа | Движок автоматизации: перебирает триггеры текущего этапа лида и выполняет их действия (задача, перенос в воронку, сообщение, создание заявки, смена статуса, вебхук). Вызывается при смене этапа; действие «Документ» здесь не обрабатывается. |
| Смена статуса заказа по триггеру | Вспомогательная функция: переводит заявку лида в нужный статус, при переходе в аренду фиксирует фактический старт, продажу инвентаря, начисляет пени и пересчитывает дочерний заказ. Создаёт заявку, если у лида её нет; статусы «В аренде» и «Просрочено» обрабатываются вместе. |
| Создание заявки для лида | Вспомогательная функция: создаёт заявку для лида с клиентом, подставляя длительность, налог и настройки пени из конфигурации, и привязывает заявку к лиду. Ничего не делает, если у лида нет клиента или заявка уже есть. |
| Формат триггера этапа | Обслуживает создание и изменение триггера; при служебном флаге «Сгенерировать лиды» (только на запись) запускает массовую генерацию лидов из заявок для триггера с генерацией лидов. |

## Модели и поля

### Лог смены этапа лида

*Запись истории перемещения лида между этапами воронки, создаётся сигналом при фактической смене этапа авторизованным пользователем. Пишется только если этап изменился и есть неанонимный пользователь.*

| Поле | Тип | Описание |
| --- | --- | --- |
| Лид | связь | Лид, у которого сменился этап. |
| Пользователь | связь | Кто выполнил смену этапа (может быть пустым). |
| Прежний этап | связь | Этап до перехода (пустой при первом попадании). |
| Новый этап | связь | Этап после перехода. |
| Дата события | дата/время | Момент смены этапа (индексируется). |

### Триггер этапа

*Правило автоматизации, срабатывающее при переводе лида на связанный этап воронки и выполняющее одно действие (сообщение, задача, смена статуса заказа и т.д.). Одно действие на триггер; тип действия определяет, какие поля используются.*

**Связи**

| Поле | Тип | Описание |
| --- | --- | --- |
| Этапы срабатывания | связь многие-ко-многим | Этапы воронки, при попадании на которые триггер выполняется. |

**Основное**

| Поле | Тип | Описание |
| --- | --- | --- |
| Действие | перечисление | Тип автоматического действия (см. «Действие триггера»). |
| Порядок | число | Порядок сортировки/выполнения триггеров. |

**Сообщение**

| Поле | Тип | Описание |
| --- | --- | --- |
| Текст сообщения | текст | Шаблон сообщения с подстановкой полей клиента и заявки (для действия «Отправить сообщение»). |
| Канал сообщения | перечисление | SMS или Wazzup (для действия «Отправить сообщение»). |

**Задача**

| Поле | Тип | Описание |
| --- | --- | --- |
| Тип задачи | связь | Метод/тип создаваемой задачи по лиду (для действия «Создать задачу»). |
| Срок задачи | длительность | Смещение от момента срабатывания до дедлайна задачи, по умолчанию 1 день. |
| Описание задачи | текст | Текст создаваемой задачи (для действия «Создать задачу»). |

**Заказ**

| Поле | Тип | Описание |
| --- | --- | --- |
| Статус заказа | перечисление | Статус, в который переводится заявка при действии «Сменить статус заказа». |
| Статус-источник заявок | перечисление | Статус заявок, из которых генерируются лиды при действии «Генерация лидов из заявок». |

**Воронка**

| Поле | Тип | Описание |
| --- | --- | --- |
| Целевая воронка | связь | Воронка, в которую переносится лид (для действия «Перенести в воронку»). |

**Вебхук**

| Поле | Тип | Описание |
| --- | --- | --- |
| URL вебхука | ссылка | Адрес для вызова при действии «Вызвать вебхук». |
| HTTP-метод вебхука | перечисление | Метод запроса (реально выполняется только POST). |

**Отображение**

| Поле | Тип | Описание |
| --- | --- | --- |
| Слот | число | Позиция для отображения в интерфейсе. |
| Индекс | число | Порядковый индекс для отображения в интерфейсе. |

**Служебные**

| Поле | Тип | Описание |
| --- | --- | --- |
| Дата создания | дата/время | Момент создания записи. |
| Дата изменения | дата/время | Момент последнего изменения записи. |

## Статусы и справочники

### Действие триггера

Тип автоматического действия, которое выполняет триггер при смене этапа лида.

- Отправить сообщение
- Создать задачу
- Сменить статус заказа
- Перенести в воронку
- Создать заявку
- Генерация лидов из заявок
- Документ
- Вызвать вебхук

### Канал сообщения

Канал отправки сообщения для действия «Отправить сообщение».

- SMS
- Wazzup (WhatsApp)

### HTTP-метод вебхука

Метод HTTP-запроса для действия «Вызвать вебхук». На практике исполняется только POST.

- POST
- GET
- PUT
- PATCH
- DELETE
