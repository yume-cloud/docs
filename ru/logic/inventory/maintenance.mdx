## Что это за раздел

Обслуживание и ремонт — это учёт технического обслуживания (ТО) каждой единицы инвентаря: что и когда нужно сделать, кто отвечает, за какой срок или пробег предупредить, а также фиксация факта выполнения и списание использованных запчастей со склада мастерской.

Раздел работает вокруг двух записей:

- **Обслуживание инвентаря** — план или факт одной работы по конкретной единице (замена масла, сезонное ТО, ремонт и т. п.).
- **Ресурс обслуживания** — строка расхода: какая запчасть/материал со склада мастерской и в каком количестве были потрачены на эту работу.

<Info>
Расчёт сроков ТО опирается на пробег единицы и её состояние (эти сущности описаны в других разделах модуля «Инвентарь и услуги»), а списание запчастей — на склад ресурсов из модуля «Мастерская».
</Info>

## Модель данных

### Обслуживание инвентаря

Одна запись описывает одну работу по одной единице. Она может быть плановой (в будущем), выполненной прямо сейчас или повторяющейся.

**Основное**

| Поле | Тип | Назначение |
| --- | --- | --- |
| Название | текст | Наименование обслуживания. |
| Тип обслуживания | перечисление | Разовое или периодическое. |
| Тип периодичности | перечисление | По интервалу времени или по пробегу. |
| Описание | текст | Подробности работ; подставляется в текст уведомления. |
| Комментарий | текст | Заметка; заполняется при завершении обслуживания, в обычном редактировании доступна только для чтения. |

**Связи**

| Поле | Тип | Назначение |
| --- | --- | --- |
| Единица инвентаря | связь | Обслуживаемая единица. |
| Ответственный | связь | Сотрудник, отвечающий за работу. |
| Состояние инвентаря | связь | Состояние, которое присваивается единице при этом ТО (например, «на ремонте»). |

**Сроки, периодичность и пороги**

| Поле | Тип | Назначение |
| --- | --- | --- |
| Плановая дата ТО | дата/время | Когда планируется обслуживание. |
| Интервал повторения | интервал | Период между повторами для периодического ТО по времени. |
| Интервал по пробегу | число | Пробег между обслуживаниями для периодичности по пробегу. |
| Порог уведомления по времени | интервал | За сколько до плановой даты предупредить. |
| Порог уведомления по пробегу | число | За сколько километров до достижения пробега предупредить. |
| Начальный пробег | число | Пробег единицы на момент назначения ТО — база отсчёта. |

**Завершение** (заполняется автоматически, в API только для чтения)

| Поле | Тип | Назначение |
| --- | --- | --- |
| Фактическая дата ТО | дата/время | Дата завершения. Пустое значение означает, что ТО ещё не выполнено. |
| Пробег при завершении | число | Пробег единицы в момент фактического завершения. |

<Note>
Пустая «Фактическая дата ТО» — это признак незакрытой работы. Именно по нему списки задач и уведомления отбирают то, что ещё предстоит сделать.
</Note>

### Ресурс обслуживания

Строка расхода запчастей и материалов на конкретную работу.

| Поле | Тип | Назначение |
| --- | --- | --- |
| Обслуживание | связь | К какой работе относится расход. |
| Ресурс мастерской | связь | Позиция со склада мастерской. |
| Цена | число (2 знака) | Цена за единицу ресурса. |
| Количество | число (2 знака) | Списываемое количество (по умолчанию 1). |

## Логика и побочные эффекты

### Состояние единицы меняется сразу при сохранении

Как только запись обслуживания сохранена и в ней указано состояние, это состояние немедленно переносится на саму единицу инвентаря.

<Warning>
Это происходит в момент **сохранения записи**, а не в момент выполнения работы. Если запланировать будущее ТО и указать в нём состояние (например, «на ремонте»), единица получит это состояние прямо сейчас, ещё до наступления плановой даты. Учитывайте это при планировании — иначе доступная единица будет заранее выведена в нерабочее состояние.
</Warning>

### Создание записи обслуживания

При создании система действует так:

1. Если плановая дата не задана — она принимается равной текущему моменту.
2. **Периодичность по пробегу.** Отдельное расписание уведомлений не создаётся. Такие работы отслеживаются опросом (см. список «по пробегу» ниже): система периодически сравнивает текущий пробег единицы с порогом. Запись сохраняется и на этом обработка завершается.
3. **Разовое ТО на будущую дату.** Момент напоминания вычисляется как плановая дата минус порог уведомления по времени. Если этот момент оказывается в прошлом, сохранение отклоняется с ошибкой о недопустимости даты в прошлом. Иначе создаётся разовое отложенное задание, которое один раз сработает в вычисленный момент.
4. **Периодическое ТО по времени.** Создаётся повторяющееся задание с периодом, равным интервалу повторения (в днях), стартующее за «порог уведомления по времени» до плановой даты.

<Note>
Для периодического ТО по интервалу времени плановая дата обязательна — без неё сохранение не пройдёт валидацию.
</Note>

### Добавление и изменение ресурсов (запчастей)

Работа с ресурсами напрямую затрагивает склад мастерской и финансы:

- **Добавление ресурса** списывает указанное количество со склада мастерской и создаёт расходную (дебетовую) финансовую транзакцию на сумму «цена × количество» со знаком минус, привязанную к обслуживанию и к единице инвентаря.
- **Изменение ресурса** пересчитывает остаток на складе (возвращает старое количество, списывает новое) и обновляет сумму связанной транзакции.
- **Удаление ресурса** возвращает списанное количество обратно на склад, а связанная расходная транзакция удаляется.

<Info>
Если склада не хватает для списания, операция добавления/изменения ресурса завершается понятной ошибкой о нехватке остатка — запись не сохраняется.
</Info>

### Завершение обслуживания

Завершение — это отдельное действие. При нём:

1. Проверяется, что работа ещё не закрыта; повторно завершить уже выполненное ТО нельзя (возвращается ошибка «уже завершено»).
2. Фиксируется фактическая дата (текущий момент) и пробег при завершении (текущий пробег единицы).
3. Ответственным записывается пользователь, выполняющий завершение (прежний ответственный перезаписывается).
4. Если при завершении указано состояние, оно, как и при обычном сохранении, переносится на единицу инвентаря.

**Для периодического ТО** при завершении дополнительно:

- Текущее повторяющееся задание уведомлений отключается.
- Автоматически создаётся **следующая запись** того же обслуживания. Её плановая дата = прежняя плановая дата плюс интервал повторения (но не меньше одного дня); если данных для расчёта нет — текущий момент. Базовый пробег новой записи берётся из текущего пробега единицы (если у прежней записи пробег отслеживался); факт завершения и состояние очищаются.
- Для новой записи создаётся новое повторяющееся задание уведомлений — но только если у неё заданы и плановая дата, и порог уведомления по времени, и интервал повторения.

<Warning>
Следующая периодическая запись создаётся всегда, но задание-напоминание к ней привязывается только при наличии порога уведомления по времени. Если порог не задан, следующая работа появится в списке, но автоматического напоминания по времени по ней не будет.
</Warning>

## Списки задач: что уже пора обслуживать

Для оперативной работы предусмотрены отдельные списки единиц, требующих внимания.

### По пробегу

Отбираются незакрытые работы с периодичностью по пробегу. Для каждой считается **остаток пробега до ТО**:

- для периодического ТО: начальный пробег плюс интервал по пробегу минус текущий пробег единицы;
- для разового ТО: интервал по пробегу минус текущий пробег единицы.

В список попадают единицы, у которых остаток пробега меньше либо равен порогу уведомления по пробегу. Единицы, выведенные из оборота, исключаются. Сортировка — по возрастанию остатка (самые срочные сверху).

### По времени

Отбираются незакрытые работы с периодичностью по интервалу времени; единицы сортируются по ближайшей плановой дате. Выведенные из оборота единицы исключаются.

### Табличный список инвентаря

Показывает единицы с рассчитанной доступностью и приложенным перечнем их незакрытых работ ТО — удобно для общего обзора парка.

## Фоновые уведомления о ТО

Напоминания рассылает фоновая задача, которую запускают созданные при сохранении расписания (разовое — для разового будущего ТО, периодическое — для повторяющегося по времени).

Логика задачи:

1. Проверяется, включена ли у компании интеграция обслуживания. Если интеграция выключена или не настроена — задача молча завершается и **ничего не отправляет**.
2. Формируется внутреннее уведомление с текстом вида `«Проведите ТО для <единица>! (<описание>)»` и темой «назначено обслуживание». В подпись единицы при включённой авто-функции добавляется госномер.
3. Если дополнительно включена интеграция мессенджера, клиенту отправляется сообщение в WhatsApp.

<Warning>
Уведомления о ТО работают только при включённой интеграции обслуживания. Пока она не активирована, задача отрабатывает вхолостую и напоминания не приходят.
</Warning>

### Кому уходит сообщение в WhatsApp

Сообщение адресуется **клиенту, у которого единица сейчас в аренде**, а не ответственному сотруднику. Задача берёт самую свежую активную аренду единицы в статусе «в аренде» или «просрочена», находит её клиента и его телефон. Сообщение не отправляется, если:

- единица выведена из оборота;
- у единицы нет активной аренды или у клиента нет телефона.

Текст просит клиента пройти техобслуживание и связаться с менеджером; в подпись подставляется название компании.

<Tip>
Внутреннее уведомление (в приложении) и сообщение в WhatsApp — независимые каналы: внутреннее создаётся при активной интеграции обслуживания, а WhatsApp — дополнительно, только когда включена интеграция мессенджера.
</Tip>

## Как это используется

Типовой сценарий:

1. Для единицы заводят обслуживание: разовое (на дату) или периодическое (по времени или по пробегу), указывают ответственного, пороги предупреждения и, при необходимости, состояние.
2. Система планирует напоминание (для сроков по времени) либо начинает отслеживать пробег (для периодичности по пробегу).
3. Ближе к сроку менеджер видит единицу в списке задач и/или получает уведомление.
4. По ходу работ добавляют израсходованные запчасти — они списываются со склада мастерской и формируют расходные транзакции.
5. Работу завершают: фиксируются факт даты и пробега; для периодического ТО автоматически заводится следующая итерация.

## Подводные камни

<Warning>
- **Состояние переносится на единицу сразу при сохранении записи**, а не при выполнении работы: запланированное на будущее ТО с указанным состоянием немедленно меняет состояние единицы уже сейчас.
- **Уведомления о ТО (и внутренние, и в WhatsApp) не отправляются вовсе**, если у компании не активирована интеграция обслуживания — фоновая задача в этом случае молча завершается.
</Warning>

- **При завершении обслуживания ответственный перезаписывается** на пользователя, выполнившего завершение, — прежде назначенный ответственный теряется.
- **Для следующей периодической записи, создаваемой при завершении, напоминание планируется только при наличии порога уведомления по времени** (вместе с плановой датой и интервалом); без порога запись появится, но автоматического напоминания по ней не будет.
- **Разовое ТО на будущую дату отклоняется**, если момент напоминания (плановая дата минус порог по времени) оказывается в прошлом.

<Info>
- Периодичность по пробегу не создаёт никакого фонового расписания — такие работы отслеживаются только опросом через список «по пробегу», сравнивающий текущий пробег единицы с порогом.
- Сообщение в WhatsApp о ТО уходит клиенту текущей активной аренды единицы (статусы «в аренде»/«просрочена»), а не ответственному сотруднику; при отсутствии активной аренды, телефона клиента или при выведенной из оборота единице отправка пропускается.
- Завершение требует, чтобы поле комментария присутствовало в запросе (значение может быть пустым или отсутствующим), и запрещает повторное закрытие уже выполненного ТО.
- Возврат запчасти на склад при удалении ресурса выполняется автоматически по сигналу удаления, а связанная расходная транзакция удаляется отдельно при обработке удаления — это два разных механизма.
</Info>
