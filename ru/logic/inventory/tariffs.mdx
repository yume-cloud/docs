Полный перечень полей — в [глоссарии](/ru/logic/inventory/tariffs-glossary).

## Обзор

Этот раздел описывает, как в системе хранятся и обслуживаются **тарифы** — правила ценообразования. Раньше тарифов было два разных вида в двух таблицах (тарифы инвентаря и тарифы услуг), и у каждого объекта тарификации были свои адреса и свои права. Теперь это **один справочник**: одна и та же запись обслуживает единицу инвентаря, продукт, позицию комплекта и услугу. От того, какая связь заполнена, зависит, к чему тариф относится.

<Info>
Сама арифметика стоимости — как тариф превращается в цену строки аренды, что такое интервал тарификации, округление вверх, «заморозка» тарифа в момент оформления — описана отдельно: [«Пересчёт сумм и цен»](/ru/logic/rent/pricing). Здесь объясняется устройство самих записей, их адреса и массовые операции.
</Info>

<Note>
Прежние тарифы услуг перенесены в общий справочник вместе со своими ссылками из начислений и строк аренды. Право на тарифы тоже стало одним: выданные роли, у которых были права на тарифы инвентаря или на тарифы услуг, получили общее право на тарифы.
</Note>

## Модель данных

Тариф — это цена за один тарифицируемый период (час, сутки и т. п.) с необязательным ограничением по дням недели и времени суток.

| Поле | Тип | Назначение |
|------|-----|-----------|
| Название тарифа | текст | Человекочитаемое имя; если не задано, подставляется имя объекта тарификации |
| Цена | число (2 знака) | Стоимость за один период |
| Период времени | связь | Тарифицируемый период (час/сутки и т. п.); может быть пустым. Период нельзя удалить, пока на него ссылается тариф |
| Порядок | число | Позиция при сортировке |
| Дни недели | список чисел (0–6) | В какие дни недели действует тариф; по умолчанию пустой список |
| Начало действия | время | Время начала действия в пределах суток |
| Конец действия | время | Время окончания действия в пределах суток |
| Опубликован | флаг | Виден ли тариф клиентам (по умолчанию — да) |
| Разовая оплата | флаг | Тариф берётся один раз за аренду, а не за каждый период. Применяется к услугам |
| Единица инвентаря | связь | Заполняется для тарифа отдельной единицы |
| Продукт | связь | Заполняется для тарифа продукта |
| Позиция комплекта | связь | Заполняется для тарифа позиции внутри комплекта |
| Вариант цены комплекта | связь | Привязка тарифа к конкретному варианту цены комплекта |
| Услуга | связь | Заполняется для тарифа услуги |
| Компания | связь | Владелец записи |
| История изменений | журнал | Аудит-лог изменений |

### Четыре роли одной записи

- **Тариф единицы** — заполнена связь с единицей инвентаря. Индивидуальная цена конкретного экземпляра.
- **Тариф продукта** — заполнена связь с продуктом. Действует для всех единиц продукта, у которых нет собственного тарифа.
- **Тариф позиции комплекта** — заполнены связи с позицией комплекта и с вариантом цены комплекта. Из суммы таких тарифов складывается итоговая цена варианта (см. ниже).
- **Тариф услуги** — заполнена связь с услугой. Только у него имеет смысл флаг разовой оплаты.

### Правило одного владельца

Проверка при сохранении простая и жёсткая:

- тариф обязан быть привязан **хотя бы к одному** объекту — единице, продукту, позиции комплекта, варианту цены комплекта или услуге; иначе сохранение отклоняется;
- привязка может быть **только одна**: два объекта тарификации в одной записи не допускаются;
- вариант цены комплекта указывается **только вместе** с позицией состава — сам по себе он владельцем быть может, а вместе с единицей, продуктом или услугой — нет.

<Note>
Название тарифа позиции комплекта формируется автоматически по шаблону «Название комплекта | Название варианта цены» (если вариант не указан — просто название комплекта). Период времени такого тарифа тоже подставляется из варианта цены, если не задан явно. Для остальных ролей незаполненное название заменяется именем объекта: единицы, продукта или услуги.
</Note>

### Менеджер тарифов: скрытие отключённых периодов

Стандартный доступ к тарифам идёт через менеджер, который **автоматически прячет тарифы с отключённым периодом времени**. В выборку попадают только тарифы без периода вообще либо тарифы, чей период не отключён. Если временной период выводят из оборота, все привязанные к нему тарифы разом исчезают из списков и расчётов, хотя сами записи остаются в базе.

### Сортировка по умолчанию

Сначала тарифы без продукта (тарифы единиц, комплектов и услуг идут первыми), затем по полю порядка, затем от новых к старым по дате создания.

## Адреса и операции

Все тарифы обслуживаются одним набором адресов; отдельных адресов «тарифы такой-то единицы», «тарифы такого-то продукта» и «тарифы такого-то комплекта» больше нет.

| Операция | Что делает |
|----------|-----------|
| Список и создание | Отдаёт тарифы с учётом фильтров и создаёт одиночный тариф |
| Деталь | Чтение, изменение и удаление одного тарифа |
| Массовое создание | Список новых тарифов одним запросом |
| Массовое обновление | Список правок одним запросом |
| Массовая операция | Добавление, изменение и удаление **в одном запросе** |

<Tip>
Список по умолчанию **не постраничный**: прайс читают целиком. Страницы включаются только по явной просьбе — прайс никто не листает.
</Tip>

Совместимости ради у услуг остались собственные адреса создания и правки тарифа — они работают с тем же общим справочником.

### Фильтры списка

| Параметр | Описание |
| --- | --- |
| Единица, продукт, позиция комплекта, вариант цены, услуга | Точное значение или признак «не задано» |
| Комплект | Все тарифы позиций указанного комплекта |
| Период времени | Точное значение или «без периода» |
| Опубликован | Только опубликованные или только скрытые |
| «Прайс единицы» | Тарифы, по которым считается цена конкретной единицы |

Параметр «прайс единицы» отвечает на вопрос «сколько стоит вот эта единица», а не «какие записи на неё ссылаются», поэтому он не сводится к простому отбору по связи. Область уточняется дополнительным параметром:

| Область | Что показывается |
|--------|------------------|
| не задана | собственные тарифы единицы и тарифы её продукта вместе |
| «единица» | только собственные тарифы единицы |
| «продукт» | только тарифы продукта этой единицы |
| «комплект» | тарифы позиций комплектов, куда входит продукт этой единицы |

<Warning>
Области «продукт» и «комплект» работают только у единицы, у которой есть продукт. Если продукта нет, отбор сводится к собственным тарифам единицы — пустого списка ждать не стоит. Полностью пустой ответ отдаётся лишь тогда, когда единицы с таким идентификатором не существует.
</Warning>

### Массовая операция: добавить, изменить и удалить сразу

Отдельный адрес принимает три списка: что добавить, что изменить и что удалить. Всё выполняется в одной транзакции, цены вариантов комплекта пересчитываются один раз в конце, а в ответе приходит, сколько записей добавлено, изменено и удалено.

<Tip>
Это основной способ сохранить прайс из интерфейса: пользователь правит таблицу тарифов целиком, а уходит один запрос вместо запроса на строку. Массовое создание и массовое обновление остаются отдельными адресами и тоже выполняются каждое в своей транзакции.
</Tip>

При массовом обновлении применяются цена, название, порядок, дни недели, время начала и конца, признак публикации, период времени и признак разовой оплаты. **Привязки тарифа к объекту тарификации массовое обновление не меняет**: даже если в строке передана другая позиция комплекта или другой вариант цены, владелец останется прежним. Чтобы переставить тариф на другой объект, его удаляют и заводят заново.

## Тарифы и цены комплектов

Комплект — это набор позиций, каждая со своим количеством. У комплекта есть один или несколько **вариантов цены** (например, «за час», «за сутки»), и итоговая цена каждого варианта не задаётся руками, а **вычисляется как сумма тарифов позиций**.

### Формула итоговой цены варианта

Итоговая цена варианта цены комплекта равна сумме по всем его тарифам произведения:

**цена тарифа × количество соответствующей позиции комплекта.**

Если у варианта нет ни одного тарифа, его итоговая цена считается равной нулю.

Именно поэтому формат варианта цены комплекта при записи **не принимает поле итоговой цены** — оно всегда пересчитывается системой. Через этот формат задаются только название варианта, его временной период и порядок сортировки; связь с комплектом проставляется автоматически из адреса запроса.

### Когда пересчитывается цена варианта

Пересчёт запускается сам при **любом** изменении тарифов, затрагивающем комплект: при одиночном создании, правке и удалении тарифа, при каждой из массовых операций. Система определяет, каких комплектов коснулась операция, и пересчитывает цены всех их вариантов одним пакетным обновлением.

<Check>
Прежнего запрета «тариф позиции комплекта нельзя изменить или удалить через обычный адрес» больше нет. Раньше такие тарифы правились только массовыми операциями комплекта, потому что иначе итоговая цена варианта осталась бы старой. Теперь пересчёт привязан к самой операции, поэтому одиночная правка и одиночное удаление тоже безопасны.
</Check>

При правке тарифа пересчитываются комплекты и до, и после изменения: если тариф переехал с одного комплекта на другой, обновятся цены обоих.

## Как это используется

- **Прайс на единицу и на продукт.** Оператор задаёт тарифы продукта (общая цена для всех его единиц) и при необходимости индивидуальные тарифы отдельных единиц. При расчёте стоимости аренды система выбирает подходящий тариф с учётом периода, дней недели и времени суток — по правилам из раздела про расчёт стоимости.
- **Прайс на комплект.** Оператор настраивает варианты цены комплекта, затем правит тарифы позиций. Итоговая цена каждого варианта пересчитывается автоматически из тарифов позиций и их количеств — руками её не редактируют.
- **Прайс на услугу.** Тариф услуги живёт в том же справочнике и отличается только флагом разовой оплаты: с ним услуга стоит фиксированную сумму за аренду, без него — за каждый период.
- **Вывод периода из оборота.** Если временной период отключают, тарифы, привязанные к нему, автоматически исчезают из выборок и расчётов, оставаясь в базе для истории.

Про дополнительные услуги и полную арифметику стоимости строки аренды — см. соседние разделы модуля и страницу [«Пересчёт сумм и цен»](/ru/logic/rent/pricing).

## Особенности поведения

- Тариф обязан иметь ровно одного владельца: без привязки его не сохранить, с двумя — тоже. Вариант цены комплекта допустим только вместе с позицией состава.
- Массовое обновление не переставляет тариф на другой объект тарификации: переданные в строке связи игнорируются, меняются только цена, название, порядок, дни недели, время, публикация, период и разовая оплата.
- Итоговая цена варианта цены комплекта нигде не задаётся вручную — она всегда пересчитывается как сумма цен тарифов позиций, умноженных на количество позиций, и обновляется при любой операции с тарифами этого комплекта.
- Список тарифов по умолчанию отдаётся целиком, без страниц; постраничный режим включается параметром запроса.
- Область «прайс единицы» по продукту и по комплекту работает только при наличии у единицы продукта; иначе возвращаются собственные тарифы единицы, а не пустой список. Полностью пустой ответ отдаётся лишь при отсутствии самой единицы.
- Название и период времени тарифа позиции комплекта подставляются автоматически (имя по шаблону «Комплект | Вариант цены», период — из варианта цены), если не заданы явно.
- Период времени защищён от удаления: пока на него ссылается хотя бы один тариф, удалить его нельзя.
