К любому объекту можно прикрепить произвольные файлы-документы (договоры, акты, PDF, изображения, любые форматы). Каждый
файл сохраняется в облачном хранилище в отдельной папке для файлов и связывается с родительским объектом через ту
же пару «тип объекта + идентификатор», что и остальные [вложения](/ru/logic/attachments). Все выборки жёстко
ограничены компанией текущего запроса. Записи упорядочены от новых к старым.

Для крупных файлов есть отдельный сценарий — [прямая загрузка](/ru/logic/attachments/direct-upload). Полный перечень
полей — в [глоссарии файлов](/ru/logic/attachments/files-glossary).

## Логика

**Поштучное прикрепление.** Клиент передаёт сам файл, тип родительского объекта (по имени вида объекта), идентификатор
объекта и, при необходимости, категорию. Система автоматически проставляет компанию, автора и дату создания. Поля с
собственным идентификатором записи, расширением, датой создания и автором доступны только для чтения. Приём файлов идёт
только через загрузку формой. Список в поштучном режиме отдаётся без постраничного разбиения. Все операции с файлами
(список, просмотр, создание, изменение, удаление, массовая загрузка) доступны только авторизованным пользователям —
анонимный запрос отклоняется, ничего не читая и не меняя.

<Note>
В поштучном режиме поле «Название» не входит в набор принимаемых полей — клиент его не задаёт: система записывает в него
исходное имя загруженного файла. Своё название можно указать только при массовой загрузке.
</Note>

**Массовое прикрепление.** Для загрузки нескольких файлов к одному объекту есть отдельный режим. Клиент передаёт список
файлов и общие для всех параметры: тип и идентификатор родительского объекта, а также необязательные название и категорию.

- Все файлы прикрепляются к **одному и тому же** родительскому объекту.
- Название и категория **общие** для всех файлов пакета — разные имена или категории для отдельных файлов задать нельзя.
- Расширение определяется автоматически для каждого файла из его собственного имени (приводится к нижнему регистру) — здесь именно фактическое расширение, а не значение по умолчанию.
- Название — то, что передано в пакете (общее для всех); если не передано, у каждого файла остаётся его исходное имя.
- Создание идёт одной пакетной операцией внутри единой транзакции: либо создаются все записи, либо (при ошибке) ни одной.

**Фильтрация списка.** Список файлов можно отфильтровать по нескольким параметрам:

| Фильтр | Как работает |
|--------|--------------|
| Дата создания | по календарной дате: не раньше и не позже указанного дня |
| Кем создан | точное совпадение или список значений |
| Идентификатор объекта | точное совпадение или список значений |
| Категория | точное совпадение или список значений |
| Тип объекта | по имени вида объекта, с возможностью указать несколько значений |

Так операционист может получить, например, все документы конкретной заявки или все файлы определённой категории,
загруженные конкретным сотрудником за период. При изменении отдельного файла служебные поля (расширение, дата создания,
автор) остаются защищёнными от прямой правки; при удалении вместе с записью удаляется и сам файл в облачном хранилище.

## Имя файла и адрес для открытия

**Имя в хранилище.** При любой загрузке (поштучной, массовой, при замене файла) объект кладётся в хранилище под случайным
идентификатором с сохранением расширения — например, `3f2c…9a.pdf`. Одинаковые имена у разных файлов не конфликтуют, а
кириллица и пробелы в имени не попадают в адрес. Исходное имя не теряется: оно записывается в поле «Название» (при
массовой загрузке — если не задано общее).

**Адрес для открытия.** Ссылка на файл в ответе сервера строится так, чтобы браузер открывал файл в окне (а не скачивал
принудительно) и при сохранении подставлял исходное имя из поля «Название» — например, «Договор.PDF», а не случайный
идентификатор. Это работает, если у записи есть и файл, и название; иначе ссылка отдаётся обычная.

## Особенности поведения

<Note>
Расширение в обоих режимах определяется из имени загруженного файла, приводится к нижнему регистру и сохраняется вместе с
ведущей точкой (например, «.pdf»). Исключение — [прямая загрузка](/ru/logic/attachments/direct-upload): там расширение записывается без точки («mp4»), а значение по умолчанию («pdf») остаётся только у записей, созданных без файла.
</Note>

<Info>
Файлы комментариев — обычные прикреплённые файлы, у которых родитель — [комментарий](/ru/logic/attachments/comments#фото-и-файлы-в-комментарии).
</Info>
