Эта страница собирает в одном месте **проблемы, баги и логические ошибки** раздела: где поведение расходится с ожидаемым и к чему это приводит. Пункты сгруппированы по странице, на которой описано соответствующее штатное поведение.

<Note>
Остальные страницы раздела намеренно описывают только штатное поведение — все отклонения вынесены сюда.
</Note>

## Подводные камни со страниц раздела

### [Вложения](/ru/logic/attachments)

<Warning>
**Модели вложений фактически не отображаются в административной панели.** В настройке админ-панели используется вызов,
который сам по себе ничего к ней не подключает, поэтому вопреки ожиданию четыре вида вложений в стандартной админ-панели
не появятся — это похоже на ошибку.
</Warning>

<Warning>
**Списки вложений всех четырёх видов отдаются без постраничного разбиения** — для объекта с большим числом вложений в
один ответ попадут все записи сразу, что может дать тяжёлый ответ.
</Warning>

### [Вложения: Комментарии](/ru/logic/attachments/comments)

<Warning>
**Сервер принимает комментарий без текста и без вложений.** Пустой текст разрешён, чтобы комментарий из одних фото и файлов
можно было создать до загрузки самих вложений (они добавляются отдельными запросами уже к готовому комментарию). Проверки
«есть хотя бы что-то» на сервере нет: если клиент создал комментарий и не дозагрузил вложения (сбой сети, закрытая вкладка),
в списке останется пустой комментарий. Веб-интерфейс сам удаляет такой комментарий, но прямой вызов API — нет.
</Warning>

### [Вложения: Прямая загрузка крупных файлов](/ru/logic/attachments/direct-upload)

<Warning>
**Осиротевшие файлы всё ещё возможны, но иначе, чем при загрузке по частям.** Если клиент успешно загрузил файл в
хранилище, но так и не вызвал завершение (например, вкладку закрыли до перехода к следующему шагу), в хранилище
останется файл без записи в системе — сервер не отслеживает и не удаляет такие файлы автоматически. При этом, в
отличие от многочастной загрузки, здесь нет отдельного шага отмены: обычная загрузка либо целиком успевает, либо
целиком проваливается — частично собранных файлов в хранилище не остаётся.
</Warning>

<Warning>
**Завершение не проверяет, что родительский объект существует.** Ключ и вид объекта проверяются, а идентификатор объекта
принимается как любое целое число: вложение к несуществующей записи будет создано и повиснет без родителя.
</Warning>

### [Вложения: Файлы и документы](/ru/logic/attachments/files)

<Warning>
**Массовое создание скрывает результат.** Конфликтующие записи молча пропускаются без ошибки, а в ответе возвращаются
переданные входные параметры, а не список фактически созданных записей — поэтому по ответу нельзя точно узнать, сколько
файлов реально сохранилось.
</Warning>

### [Вложения: Изображения и миниатюры](/ru/logic/attachments/images)

<Warning>
**Сбой генерации миниатюры не прерывает сохранение изображения.** Любая ошибка перехватывается, вместо миниатюры
подставляется пустое значение, а сама ошибка лишь выводится в лог. В результате изображение может сохраниться без
миниатюры.
</Warning>

<Warning>
**Расширение файла ведёт себя по-разному в двух режимах.** При **поштучном** добавлении расширение не вычисляется из
загруженного файла — оно всегда остаётся значением по умолчанию, даже если загружен, например, JPG (фактическое
расширение при этом сохраняется в имени файла, но поле расширения ему не соответствует). При **массовом** добавлении в
поле расширения записывается результат разбора имени вместе с ведущей точкой. Поведение двух способов несогласованно.
</Warning>

<Warning>
**Массовое создание скрывает результат.** Конфликтующие записи молча пропускаются без ошибки, а в ответе возвращаются
исходные входные данные, а не фактически созданные записи. По ответу невозможно определить, сколько записей реально
сохранилось.
</Warning>
