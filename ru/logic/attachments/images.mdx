К объекту можно прикреплять изображения; для каждого изображения система формирует миниатюру. Привязка устроена
полиморфно — так же, как у остальных [вложений](/ru/logic/attachments). Компания-владелец и автор при поштучном
добавлении берутся из контекста запроса и не могут быть заданы клиентом. Список изображений отдаётся без постраничного
разбиения, записи упорядочены от новых к старым; доступна фильтрация выборки.

Полный перечень полей — в [глоссарии изображений](/ru/logic/attachments-images-glossary).

## Логика

Миниатюра всегда пересохраняется в формат PNG размером до 720×720 точек с сохранением пропорций, независимо от исходного
формата и размера изображения. Изображение при этом только **уменьшается** — увеличение не выполняется. Имя файла при
сохранении заменяется на случайный идентификатор с сохранением расширения.

При массовом добавлении все изображения получают одинаковые название, категорию, тип объекта и идентификатор объекта —
прикрепить одним запросом изображения к разным объектам нельзя. Групповое создание выполняется одной операцией с
пропуском конфликтов без ошибки; в ответе возвращаются исходные переданные данные, а не фактически созданные записи с
идентификаторами, поэтому клиент не узнает, сколько записей реально создано.

## Подводные камни

<Warning>
**Сбой генерации миниатюры не прерывает сохранение изображения.** Любая ошибка перехватывается, вместо миниатюры
подставляется пустое значение, а сама ошибка лишь выводится в лог. В результате изображение может сохраниться без
миниатюры.
</Warning>

<Warning>
**Расширение файла ведёт себя по-разному в двух режимах.** При **поштучном** добавлении расширение не вычисляется из
загруженного файла — оно всегда остаётся значением по умолчанию, даже если загружен, например, JPG (фактическое
расширение при этом сохраняется в имени файла, но поле расширения ему не соответствует). При **массовом** добавлении в
поле расширения записывается результат разбора имени вместе с ведущей точкой. Поведение двух способов несогласованно.
</Warning>

<Warning>
**Массовое создание скрывает результат.** Конфликтующие записи молча пропускаются без ошибки, а в ответе возвращаются
исходные входные данные, а не фактически созданные записи. По ответу невозможно определить, сколько записей реально
сохранилось.
</Warning>
